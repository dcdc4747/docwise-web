### 5.1 ⚠️ D 要做的那三篇样例（**M4 的验收地基，现在做正好**）

M4 的判据是"**自造样例 + 组内真稿，报告写「报出 N 处、人工判定 M 处成立」**"，**样例必须含三篇**：

| # | 样例 | 它证明什么 |
|---|---|---|
| 1 | **中文 · 顺序编码制**（`[1][2]`） | 主路径成立 |
| 2 | **英文 · 顺序编码制** | 判语言那一步成立（词表要按语言路由到 `text_quote`） |
| 3 | ⭐ **一篇著者-出版年制**（`（张三，2024）` 全文无 `[n]`） | **证明"不误报爆炸"** |

⚠️ **第三篇是最关键的一篇**：判据核心是"无 `[n]` 标注 → 报"，而一份著者-出版年制的稿子**全文没有一个 `[n]`** → 按现判据**所有命中句都被报成"该引未引"，误报爆炸、且爆得隐蔽（每一处都"看起来对"）**。**这篇样例是专门用来打这个洞的。**

## 八、合并流程（**照抄，别自创**）

```
1. git branch --show-current   ← 先确认自己在哪（踩过：从错的分支拉，把无关提交带进 PR）
2. git checkout main && git pull
3. git checkout -b feat/<期次>-<短语>
4. 改 → 跑全量：
     后端：cd backend && uv run ruff check .   && uv run pytest -q
     前端：cd frontend && bun run test  && bun run build
5. 红线自扫（git ls-files -z 遍历，含注释/文档字符串/提交信息）
6. git push -u origin <分支>
7. gh pr create —— PR 描述必须写：做了什么 / 怎么验证 / 截图（界面改动必贴）
8. CI 全绿 → 用户（唯一合并权人）审 → squash 合并 → 删分支
```

⚠️ **提交信息用中文引号「」**——PowerShell here-string 里的英文双引号会把命令拆坏（踩过三次）。
⚠️ **合并后跑全量**（后端 pytest + 前端 vitest + ruff）。
⚠️ **别顺手删别人的分支**（仓库里有 50 多条历史分支，不是我们的）。
