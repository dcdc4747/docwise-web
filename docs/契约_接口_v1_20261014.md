# 接口契约 v1（冻结基线 + 新增端点）

> **冻结日期**：2026-10-14 ｜ **基线提交**：`main` @ `a998585`
> **性质**：**这份文件是接口的唯一权威**。前端可以对着它先写、用 mock；后端照它实现。
> **改这份文件 = 一次 PR**（改完要同步 `docs/代码架构图.md`）。
> **本文件的数字都是实测**：基线 23 个端点，逐个从 `backend/app/routers/*.py` 的装饰器抄下来的。

## 0. 通用约定（**所有端点都适用，不再逐条重复**）

| 项 | 约定 |
|---|---|
| **前缀** | 业务接口 `/api/...`；文件 `/files/...`。**新端点一律挂在 `/api/` 下** |
| **鉴权** | 除 `/api/health`、`/api/auth/register`、`/api/auth/login`、`/api/auth/demo-login` 外，**全部要求** `Authorization: Bearer <令牌>` |
| **归属** | 所有带 `{task_id}` 的端点先 `load_owned_task`——**不是本人一律 404**（不暴露"存在但无权限"） |
| **错误体** | FastAPI 默认 `{"detail": "<人话中文>"}`。**`detail` 必须是能给用户看的中文**，不许出现英文栈或字段名 |
| **时间** | 所有时间戳一律 **UTC + 带时区偏移**（`2026-10-14T03:40:10+00:00`），由 `app/timeutil.py::iso_utc` 产出。**前端按本地解析，不许再做时区补偿** |
| **枚举** | 小写下划线字符串；**不许在前端重新定义一套判断**（语言对、native、块类型都由后端给） |
| **404 / 401 / 403 分工** | 未登录 → **401**；登录了但不是本人 / 不存在 → **404**；是本人但无管理员权限 → **403** |
| **分页** | 本期**统一不分页**（数据量 ≤ 数百）。长列表见设计规范 §7.9：`≥50` 篇时才做"加载更多" |
| **新增字段** | **只许追加**，不许改名 / 改类型。前端必须容忍未知字段 |

## 2. ⭐ 新增端点（本期要做的，先冻结再动手）

> **命名规矩**：资源用复数名词（`collections` / `tags` / `materials` / `drafts`）；子资源挂父资源下；**动词一律避开**（用方法表达）。

### 2.1 知识库 · 集合（M1，4 个）

| # | 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|---|
| N1 | GET | `/api/collections` | — | `200 {items: [{id, name, parent_id, sort, doc_count, doc_count_deep}]}` |
| N2 | POST | `/api/collections` | `{name: 1–64, parent_id?: int\|null}` | `201 Collection` ｜ 400 重名（**同一父下不许同名**）/ 父不存在 |
| N3 | PATCH | `/api/collections/{id}` | `{name?, parent_id?, sort?}` | `200 Collection` ｜ **400 成环（不许把自己移进自己的后代）** |
| N4 | DELETE | `/api/collections/{id}` | — | `200 {deleted: true, moved_to_parent: n}` ｜**只删集合，不动文献** |

⭐ **两个计数都要给**（形态 §2.3 / R4）：`doc_count` = **直接成员数（主数，和删改语义一致）**；`doc_count_deep` = 含子集合的聚合数（**括号辅数**）。
⚠️ **语义定死（照抄 Zotero，别发明第三种）**：**子集合的文献不算在父集合里**。

### 2.2 知识库 · 文献归集与标签（M1，4 个）

| # | 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|---|
| N5 | PUT | `/api/tasks/{task_id}/collections` | `{collection_ids: int[]}` | `200 {collection_ids}`（**全量替换**，天然支持"一篇挂多个"） |
| N6 | GET | `/api/tags` | `?kind?` | `200 {items: [{id, name, kind, doc_count}]}` |
| N7 | PUT | `/api/tasks/{task_id}/tags` | `{tags: [{name, kind}]}` | `200 {tags}`（**按名字 upsert**；`kind ∈ {topic, method, status}`） |
| N8 | GET | `/api/tasks` | `?reading_status?` `&collection_id?` `&tag[]?` `&smart_id?` `&unfiled?` | 复用基线 #1，**追加五个查询参数** |

⚠️ **`reading_status` 是"属性"不是"归属"**——它是文献自己的状态（待读/在读/已读），**跟文献走**；集合是"人的组织"，**跟人走**（形态 §2.1 第 3 条）。所以它落 `tasks` 表列，**不落关联表**。

⭐ **N8 四个参数的口径（2026-10-16 补写；实现与前端 mock 逐字一致）**

原来只列了参数名、没定语义，前后端各写一套必然漂移。现在定死：

- 多条参数之间是 **AND（交集）**，不是并集；
- `reading_status ∈ {todo, reading, done}`，按 `tasks.reading_status` 精确匹配；
- `collection_id` 按**直接成员**算——**子集合的文献不算在父集合里**（与集合计数同一条语义，见数据模型契约 `Collection`）；
- `tag[]`（`?tag[]=A&tag[]=B`；手写成 `?tag=A` 也收）：**每个标签都要命中**；
- `smart_id`：套那条智能集合的 `query` 规则（§2.3 的 `field/op/value`）；
- ⭐ `unfiled=1`（**2026-10-17 新增**）：**只回没进任何集合的文献**——左栏「未归类」那一档，
  与 Zotero 的 Unfiled Items 是同一件事。⚠️ 与 `collection_id` 同时传没有意义
  （"既在 X 集合里又没进任何集合"），**照实回空**、不报错；
- ⭐ **响应追加 `collection_ids: [int]`**（同日新增，属"给基线响应加字段"，**不是新端点**）：
  这篇文献当前在哪些集合里。加它的原因很具体——`PUT /api/tasks/{id}/collections`（N5）是
  **全量替换**，前端不知道当前归属就发请求，会把已有归属悄悄抹掉；
  ⚠️ **查不到的 `smart_id` 返回空数组**，不报错——契约没为它定义错误，
  而"这条规则下没有你要的文献"本来就是合法结果；
- **一个参数都不传时，行为与以前完全一致**（裸数组、最多 50 条、`archived_at` 非空的不返回）；
- 归档的文献在**任何筛选下都不出现**（藏 ≠ 删）。

### 2.3 知识库 · 智能集合（M1，3 个）

| # | 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|---|
| N9 | GET | `/api/smart-collections` | — | `200 {items: [{id, name, query, count, builtin}]}` |
| N10 | POST | `/api/smart-collections` | `{name: 1–64, query}` | `201` ｜ 400 query 非法 |
| N11 | DELETE | `/api/smart-collections/{id}` | — | `200` ｜ **400 内置规则不许删** |

⭐ **`query` 是数据不是代码**（形态 §2.3 的"规则即数据"）：
```json
{"all": [{"field": "reading_status", "op": "eq", "value": "todo"}]}
```
- `field ∈ {reading_status, tag, collection, native, text_source}`；`op ∈ {eq, in, not_in}`。
- **内置三条**（随迁移脚本种下、`builtin: true`、**不可删**）：待读 / 在读 / 已读。
- **本期不做查询构建器**。第二档（"把当前筛选存为智能集合"）**要保留接口形状**：POST 同一个端点、传当前筛选序列化结果即可。
- **判据**：任何一条智能集合，**规则必须能在界面上显示出来**（悬停或点开显示"规则：状态 = 待读"），否则退化成硬编码。

### 2.7 收口检查（M4，2 个）

| # | 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|---|
| N22 | POST | `/api/check` | `{draft_id, doc_text: string}` | `200 CheckReport` |
| N23 | GET | `/api/check/{run_id}` | — | `200 CheckReport`（供导出与刷新后回看） |
| **N43** | GET | `/api/check` | `?draft_id?` `&limit?`（上限 50） | `200 {items}`，每条只带摘要 | — |

**`CheckReport`**：
```json
{
  "run_id": 12,
  "ruleset_version": 1,
  "step": {"lang": "zh", "citation_style": "numeric|author-year|unknown"},
  "findings": [
    {"id": "f1", "kind": "missing_citation|term_inconsistent|format",
     "severity": "report|unknown",
     "sentence": "…", "reason": "命中词：研究表明；前方 8 字内无豁免词",
     "suggest": {"material_id": 7, "page": 2, "quote": "…"},
     "rule_ref": "§3.3 ②A 类"}
  ],
  "summary": {"reported": 0, "unknown": 0}
}
```
⚠️ **`unknown` 是一等公民**（诚实档）：**"未能识别引用制式"、"图注字号"这类输入里没有的信息，正确输出就是 `unknown`，不是硬猜、也不是静默跳过**。

### 2.10 记忆（M7，**5 条路由**）

> **⚠️ 这一节是"契约外的新东西"，动手前先说清它是什么。**
>
> **记忆 ≠ 台账**：台账是 `memory_events`（L0 环节流水，"几点几分做了什么"）；
> **记忆是结论**（"这个人习惯把 `chiral` 叫手性"）。两者不是一回事，**别互相替代**。
> 数据模型 §2.8 给 `memory_events` 留了 `layer = L0/L1/L2`，但**这一节没有走那条路**——
> 记忆要一条条看、一条条改、一条条删，塞进流水账的 JSON 里做不了界面（理由见 PR）。
>
> **记忆 ≠ 素材卡**：素材是"从文献里取出的证据"（有出处、有页码）；记忆是"这个人的说法与偏好"
> （没有出处，是习惯）。数据模型 §4 已写明别把素材当记忆存。
>
> ⚠️ **句级纠错记忆（D8 的第三类）不在这里**：它唯一的来源是 `block_edits`，
> 而那张表**现在 0 行**（没人点过"改译文"）。形态 §5 写死了前提——
> `观测期 ≥14 天 且 曝光块数 ≥500` 之前一律"继续观测"，**现在建就是空壳**。

| # | 方法 | 路径 | 请求 | 响应 | 错误 |
|---|---|---|---|---|---|
| **N35** | GET | `/api/memories` | `?kind? &enabled? &limit?`（默认 500 / 上限 2000） | `200 {items: MemoryItem[], counts, enabled_counts}` | 400 `kind` 不认 |
| **N36** | POST | `/api/memories` | `{kind, source, target, enabled?}` | `201 {item, created}` | 400 空 source/target 或 `kind` 不认；503 写不进去 |
| **N37** | PATCH | `/api/memories/{id}` | `{target?, enabled?}` | `200 {item}` | 404 别人的或不存在；400 两个字段都不给 / target 空；503 |
| **N38** | DELETE | `/api/memories/{id}` | — | `200 {deleted, id}` | 404 同上；503 |
| **N39** | GET | `/api/memories/resolve` | — | `200 {terms, cite, counts}` | — |

**`MemoryItem` 形状**：`id, kind, source, target, hits, enabled, created_at, updated_at`

六条口径（**别自己发明**）：

1. ⭐ **`kind` 只有两种**：`term`（术语/译名偏好：`source` = 原文里的词，`target` = 这个人习惯的译法）、
   `cite`（引用习惯：`source` **固定归一成 `default`**，`target` = 习惯的引文格式标识如 `author-year` / `numeric`）。
   ⚠️ `cite` 的 source 归一化是**故意的**——引用习惯是"一条默认格式"，不该堆出两条。
2. ⭐ **按 `(user_id, kind, source)` 幂等**：同一个人同一个词再存一次是**改**（覆盖 `target`），
   不堆第二行——否则"同一句话两个说法"当场自相矛盾。注意 `cite` 的 source 恒为 `default`，
   所以**引用习惯天然只有一条**。
3. ⭐ **改说法不许把 `hits` 清零**：`hits` 是"这条真被用上过几次"的账，不是这条记录的年龄。
   **`hits` 唯一的用处是让用户看出哪条真在起作用**——界面上**如实显示**，
   **不许当成"聪明度"吹**（那不实）。
4. ⭐ **`resolve` 只回启用的**（`enabled=false` 不注入），**取过的条目 `hits += 1`**。
   它的语义就是"要拿去用了"，所以计数在这里；调用方**别把它当普通列表接口反复调**。
   计数写失败**不影响本次注入**（不能因为记不上账就把记忆丢了）。
5. ⭐ **`counts` 用全量、`items` 才受筛选影响**：否则界面上"术语习惯 12 条"与列表里的条数
   会互相矛盾。
6. ⭐ **能改、能停用、能真删**（形态 §六"可看可删可下钻"）：
   `enabled=false` 是"先别用，但别丢"；`DELETE` 是**真删**。
   ⚠️ **记忆不是留痕**——留痕（`block_edits` / `memory_events`）不许删，
   而记忆是用户自己的偏好，**他说删就该真删掉**。
   ⚠️ **系统不许背着人改**：只有用户自己（或他明确点头的动作）能写这张表，
   **自动学习不在这条链的范围里**。

⚠️ **记忆挂在用户身上，不挂任务**（表里**没有 `task_id`**）：源文献删了，记忆还在——
它是"这个人的习惯"，不是"这篇文献的属性"。

⚠️ **注入（`_enrich()` 那一步）到这一步为止还没接**：`resolve` 已经把数据备好了，
把它喂给哪条链路要单独定（见下一条"还没做的"）。
（**2026-10-17 补记**：注入已经接了，问答与导读两条链路都会带上它，见 `app/memory.py`。）

### 2.11 个人偏好（F 卡，**2 条路由**）

> **⚠️ 这一节也是"契约外的新东西"**：`N40 / N41` 是 2026-10-17 新加的，
> 原来偏好**只活在本机 `localStorage.docwise_prefs`**，换设备就没了
> （`useReader.js` 里那句注释写的就是这件事）。
>
> **偏好 ≠ 记忆**：偏好是**界面怎么表现**（默认读法 / 默认档位 / 字号 / 动效）；
> 记忆（§2.10）是**跨文献的用法说法**（术语怎么叫、引用什么格式）。两张表、两套端点，**别合并**。

| # | 方法 | 路径 | 请求 | 响应 | 错误 |
|---|---|---|---|---|---|
| **N40** | GET | `/api/me/preferences` | — | `200 {prefs}`（**没存过回 `{}`，不是 404**） | — |
| **N41** | PUT | `/api/me/preferences` | `{prefs: {...}}` | `200 {prefs, updated_at}` | 400 非标量值 / 键太多 / 包太大 |

五条口径（**别自己发明**）：

1. ⭐ **整包覆盖（PUT 语义）**：请求里没给的键就是**不要了**。
   想改一项也得把整包发上来——前后端都照这个口径，别一边 merge 一边覆盖。
2. ⭐ **一个用户一行**（`user_prefs.user_id` unique）：有就改、没有就建，
   免得留下两行"谁的偏好算数"说不清。
3. ⭐ **值只能是 JSON 标量**（`bool / int / float / str / null`），键 1–64 字、最多 32 项、整包 ≤8KB。
   嵌套结构**直接 400**（否则"整包存 JSON"迟早变成一个能塞任意东西的口袋）。
4. ⭐ **服务端是权威，`localStorage` 是缓存**：阅读页要**同步**读偏好（等不了网络往返），
   所以缓存必须留；但**取到服务端那份就以它为准**。
   ⚠️ **一次性迁移**：服务端空、本机**真存过** → 把本机那份推上去（老用户不许被"升级清空"）。
5. ⭐ **注销账号要连偏好一起删**（`user_id` unique，留着就是一条永远对不上人的孤儿行）。

**`prefs` 这一版只认四个键**（前端只写这四个；读到不认识的值一律回落默认，不猜）：

| 键 | 取值 | 作用 |
|---|---|---|
| `defaultView` | `blocks` / `mono` / `dual` | 打开文献时的默认读法（v1 的 `pdf` 档在 v2 没有对应模式，已去掉） |
| `tier` | `fast` / `medium` | 上传卡的默认档位（精档已从界面撤下） |
| `readingSize` | `small` / `normal` / `large` | 阅读区字号缩放 |
| `reducedMotion` | `true` / `false` | "动效跟随系统" |

## 3.5 ⭐ 机器闸：契约与代码的一致性检查（**2026-10-14 新增**）

**人读的契约会漂移，机器不会。** 所以本契约在 `backend/` 下配了一份机器可读清单：

| 文件 | 作用 |
|---|---|
| `backend/.contract/api.json` | **anchors**（冻死的路由，一个个手写）+ `declared_endpoint_count` + `expected_new` |
| `backend/scripts/check_contract.py` | 比对清单与代码；`--print` 打真实路由、`--print-all` 连非 /api 的一起打（排查用） |
| `backend/tests/test_contract.py` | 把它挂进 `pytest`，这样 CI 不用另加 step 也能守 |

```bash
cd backend
python scripts/check_contract.py     # 通过 → 0；不一致 → 1
```

**它守三件事（三种漂移各一条）**：

1. **锚点删了/改名了/换方法了** → 红（契约不允许悄悄改）；
2. **代码里冒出契约没声明的路由** → 红（新端点必须先写进契约，前端才有得对）；
3. **端点总数对不上声明** → 红（⚠️ **这条是故意冗余的**：上面两条只比对"声明过的"，
   新增端点如果不写进清单，前两条会**静默通过**——没人声明它，自然既不缺也不多余）。

**加端点的正确动作**：先改本契约 → 改 `api.json` 的 `anchors` 与 `declared_endpoint_count` → 再写代码。
