### 1.2 一次上传的完整数据流

```text
POST /api/tasks/upload（multipart：file + tier + source_lang + target_lang）→ 202 立即返回
  → worker 扫表认领（行锁）→ 线程池里起引擎子进程
      ├─ 有文字层 → 取字（块号 p{页序}_b{块序}，页序从 0 起）+ 版面信号
      ├─ 无文字层 → 自动转本地 OCR（同一页内按基线间距合并段落）
      └─ 外文 → 翻译（快/中档）→ 双语稿 + 纯中文稿；中文 → 不翻译（产物＝原稿副本）
  → 解析引擎日志里的 tqdm 进度 → tasks.progress / eta_seconds / stage（只增不减）
      → SSE 推给前端（前端另有轮询兜底）
  → 理解层按需（惰性）：POST /understanding → 导读 5 字段 + 术语表（每条带 source_block_ids）
  → 问答：POST /api/tasks/{id}/ask → 答案 + source_block_ids（后端校验这些块真在本任务里）
  → 每一步写环节台账 memory_events（actor ∈ {local, api, user}）
  → 素材卡：POST /api/materials（出处四字段**创建时深拷贝**）
  → 起草：drafts / citations（CSL-JSON）；点 [1] 回原文走阅读区同一条跳转链路
  → 收口：POST /api/check → CheckReport 落库（check_runs）；导出走前端纯函数层
```

## 二、技术栈与依赖红线

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | **Vue 3**（组合式 API）+ **Vite** | **不引 vue-router**（手写哈希路由 `router.js`）、**不引 Pinia**（用普通组合式函数模块当 store）；测试用 **vitest + happy-dom**，PDF 用 **pdf.js** |
| 后端 | **FastAPI** + **SQLAlchemy ORM** + **SQLite** | 单进程 worker；**运行时依赖只允许 6 个包** |
| 引擎 | 子进程 + 独立环境 | 翻译 / OCR / 结构解析全部在引擎侧，后端只负责编排与落库 |

**后端运行时依赖白名单**（现场数：`backend/pyproject.toml`，共 6 个）：

```text
fastapi · python-multipart · uvicorn[standard] · sqlalchemy · pydantic-settings · httpx
```

**为什么要这条红线**：后端是"编排器"，不是"算法容器"。翻译、OCR、版面/结构解析这些重依赖（PyMuPDF、ONNX 运行时、排版与富文本栈）放进后端会带来三件事——部署变重、升级互相牵制、**一个模型的依赖冲突能弄挂整条服务**。所以规矩是：**重的依赖一律放引擎侧独立环境，用子进程调**；后端只拿 `result.json` 这类结构化产物。

> 这条红线是可验证的：`backend/pyproject.toml` 里除这 6 个之外只有 `ruff` 与 `pytest`（dev 依赖）。

### 3.2 为什么是"单进程 worker"

- **SQLite 是单写者**：所有写库收敛到一条写路径，避开写锁竞争；
- **SSE 靠进程内事件总线**（`app.state.event_bus`）——多进程会直接失去这条通道；
- 因此**禁止 `--workers N`**，也禁止引入跨进程 pub/sub。

代价与应对：worker 是串行的，所以队列可见（任务详情给 `queue_position`），并且**单任务异常不杀循环**（一个任务失败不影响后面排队的）。

### 3.3 进度、取消、重试

| 机制 | 实现要点 |
|---|---|
| **诚实进度** | 进度只来自引擎自己打在 `engine.log` 的 tqdm；worker 每 **1.5s** 搬运到 `tasks.progress/eta_seconds/stage` 并推 SSE；**只增不减**（引擎分阶段重跑会跳回 0，跳回去像坏了）；"已用时间"由 `started_at`/`finished_at` 算，是主指标 |
| **取消** | `POST /cancel` → 跑着的**真杀掉引擎子进程**（所以用 `Popen`，且子进程要设 `PYTHONUNBUFFERED=1`，否则进度攒着不落盘）；排队中的直接置终态。**取消是第四个终态**，SSE/前端/健康检查都要认它 |
| **取消信号** | 只由 `worker.request_cancel()` 发；接口层不许抢着写终态（会和 worker 落库打架） |
| **删除** | SQLite 外键没开级联 → **必须手工删子表**（`_purge_task_children`）；磁盘产物一起清，启动时回收孤儿目录 |

## 四、接口面与契约闸

### 4.1 数字（现场跑契约闸）

```text
cd backend && python scripts/check_contract.py
→ 锚点 63 条全对上 / 待实现 0 条 / 代码里共 63 个 = 声明的 63 个   （退出码 0）
```

⚠️ `docs/契约_接口_v1_20261014.md` 的 §3 合计表里有一个更小的数（58），**该文档自己也写着"别拿它当现在有多少个端点"**——**唯一真源是 `backend/.contract/api.json` 的 `declared_endpoint_count`**。

### 4.2 契约闸守三种漂移

| 漂移 | 后果 | 闸怎么拦 |
|---|---|---|
| **锚点被改**（已冻结的路由被改名/改方法） | 前端与 mock 一起失准 | 逐个手写的 `anchors` 列表比对 |
| **冒出未声明的路由** | "偷偷加了端点却没更新契约"——前端对着 mock 写完了才发现形状不对 | 与 `anchors` 对账，多出来的就红 |
| **总数对不上** | 单条改动看不出来，累积成"契约失效" | `declared_endpoint_count`（**故意冗余**） |

**加端点的正确顺序**：先改契约文档定稿 → 改 `api.json` 的 `anchors` 与 `declared_endpoint_count` → 再写代码。

**通用约定**：新端点一律挂 `/api/`；除 health / register / login / demo-login 外**全部要 Bearer 令牌**；**未登录 401 / 非本人 404 / 无权限 403**；错误体统一 `{"detail": "<人话中文>"}`；时间一律 UTC 带偏移；**新增字段只许追加**，前端必须容忍未知字段。

### 4.3 三种"浏览器带不了请求头"的请求

进度推送（SSE）、PDF 预览、文件下载由浏览器自己发起，**带不了 `Authorization`**，所以走 **`?ticket=` 临时票据**：绑定 `用户 + 任务 + 用途`，**60 秒内可重复使用**（不是一次性消费——否则同一页面多次取 URL 会互相把票用掉，表现为"有时打不开"）。

⚠️ 例外：pdf.js 按需分片加载会超过 60 秒，所以**PDF 内容不用票据**，改走 `authFetch` 取 `ArrayBuffer` 一次性喂给 `getDocument({data})`。

### 5.1 表（现场枚举 `Base.metadata.tables`，共 19 张）

| 素材与写作 | `materials` · `drafts` · `citations` |
| 台账与埋点 | `memory_events` · `block_edits` · `block_exposures` |
| 收口 | `check_runs` |

⚠️ **文档滞后一处**：`docs/契约_数据模型_v1_20261014.md` 与 `docs/代码架构图.md` 写的是 18 张（7 + 11 名单），差的那张是 **`check_runs`**（收口检查报告落库，N22–N23 时新增）。**以 19 为准**。

### 5.2 三条关键设计

**① `materials` 是快照，不是活引用。**
`text_quote` / `translated_quote` / `page` / `source_name` 在**创建时深拷贝**。这才让"**删掉源任务后素材卡仍显示出处**"这条判据成立；`task_id` 变 null 但卡还在（**不级联删**）。回跳原文时若源已删，界面如实说"源文献已删除，仅存快照"——**不许用 JOIN `tasks` 取来源名**（那就退回活引用，判据当场失效）。

**② `memory_events` 是"AI 使用台账"与"处理过程一屏"的唯一真源。**
`actor ∈ {local, api, user}` 就是"数据流向"的机器证据；**写入方是服务端**（前端只能 GET，不许手工埋点）；记录失败只打日志、**不让任务失败**；`payload` 只放中性标识（模型名、参数、条数），**不放密钥与提示词全文**。

**③ 埋点口径（修改率）写死在契约里。**
修改率 = **被改块数 / 被曝光块数**——**不是总块数**（用总块数会把真实的 18% 稀释成 7%，直接改变"建不建记忆"的结论）；生效前提：观测期 ≥ 14 天且曝光块 ≥ 500；引用这个数字必须带前提"**这是在提供了编辑入口的条件下测的**"（观察者效应）。`block_exposures` 按 `(user_id, task_id, block_id, session_id)` 唯一，**重复上报不长新行、只把离开时间往后推**。

### 5.3 迁移八条硬规矩

放 `backend/scripts/migrate_<主题>.py`；**默认 dry-run**（打印将要做什么、一行不写）；**`--apply` 才写**；**幂等**（连跑两遍第二遍无操作）；**带 `_migration_marker`**；**可撤 / 有反向脚本**；**不许动 `backend/data/` 里的真实数据文件**；新表建完要跑 pytest **并手测一次"空库从零建"**——`create_all`（新库）与迁移脚本（老库）两条路径的字段必须一模一样。

**现有 7 张老表只许加列**（本期唯一改动是 `tasks.reading_status`，取值 `todo`/`reading`/`done`，默认 `todo`）。

### 5.4 检索

SQLite **FTS5 + trigram** 分词（`unicode61` 不拆 CJK，`实*` 零命中）：查询词 = ASCII ≥3 字 + CJK 三字滑窗（去虚词）；2 字词（如"方法"）走 `LIKE %词%` 兜底；**检索必须限定任务**——`block_id` 跨任务会重名，不限定会把别的论文的块当出处，而前端按当前任务解析后**看不出引错**。SQLite 下 `bm25()` 必须写表真名。

## 六、引擎侧

### 6.1 选引擎看"语言对"，不看档位

| 语言对 | 走哪条路 | 产物 |
|---|---|---|
| `zh → zh`（中文文献） | **NativeEngine**：子进程跑 `scripts/extract_blocks.py`（PyMuPDF 抽段落块） | `mono` = 原稿副本、`dual` = null、每块 `translated` = null |
| `zh → en` / `en → zh` 等 | 翻译引擎（**快档 / 中档**） | 双语稿 + 纯中文稿 |
| 无文字层（扫描件） | 自动转**本地 OCR**（`scripts/ocr_blocks.py`，离线、零成本、模型随包自带） | 同上；界面如实标注"字由 OCR 识别，可能有个别错字" |

⚠️ **只判源语言是错的**：`is_native_pair(source_lang, target_lang)` 必须**两个都是中文**才走取字；`zh → en` 是翻译任务。
⚠️ **没有译文不是缺陷**：中文文献的块 `translated` 一律 `null`，**凡是要读块文字的地方都用 `translated or text` 兜底**——理解层因此零改动即可用。

**档位只有两档**：快 / 中。精档已从界面撤下（它在 `engine/registry.py` 里一直映射到中档、没有审校步骤，界面却写"最准，多一道审校"，属**不实宣称**）；后端 `Tier.PRECISE` 枚举**故意保留**（老任务数据与 `Tier()` 校验要用）。

### 6.2 版面量与块分级

- **块分级只有一处判定**：`app/blocktypes.py`（纯函数、当场算、不落库——所以老任务立刻生效、没有回填问题）。
- **三条取字路"谁手里有版面量谁就往块上带"**：文字层 ✅（字号 + 加粗 + 位置）、外部翻译引擎 ✅（字号 + 位置，给不出加粗）、扫描件 OCR ✅（行高 + bbox）。
- ⚠️ **判定不跟着走**：各判一遍类型口径必然漂移。
- ⚠️ **判不出来的那一类是上游没给**（翻译引擎那条路的块流里没有独立章节标题，实测化学那份 182 块里 `introduction`/`references`/`abstract` 出现 0 次）——**别为了让界面上有标题，就把正文块硬判成标题**。

### 6.3 OCR 与段落合并（数字都是量出来的）

- **不用"倍数 × 行高"**：OCR 框紧贴字形，同页行高能差 25% → 改用**基线间距**判（≤ 1.25 × 基准算同段）；
- **行距基准必须按栏筛**：双栏页里按 y 排序的"相邻两行"常分属左右栏（实测间距只有 4–10px，真行距 31–37px），会把基准拉低一半；
- 样本 < 4 条不敢信基准；合并用**并查集**。**改前 246 段 → 改后 46 段**。

### 6.4 结构解析跑在引擎侧

标题层级 / 表格 / 公式 / 参考文献区由**引擎侧**解析（选型见 `docs/结构解析选型记录_20261015.md`），结果进 `tasks.structure`，目录据此从平铺变树：**结构优先、`block_id` 为 null 的条目不可点、没有结构就退回平铺**。理由与 §2 的红线一致：解析器是重件，不进后端 venv。

## 七、关键工程决策与踩过的坑

| # | 决策 / 坑 | 要点 |
|---|---|---|
| 1 | **单进程 worker + SQLite 单写者** | 见 §3.2；禁用 `--workers N` |
| 2 | **前端挂载必须写在 `main.py` 最后** | Starlette 按注册顺序匹配，写在前面会把 `/api/...` 吃成静态文件 |
| 3 | **SPA 回退只捕 Starlette 的 `HTTPException`** | `fastapi.HTTPException` 是它的子类，写成那个就永远接不住 404；且 `/api`、`/files` 下的未知路径**不参与回退**（保持 JSON 404——回退成 HTML 会让前端错误处理拿到页面源码） |
| 4 | **`sanitize_proxy_env`** | 把 `NO_PROXY` 里带方括号的 IPv6（`[::1]`）改成 `::1`。不洗的后果很重：引擎在**导入期**就 import ollama → httpx 拿 `NO_PROXY` 建 URLPattern → `InvalidURL` → **引擎一行没跑就崩、任何上传都失败**。`llm.py` 导入时也洗一次 |
| 5 | **诚实进度** | 见 §3.3；tqdm 用 `\r` 原地重绘 → 按 `[\r\n]+` 切开取最后一条；子进程设 `PYTHONUNBUFFERED=1` |
| 6 | **FTS5 用 trigram 且必须限定任务** | 见 §5.4 |
| 7 | **块分级只判一处** | 见 §6.2 |
| 8 | **时间口径唯一入口** | 库里一律 UTC（naive）、接口一律带时区；自洽判据：`started_at - created_at` 应该是**几秒**（迁移前是 8 小时） |
| 9 | **结果文件一律落 `storage.outputs_dir(task_id)`** | 不用 `tempfile.mkdtemp`；删文件必须过 `storage.remove_file/remove_dir`（只删 `data/` 以内，防记录里的路径被人改过） |
| 10 | **引擎子进程用 `Popen` + 输出重定向到文件** | 只有 `Popen` 能中途终止；用管道会互相卡死、日志也留不下来 |
| 11 | **前端模板里要渲染的值一律用 `computed`/`ref`** | 真出过事故：模板里把函数当值插值（少写一对括号），Vue `String(fn)` 会把**整个函数源码印在页面上**，而 `vite build` 一声不吭。所以有冒烟用例断言页面文本不含 `function `/`=>`/`{{` |
| 12 | **PDF 视图用 pdf.js 而不是 iframe** | iframe 拿不到 DOM 与文字位置 → "点出处跳到那一段""点 PDF 里的段落提问"**物理上做不到**；同一个 canvas 并发 `page.render()` 会直接抛错 → 必须串行渲染链；缩放变化要先 `task.cancel()` 再重画 |
| 13 | **改了 `sw.js` 或应用壳要升 `CACHE_NAME`** | 否则用户一直吃旧壳、刷新也看不到新版本 |

## 八、部署形态

### 8.1 同源部署（推荐演示与手机真机）

```bash
cd frontend && bun run build                 # 出 frontend/dist
cd ../backend && uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
# 手机连同一 Wi-Fi 打开 http://<电脑局域网IP>:8000/（启动日志直接列出内网地址）
```

**一个地址同时给页面与接口**——不用拼 `?apiBase=`、也不用配 CORS。实现要点（`webapp.py`）：

- 挂载点之后**不许再有 `/api`、`/files` 路由**（有结构性用例在守）；
- 只有 `Accept: text/html` 的浏览器导航才回退 `index.html`；
- `index.html` / `sw.js` / `manifest.webmanifest` 发 `Cache-Control: no-cache`（防装了 PWA 的手机吃旧壳）；
- 产物不存在只跳过挂载 + 打一条日志（**开发态不构建也能起服务**）；`DOCWISE_SERVE_FRONTEND=0` 关闭、`DOCWISE_FRONTEND_DIST=<路径>` 改位置。

⚠️ **改完前端要重新 `bun run build`**——后端只负责端出去、不会替你编译。

### 8.2 与"生产就绪"的差距（如实列）

| 项 | 现状 |
|---|---|
| 数据库 | SQLite 起步（WAL + busy_timeout）。将来换 PostgreSQL 只改配置（统一走 SQLAlchemy ORM），但**迁移脚本与 FTS5 用法需要一次专项适配** |
| 进程模型 | 单进程 worker：串行处理，**不适合多实例横向扩展**（事件总线在进程内） |
| 引擎环境 | 需要 `DOCWISE_ENGINE_*` / `DEEPSEEK_*` 写入 `backend/.env`（启动时自动注入）；未配置时创建任务会**如实失败并显示原因**（属预期行为，不是 bug） |
| 备份 | 有 `scripts/backup_db.py`（`VACUUM INTO` 备份 + 只留最近 N 份）；**没做**自动定时与异地 |
| 观测 | 有轮转日志与 `/api/health` 真检查；**没有**指标/追踪系统 |
