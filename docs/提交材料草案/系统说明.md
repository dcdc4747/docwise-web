## 一、这是什么

**docwise-web 是一个文献理解与写作辅助平台。**

它把"读文献 → 攒素材 → 写稿 → 查引用"这一条链放在同一个工作区里，三个模块**彼此独立、又可以合作**，**共享同一套文献资产**：

| 模块 | 干什么 | 能不能单独用 |
|---|---|---|
| **读懂** | 读一篇文献：段落精读 / 原版 PDF / 纯中文 / 双语对照；结构化导读、术语表、带出处的问答 | 是 |
| **起草** | 写稿：素材栏 + 草稿区 + 助手（提纲 / 引用 / 过程）；把素材插成引文，点引文回原文 | **是——不需要先有文献** |
| **收口** | 检查稿子：该引未引、术语一致性、格式自检 | 是（入口在起草页里的检查抽屉） |

**对象是文献本身，不限于外文**：外文文献译成中文并保留原排版（纯中文稿 / 双语对照稿）；**中文文献不翻译**，直接抽文字层进理解层；没有文字层的扫描件自动走**本地 OCR** 兜底。

### 差异化只有一句

> **每条结论都能点回原文那一句。**

同类文献工具普遍管到**文献级**——"推荐你读这篇"；我们管到**句级**——"这个结论来自第 2 页的那一句"。

这句话在产品里是可以被验证的，不是文案：

- 导读的每一条、问答的每一条答案，都带出处；**点出处会滚到原文那一段并高亮那几句**；
- 出处只有一种写法：**「第 X 页 ·「这一句的开头…」」**——**不写"第 Y 段"**（段号靠 PDF 版面切分算，实测在没见过的期刊上只有五六成准；**不准的段号比没有更糟**，用户会拿它去数，数不上就不信整条出处了）；
- **推导不出位置就写"位置待定 / 出处未能定位"**，并如实说明为什么——**绝不假高亮、绝不裸露块编号**（块编号是内部标识）；
- 没有出处的要点**置灰、不可点**：**死链不许做成活链样式**。

## 二、它解决谁的什么问题

**主要用户**：需要读大量文献并写出带引用规范的稿子的学生与研究者（学位论文、开题报告、综述、期刊投稿）。

三条真实的痛点，对应产品的三个模块：

| 痛点 | 具体表现 | 产品怎么接 |
|---|---|---|
| **读得慢** | 外文文献逐句啃；图表、公式、版式在复制粘贴里全丢 | 保留原排版的译文（双语 / 纯中文）+ 结构化导读 + 术语表，**每条都能点回原文那一句** |
| **攒不住** | 读到好句子，写完就找不到它在哪一页、哪一段 | **素材卡**：把证据连同出处**快照**存下来（`来源名 · 第 X 页 ·「原句…」`），插入草稿即成为引文 |
| **写完不知道哪句该引** | 通篇论断没有引用标注，评审一眼看出来 | **收口检查**：该引未引（核心）/ 术语一致性 / 格式自检；**只出报告、不替你改稿** |

⭐ 一条重要的产品判断：**起草与收口可以不经过"读懂"直达**。素材为空时，起草页给的是两个平级出口——「去读懂一篇」和「**不读文献，直接写**」，后者**必须真能用**。这是"三个模块独立"的真实证据，而不是"界面上有几个入口"。

## 三、一条端到端主流程

```text
上传 PDF
  → 取字（有文字层：直接抽；无文字层：本地 OCR 兜底）
  → 分块（每块带版面信号：字号 / 位置）+ 块分级（题名 / 章节标题 / 图注 / 正文）
  → 外文：翻译（快档 / 中档）并出双语稿与纯中文稿；中文：不翻译，出原稿副本
  → 理解层（按需、惰性）：结构化导读（研究问题 / 方法 / 结论 / 创新点 / 贡献）、术语表
  → 问答（一次性模型调用 + 结构化输出 + 后端出处校验）
  → 存素材卡（出处连同页码、原句一并深拷贝）
  → 起草（素材栏 → 插成 [1] 引文 → 点 [1] 回原文高亮）
  → 收口检查（该引未引 / 术语一致性 / 格式自检）→ 导出报告
  → 全程写"环节台账"（这一步是本地做的，还是发往模型 API 的）
```

上传后**立即返回**（任务进入队列），处理过程通过 SSE 实时推送进度，前端也有轮询兜底。

## 四、三个模块在界面上是什么样

### 4.1 读懂

左栏选「读懂」→ 未选文献先进"我的库"；选了就进**阅读工作区**。

- **左：四种渲染**——**段落精读（默认）** / 原版 PDF / 纯中文 / 双语 PDF。
  后三种用 **pdf.js** 渲染（canvas + 文字层坐标），所以**点出处能滚到那一段并画高亮框**，**点 PDF 里的任意一段能「就这段提问」**。
  段落精读按块重排，标题 / 正文 / 图注分层显示，原文小字灰、译文主文，跨页有插页分隔条。
- **右：三个副页签**——问答 ｜ 导读 ｜ 术语。**页签数不增加**：素材不做成第四个页签，而是作为固定区块「本篇已产出」。
- 划词即可提问（提问请求带上"本任务真实存在"的块编号）。
- **段落精读的译文可以人工改**：改过之后那一段标「已人工修改」，并留痕进"AI 使用台账"（改前 / 改后两条）。

**三种产物都能对到段**：双语稿在原页直接搜到；中文文献在原稿直接搜到；纯中文稿靠双语稿的"原页 → 译页"几何参照对齐——**对不上时只翻到那一页并如实说明，绝不假高亮**。

### 4.2 起草（不需要先有文献）

```text
左栏 ｜ 素材（资产层）｜ 草稿 ｜ 助手（提纲 / 引用 / 过程）
```

- **起稿四入口**：模板 / 大纲 / 空白 / 上传自己的文本模板（`.md` / `.txt`）。`template_id` 只存标识、不做版式渲染（契约如此），所以**不预填正文骨架**——预填就等于替你开了头。
- **素材栏**顶部有来源筛选；素材卡上「插入引文」把 `[1]` 落进光标处。
- **点 `[1]` 回原文并高亮那一句**（复用阅读区同一条跳转链路，不另写一套）；**源文献已删**时那个编号是**灰的、不可点**，并写清"源文献已删，仅存快照"。
- ⚠️ **本页一个字都不替用户生成正文**：页面上没有任何"生成 / 续写 / 润色"入口，连注释里也不许出现。这条是产品红线。

### 4.3 收口 ⭐ 是起草页里的**检查抽屉**，不是独立页面

**为什么是抽屉**：收口与起草共用大部分界面元素（文档区 + 报告区），单独成页是重复；做成抽屉后，**检查时能同时看到自己的草稿**（"这句话该引没引"要对着上下文看）。`Esc` 可关、点遮罩可关。

三类检查：

| # | 检查 | 口径 |
|---|---|---|
| ① | **该引未引**（核心） | 标出"有论断、但句内无引用标注"的句子，**并指出该引素材库里的哪一条 · 第几页 · 哪一句** |
| ② | **术语一致性** | 依据"被引文献的术语表"比对，**并列摆出两处原文，不自动改** |
| ③ | **格式自检（最小必要集）** | 引文编号连续性 / 文内编号与文后条目对应 / 条目字段完整性。输入是**我们自己生成的 CSL-JSON**——不接 Word、不做版面分析 |

⭐ **该引未引走的是"最保守判据"，宁可少报**：
① 标记词表命中（数据断言 / 他人观点两类）；
② 句内**无 `[n]` 标注才报**；
③ 有标注、或含模糊限定词（可能 / 或许 / 一般认为）→ 不报；
④ 命中词**前方 8 字内出现「我们 / 本文 / 本工作 / 本研究 / 本课题组」→ 一律不报**（"本研究表明"是作者自己的工作）。

**两个输入盲区在实现里被显式处理**（不是"以后再说"）：

- **判语言**：词表分中文 / 英文两套，先判语言再按语言路由到 `text_quote`（英文稿）/ `translated_quote`（中文稿）；
- **判引用制式**：判据核心是"无 `[n]` → 报"，但**著者-出版年制**的稿子全文没有 `[n]`，会被全部误报（**误报爆炸且爆得隐蔽**）。所以先判制式（顺序编码 / 著者-出版年），**识别不出就明示"未能识别引用制式"并归入「无法判断」档**，不硬猜。

⭐ **`unknown`（无法判断）是一等公民**：报告里它与"该报的"分开单独一栏，不混进计数充数；**汇总只写「报出 N 处，另有 M 处判不出」，不报百分比**。

⭐ **报告可以导出带走**：Markdown（含全部条目 + **筛子账**）与 CSV（一行一条，带 UTF-8 BOM，Excel 打开不乱码）。**"筛子账"就是那句"为什么只报这么少"**——它正是我们与同类工具的差别，所以**不许只导结论**。

> **筛子账**（界面原文示例）：`该引未引：命中标记词 4 句——已有引用 2、含模糊限定 0、属作者自指 2，报出 0 处`。

### 4.4 个人中心与知识库

**个人中心（整页）六个区块**：① 身份（显示名可改、上次登录）· ② 账号安全（改密码 / 登录设备与会话列表，可逐个吊销）· ③ 我的数据（概览 / 磁盘占用 / 一键导出全部数据）· ④ **AI 使用台账**（环节 × 数据流向 × 产出；哪些是 AI 生成的、哪些被人改过并可逐条看 diff；可导出 CSV / Markdown）· ⑤ 偏好 · ⑥ 管理 + 危险区（删除账号与全部数据：说清不可恢复 + 引导先导出 + 二次确认）。

**知识库五个实体**（都在现有 SQLite 里，不引新基建）：

| 实体 | 是什么 |
|---|---|
| **文献** | 一篇读过的文献，带 `reading_status`（待读 / 在读 / 已读） |
| **集合** | 可嵌套的组织容器，**一篇可同时属于多个集合**（不复制） |
| **标签** | 文献的属性，分三类：主题 / 方法 / **状态**（状态类驱动"我今天该干什么"） |
| **素材** | 从文献里取出的**证据快照** |
| **智能集合** | **已保存的搜索规则**，自动更新；**规则在界面上可见**（否则就退化成硬编码） |

**三条写死的语义**（避免将来扯皮）：

1. **子集合的文献不算在父集合里**——集合只含直接成员；展示层用括号辅数「手性课题 3（含子集合共 8）」。**为什么不让步**：改成"包含子项"会让"移出"变得不可预测（从父集合移出，它还在子集合里）。
2. **智能集合是"规则即数据"**——加一条规则在数据里是插一行表，在代码里是改代码 + 测试；**硬编码分支超过 2 处，"规则即数据"就回本**。
3. **一篇可属多个集合**是**待验证假设**：多挂率 < 10% → 退化为单选字段。

## 五、诚实机制（这个产品最"不像 demo"的地方）

这套机制不是合规补丁，而是**产品的信任来源**：

| 机制 | 具体做法 |
|---|---|
| **不编进度** | 进度不是估算的，是**解析引擎自己打在 `engine.log` 里的真实页进度**；**解析不出就显示"引擎还没报进度"**，绝不编百分比。进度**只增不减**（引擎分阶段重跑会跳回 0，跳回去像坏了）；"已用时间"才是主指标，引擎报的页数一律标成"引擎自报" |
| **`unknown` 是一等公民** | 输入里没有的信息，正确输出就是"无法判断"，**不是硬猜、也不是静默跳过**；判不出引用制式时整族不判，并说明为什么 |
| **出处可核** | 出处＝页码 + 那一句的开头；**点它高亮的是原文那几句**（按文字匹配算，不依赖分段）；对不上就只翻页 + 如实说 |
| **"没有"要如实说** | OCR 来的字标"可能有个别错字"；没有块级译文的块不给编辑入口；`last_read_page` 为空时显示「开始阅读」而不是「继续读」，**不假装记得** |
| **AI 参与要标注** | 译文标「AI 翻译」，导读 / 术语 / 问答标「AI 生成」，并给出"怎么核"；**人改过的译文标「已人工修改」，不再标 AI 翻译** |
| **数据流向可查** | 每一步处理都写进环节台账，`actor` 只有 `local` / `api` / `user` 三种；"处理过程"一屏把它摊开 |
| **不宣称未实现的能力** | 曾把"精档（最准，多一道审校）"从界面撤下——因为它在代码里一直映射到中档、没有审校步骤，属**不实宣称**。后端枚举故意保留（老数据与校验要用），但**界面只提供快 / 中两档** |

⭐ 与"数据流向"有关的一条**必须说准的口径**（对外说明也别写错）：

> **取字与扫描件 OCR 是真本地；但外文翻译、扫描件逐段翻译、导读与问答四处仍调用云端模型 API。**
> 准确说法是「**服务自持 + 文献存本地**」——**不写"数据不出本机"**。

## 七、设计取舍与"不做"清单

**做减法比加功能更需要理由**，所以把"不做"写下来：

| 不做 | 理由 |
|---|---|
| 深色 / 沉浸模式 | 段落视图在暗色下成立，但 **PDF 是画布、不跟随主题**；需要一整套语义色重定义 + 逐屏验证 |
| 主题换肤 / 自定义配色 / 插画与吉祥物 / 品牌 VI 重做 | 本阶段做的是"不干扰阅读 + 让溯源成为视觉签名 + 不空"，不是"好看" |
| 玻璃拟态 / 渐变 / 3D / 视差 / 动效"惊喜感" | 读文献时任何多余运动都是干扰 |
| 重基建：向量库 / 状态管理框架 / 迁移框架 / 图数据库 | 现有 SQLite + FTS5 + 手写迁移够用；**后端运行时依赖只允许 6 个包** |
| 用户自定义查询构建器 | 属几千条规模的解法；"预置规则 + 把当前筛选存为"两档已够 |
| 协作 / 共享 | 口径是「单部署、多账号、无协作」——账号只用于**数据隔离与管理** |
| 工作区隔离（一个 notebook 一组来源） | 我们的"读懂"是**跨文献**的，否则"该引哪一篇第几页"就做不成；**工作区是组织，不是隔离** |
| 在手机上做精读 | 手机端定位是"**口袋里的库**"（待读队列 + 素材复习 + 进度查看）；硬塞一个挤巴巴的精读页不如做减法 |

**两条设计原则**（贯穿全部界面）：

1. **颜色里不塞情绪**：`无法判断` 用中性灰（不是红也不是黄）；数据流向靠**图标形状 + 位置**表达，不靠高饱和文字色。
2. **诚实提示必须说"为什么"**：✅「无法判断（稿件未含版式信息）」 ❌「无法判断」——只说结论不说原因，用户既不能判断该不该信，也不知道下一步做什么。

## 八、技术一览（详见《技术架构》）

| 项 | 值 |
|---|---|
| 前端 | Vue 3（组合式 API）+ Vite，**不引 vue-router / Pinia**（手写哈希路由与普通组合式函数模块） |
| 后端 | FastAPI + SQLAlchemy ORM + SQLite（WAL + FTS5 trigram），**单进程 worker** |
| 引擎 | 通过**子进程**调用：快档 / 中档翻译引擎、中文文献取字、本地 ONNX OCR；**重依赖一律放引擎侧独立环境** |
| 接口 | 63 条端点（契约冻结 + 机器闸守漂移：锚点被改 / 冒出未声明路由 / 总数对不上，三种都会红） |
| 数据 | 现有表只许加列；新表一律配迁移脚本（默认 dry-run、`--apply` 才写、幂等、带标记、可撤） |
| 部署 | 同源部署：后端同时提供页面与接口，手机连同一 Wi-Fi 直接访问；缺前端产物时自动跳过挂载（开发态不构建也能起服务） |
| 时间口径 | 库里一律 UTC，接口一律带时区；唯一入口 `app/timeutil.py` |

## 九、后续规划（按依赖顺序）

1. **M7 记忆**：把已经在采的"块改动 / 块曝光"数据变成机制（术语偏好、引用偏好、句级纠错 + 请求前注入），并给出**"术语一致率（有记忆 / 无记忆）"的对照数字**。⚠️ 生效前提写死：观测期 ≥ 14 天且曝光块 ≥ 500；**修改率的分母是"被曝光块数"而不是"总块数"**（用总块数会把真实的 18% 稀释成 7%，直接改变结论），引用这个数字必须带上"**这是在提供了编辑入口的条件下测的**"这句前提。
2. **个人中心偏好接真接口**（先改契约，再改库表与界面），把"偏好只在本机"这条诚实提示去掉。
3. **阶段 3 / 4**：中间表示 DOM + 轻量角色化编排与**质检打回闭环**——这是精档重开的前提。
4. **阶段 7 质量回归**：固定测试集约 20 篇的回归集，把"翻译质量"变成可对照的数字。

## 附：如何复现本文的说法

```bash
# 后端（在仓库根目录下执行）
cd backend
uv run ruff check .                     # 全量 lint（含 scripts/）
uv run pytest -q                        # 后端用例
uv run python scripts/check_contract.py # 契约闸：应打印「锚点 63 条全对上 / 待实现 0 条 / 代码里共 63 个」
uv run uvicorn app.main:app --port 8000 # 起服务，健康检查见 /api/health

# 前端
cd frontend
bun install && bun run test             # vitest
bun run build                           # 产物给同源部署用

# 同源部署（推荐演示与手机真机）
cd frontend && bun run build
cd ../backend && uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
# 手机连同一 Wi-Fi 打开 http://<电脑局域网IP>:8000/
```

> ⚠️ 受限沙箱（无子进程权限）里前端 vitest 可能报 `spawn EPERM`、后端少数需要真起子进程的用例会失败——**那是环境限制，不是断言失败**；以 CI 为准（两个 job：`backend-health` 与 `frontend`）。
