## 二、后端测试

### 2.1 用例规模（**跑出来的**）

```powershell
cd backend
```

### 2.2 本机真跑结果（**如实报告，不含"全部通过"**）

```powershell
& .venv\Scripts\python.exe -m pytest -q
# → 388 passed, 4 warnings, 28 errors in 28.65s   （退出码 1）
```

**那 28 个 `error` 不是断言失败，是环境限制**，而且原因不是"spawn 子进程"：

```text
E  PermissionError: [WinError 5] 拒绝访问。: '...\.dsh-tmp\pyt\pytest-of-shi11'
```

- 出错的是**全仓仅有的三份显式使用 `tmp_path` fixture 的文件**：`test_engine.py`（3）、`test_files.py`（4）、`test_migration_v2_schema.py`（21）——共 28 条；
- 其余测试文件头部都写着「**不用 `tmp_path`（受限环境不可写）**」，改用 `storage` 的模块级目录或 `tempfile.gettempdir()`；
- 这 28 条在 **setup 阶段**就 error，**一条断言都没执行**；
- **三次对照**排除"临时目录没配好"：换全新 temp 目录、用 `PYTEST_DEBUG_TEMPROOT` 覆盖、用 `--basetemp` 单跑这三份 → 结果一致（28 errors）。
  → 结论：**`tmp_path` 这条机制在本机受限沙箱下不可用**，与临时目录的位置无关；**以 CI 为准**。

⭐ **必须纠正一个常见假设**：`test_engine_cancel.py`（"取消能不能真把引擎杀掉"）**本机是过的**：

```powershell
& .venv\Scripts\python.exe -m pytest -v tests/test_engine_cancel.py
# → 3 passed in 0.72s（退出码 0）
```

该文件自己规避了沙箱限制（注释写明：不用 `tmp_path`、不用 `mkdtemp`，改用 `tempfile.gettempdir()` + uuid），所以"取消 → 真杀子进程"这条**本机可自证**，不必让给 CI。

### 3.2 前端为什么"必须进 CI"

**受限沙箱里 vitest 默认跑不起来**，真实报错（连配置都没加载完，**0 条用例执行**）：

```text
failed to load config from …\frontend\vite.config.js
[plugin externalize-deps] Error: EPERM: operation not permitted, uv_spawn 'C:\Windows\system32\cmd.exe'
```

（把 `TEMP` / `TMP` 指到工作区内仍不行——堵的是 vite 在**配置加载期**要 spawn 子进程做 realpath，属沙箱的既定边界；`bun run build` 同一个点失败。）

这正是**必须把前端补进 CI 的原因**（PR #81）：**本地跑不了、CI 又不跑 = 前端完全没人守**。CI 上实测 3.6 秒跑完全部用例 + 构建，所以"跑不了"从来不是性能问题。

> 本次本批两个 PR 的前端用例，是在**临时放宽沙箱并把握 `TEMP` 指进工作区**之后真跑通的（412 条全过）——数字属实，且 CI 上同样会跑。

## 五、真文本验收：收口检查（M4）

⚠️ **口径**：报告格式一律「**报出 N 处、人工判定 M 处成立**」——**不写百分比**（这是文档与界面共同的口径；`M/N < 70%` 只是**判据阈值**，不是结论口径）。分母出处：`docs/m4-验收样例与说明_20261015.md`；结论出处：`docs/m4-验收结论_20261016.md`。

**三篇样例（判引用制式已生效的口径）：报出 4 处、人工判定成立 2 处。**

| 样例 | 报出 | 成立 | 说明 |
|---|---|---|---|
| ① 中文 · 顺序编码制 | 2 处 | 1 处 | 成立＝「调查显示」那句；不成立＝作者自报数据那句（**已知误报**） |
| ② 英文 · 顺序编码制 | 2 处 | 1 处 | 成立＝`reported` 那句；不成立＝`reduced` 那句（**已知误报**）；⭐ **报出的是英文原句**（语言路由生效） |
| ③ **著者-出版年制** | **0 处** | 0 处 | 判出制式 `author-year`（识别到 5 处「（作者，年份）」）；**无 E2 这道闸时是 4 处、全部误报** |

**两个输入盲区的实测**：**E1 语言**——英文稿报出 2 处（词表收窄的第一版是 **0 处**，即"一句都报不出来还说自己支持"）；**E2 引用制式**——著者-出版年制报出 **0 处**；判不出制式时 `reported = 0`、`unknown = 1`。

**两处已知误报点名到句、没有为了让数字好看把它们压掉**：样例一句 6、样例二句 6 都是作者自报数据，但自指词离命中词超过了 8 字窗；**单测里显式断言它们仍然被报出来**（`tests/test_check_samples.py`），本轮**不动窗宽**——按"宁可少报"的反面同样成立：**宁可让它误报一处，也要保证同一条规则可解释**。

**这次验收顺带修掉的四处实现偏差**（都是"看着合理其实错了"）：① 词表比验收口径窄，导致英文稿一句都报不出来；② 英文按子串匹配（`were` 里的 `we` 会误免一大片）→ 改成按词边界；③ 自指窗口写成"句首 → 命中词"（过大）→ 改成"命中词前 8 字 + 命中词本身"；④ 著者-出版年只认「（张三，2024）」不认「Wang 等（2022）」→ 把作者段改为可选。

**边界（如实）**：⚠️ **样例本体（完整原稿）仍不在仓库里**——用例跑的是样例文档里**嵌入的关键样句**；"人工判定成立 M"是**人工逐句核对**的结论（依据写在两张表里），**不是引擎自评**。复现：`pytest -q tests/test_check_samples.py`（**7 条**）。

## 六、其他实测数字（引自仓库实测记录）

### 6.1 块分级（`docs/块分级阈值实测记录.md`）
