## 0. 怎么重新生成（三条命令，工具已装好）

用的是 **[colbymchenry/codegraph](https://github.com/colbymchenry/codegraph)**（**MIT**，73k★，**100% 本地、不上传代码**、索引是 SQLite）。
本机已装（`codegraph --version` → `1.4.1`），索引目录 `.codegraph/` **已在 `.gitignore` 里**（生成物，不进仓库）。

```bash
# ① 建/重建索引（新克隆一台机器跑一次；之后它自动跟随文件变化）
codegraph init

# ② 看规模与构成
codegraph status

# ③ 查"改这个会影响谁" —— 最有用的一条
codegraph impact traceTo          # 换成任何函数/方法名

# ④ 问一个流程问题（返回相关符号的**逐行源码 + 调用路径 + 波及面 + 有无测试**）
codegraph explore "上传一篇文献之后，worker 是怎么一步步处理的"
```

⚠️ **`codegraph` 不是项目依赖**：它对我们的运行时**零影响**（不进 6 个后端依赖、不进 `package.json`）。
**它只是开发期的一面镜子**：换台机器不装它，项目照样跑。

## 3. ⭐⭐ 热点：改哪里会波及谁（这才是这张图的价值）

```
$ codegraph impact traceTo
Impact of changing "traceTo" — 5 affected symbols:
  frontend/src/App.vue
    function  traceTo:565
    function  goOutline:458      ← 目录跳转复用它
    function  locateTerm:902     ← 术语定位复用它
    function  runSearch:1087     ← 搜索复用它
    component App:1
```

**"点出处 → 回原文高亮"这条主线被 4 个功能复用，而它们全在 `App.vue` 一个文件里。**

这一条**用机器证明了两件已经定下来的事**：

| 结论 | 机器证据 |
|---|---|
| **M0 必须先拆 `App.vue`** | 5 个受影响符号全在同一个文件；不拆，任何人动"出处"这条线都在这一个文件里打架 |
| **拆分要"纯搬迁"** | `traceTo` 是共享因子（4 处调用）——**搬迁时语义一个字都不能变**，否则四处一起坏 |

### 三个已知热点（人算 + 机器算，结论一致）

| 热点 | 谁会碰 | 处置 |
|---|---|---|
| `frontend/src/App.vue` | 外壳拆分的 5 步 + 左栏 + 手机标签栏 + 状态条 | **R0 拆完 + R4 预留挂载点**，把后续写入者收敛到 2 处 |
| `backend/app/models.py` | **6 个后续任务**（B1/B2/C2/D1/D2/E6） | **数据层一次性建全部新表**，别人只加路由不改模型 |
| `backend/app/worker.py` + `llm.py` | 台账写入 / 记忆注入 | 只加旁路，**不改翻译行为** |

> 这两条的完整清单在 [`契约_前端命名与拆分_v1`](契约_前端命名与拆分_v1_20261014.md) §0.5「共享接口面」。

## 附：本文的数字怎么来的

```bash
git ls-files | wc -l                    # 受控文件总数
codegraph status                        # 索引规模、节点构成、语言分布
codegraph files --max-depth 3           # 目录树
codegraph impact <符号名>               # 改动波及面
codegraph explore "<流程问题>"           # 流程 + 逐行源码 + 有无测试
```

> ⚠️ **改完代码请重跑 `codegraph sync`**（通常自动同步），并在**动过结构**时回来更新本文第 2 / 3 节。
> 如果发现本文与命令输出不一致 —— **以命令输出为准**，然后**把本文改对**。
