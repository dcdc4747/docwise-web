# docs 目录索引

本目录放**长期有效**的项目文档。现行文档在根下，过程记录统一进 `records/`，
一次性材料放本地 `素材\`（不入库）。

| 文件 / 目录 | 用途 |
|---|---|
| `ARCHITECTURE.md` | **当前代码架构的权威快照**（分层 / 模块依赖 / 数据流 / 接入点 / 注意事项）。**改代码后必须同步更新**。 |
| `PRODUCT.md` | 产品形态说明（左侧导航 + 知识库化；界面长什么样、三个模块各自做什么、明确不做什么）。 |
| `AGENT.md` | Agent 工具清单与挂载规则（两个场景各挂哪些工具、写操作边界）。 |
| `contracts/` | 三份契约：`api.md`（接口面）、`data-model.md`（表与迁移规矩）、`frontend.md`（视图拆分与命名冻结）。**改接口/表/前端命名前先读**。 |
| `guides/` | `onboarding.md`（组员入门：环境、分支、PR 流程）、`note-shortcuts.md`（写作页快捷键）。 |
| `design/` | 可点开的界面原型（`product-form.html`）与设计方向稿。原型是设计权威，但**以现行 `PRODUCT.md` 为准判断哪一版**。 |
| `records/` | 过程记录：阶段验收、量测、选型、历史形态稿。**按日期留档，不代表当前实现**。 |
| `screenshots/` | 文档与 PR 用的界面截图（统一放这里，不要再散落到源码目录）。 |

## 约定

- **架构图是硬约定**：涉及模块 / 接口 / 数据结构 / 路由 / 引擎层 / 前端入口的改动，必须同步更新 `ARCHITECTURE.md`。
- **契约优先**：实现与契约不一致时以契约为准改代码；确属契约写错，先改契约再改代码（同一条 PR 里都行）。
- 提交前自查对外口径：不出现参考项目真名、真实姓名，也不出现指向具体活动的字眼（一律用中性词描述）。
- 大型样本、录屏、对比表格不走 git；仓库只放文档与轻量截图。
