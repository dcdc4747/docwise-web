## 0. 迁移脚本的硬规矩（**每张新表、每个新列都要照这个来**）

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | 放 `backend/scripts/`，命名 `migrate_<主题>.py` | 现有 `fix_timestamps_utc.py` / `curate_demo_library.py` 就是这个形状 |
| 2 | **默认只打印将要做什么（dry-run），不写一行** | 生产库里是真人数据 |
| 3 | **`--apply` 才真写** | 一条命令两个语义，杜绝"手滑就改了" |
| 4 | **幂等**：跑第二遍必须什么都不做 | 重跑是常态（换机器、回滚后重来） |
| 5 | **带 `_migration_marker`**（在库里记一条"已迁移"），防重复执行 | `fix_timestamps_utc.py` 已有这个做法，照它 |

| 8 | 新表建完后**必须跑一次 `pytest`**，并**手工验证一次"空库从零建"**（`create_all` 能不能直接建出来） | 两套建表路径（老库迁移 vs 新库 `create_all`）都要通 |

### 1.1 `tasks.reading_status`（M1 的改列）

```python
reading_status: Mapped[str] = mapped_column(
    String(16), default="unread", nullable=False, server_default="unread", index=True
)
```
- 取值 **`todo`（待读）/ `reading`（在读）/ `done`（已读）**。
  ⚠️ **默认值定 `todo` 还是 `unread` 是一个决定**——**采用 `todo`**：一篇刚上传的文献，用户的默认意图就是"待读"，而且它直接喂"待读 N"这个入口。（`nullable=False` + `server_default="todo"`，老数据迁移时**全部置 `todo`**。）
- ⭐ **为什么它是 `tasks` 的列，不是关联表**：**状态是文献自己的属性（跟文献走）；集合是人的组织（跟人走）**——Zotero 原话："**标签可以迁移，但收藏集不能**"（形态 §2.1 第 3 条）。
- ⚠️ **`reading_status` 与"块级曝光埋点"不是一回事**：前者是用户手动/半自动的状态，后者是埋点 1 的**块曝光**（进视口就记、幂等）——**别混成一个字段**。

### 1.2 `tasks.structure`（**M6 / C1 新增，2026-10-15 补进本契约**）

```python
structure: Mapped[dict | None] = mapped_column(JSON, nullable=True)
```

- **只存原始量、不存判定结果**——与 `regions`、`task_blocks.layout` 同一口径：**引擎侧解析器给什么就存什么**，后端不做判级、不做推断、不补默认值。结构缺失（老任务、引擎那条路还没接上）就是 `NULL`。
- **形状**（引擎 `result.json` 的 `structure` 字段 → 原样落库；**只许追加**）：

```json
{
  "headings": [
    {"block_id": "p1_b5", "level": 2, "text": "2.1. 技术接受模型"}
  ],
  "references": {
    "count": 47,
    "entries": [{"index": 1, "text": "F. Hund, Z. Phys. 43, 805 (1927)."}]
  }
}
```

  - `headings[].level`：**引擎侧解析器给的**层级（实测由编号深度稳定给出，`2.1` → 2）。**后端不重算**——判级仍归 `blocktypes.py`，这里只多一列"层级"。
  - `headings[].block_id`：能对上 `task_blocks.block_id` 就给（C3 目录跳转要用它定位），对不上就是 `null`。
  - `references.count` / `entries`：解析器的原始产出，后端不合并、不去重。
- ⚠️ **表格 / 公式本轮不在形状里**：选型实测（[`结构解析选型记录_20261015.md`](结构解析选型记录_20261015.md)）显示规则法在这批样本上不可用（真表 0/2 命中、中文篇 4 处误报）、模型法本机又跑不起来（torch DLL）。**等补测出数字再按"只许追加"加键**——**现在不许写空壳字段冒充已支持**。
- ⚠️ **不许改 `layout` / `regions` 的既有字段**（C1 判据③）。
- 老库补列走 `app/main.py::_ensure_schema`（与 `regions` / `archived_at` 同一通道，幂等）；新库由 `create_all` 直接建出——**两条路径字段一致**。

## 2. 本期新增 10 张表（`drafts` + `citations` 算一组，分两节写）

> **全部落在现有 SQLite**，不引任何新基建（**后端运行时依赖仍只有 6 个包**）。
> **公共列**（下面不再重复）：`id INTEGER PRIMARY KEY`、`created_at DATETIME`（**写库统一走 `app/timeutil.py::utc_now()`**）。
> ⚠️ **时间戳口径是踩过坑的**：`created_at` 曾经是 SQLite `func.now()`（UTC），而 `started_at` 是 Python `datetime.now()`（本地）→ 列表页"上传时间"整体差一个时区。**新表一律用 `utc_now()`**。

### 2.1 `collections`（集合，可嵌套）

| 列 | 类型 | 约束 |
|---|---|---|
| `id` | int | PK |
| `user_id` | int | FK `users.id`，**index**，非空 |
| `name` | str(64) | 非空 |
| `parent_id` | int \| null | FK `collections.id`，**index**，可空（null = 顶层） |
| `sort` | int | 默认 0 |
| `created_at` | datetime | `utc_now()` |

- **唯一约束**：`(user_id, parent_id, name)` —— **同一父下不许重名**（不同父下可以同名）。
- ⭐ **语义定死（照抄 Zotero，不许发明第三种）**：**子集合的文献不算在父集合里**——集合**只含直接成员**。计数＝**直接成员数**。
- ⭐ **展示层**给"含子集合共 N"的**括号辅数**（`doc_count_deep`），**不改语义**。
- ⚠️ **成环必须挡**：把集合移进自己的后代 → **400**。这个判断在服务端做（`parent_id` 链上走一遍），**不许只靠前端**。

### 2.2 `tags`（标签，三类）

| 列 | 类型 | 约束 |
|---|---|---|
| `id` | int | PK |
| `user_id` | int | FK `users.id`，**index**，非空 |
| `name` | str(64) | 非空 |
| `kind` | str(16) | **`topic` / `method` / `status`**，非空 |
| `created_at` | datetime | `utc_now()` |

- **唯一约束**：`(user_id, kind, name)`。
- ⭐ **`kind` 分三类**（形态 §2.3）：主题 / 方法 / **状态**。**状态类最有价值**——它驱动"我今天该干什么"。
- ⚠️ **`tags` 与 `tasks.reading_status` 的关系要写清**：`reading_status` 是**驱动"待读/在读/已读"三个入口的那一份数据**（有索引、可高效筛）；`kind='status'` 的标签是**用户自己打的额外状态标签**。**两者不互为镜像、不做同步**——否则会出现"改了 A 没改 B"的老问题。

### 2.5 `smart_collections`（智能集合＝已保存的搜索规则）

| 列 | 类型 | 约束 |
|---|---|---|
| `id` | int | PK |
| `user_id` | int | FK `users.id`，**index** |
| `name` | str(64) | 非空 |
| `query` | JSON | **规则即数据**，形状见下 |
| `builtin` | bool | 默认 false；**内置三条为 true，不可删** |
| `sort` | int | 默认 0 |
| `created_at` | datetime | `utc_now()` |

**`query` 形状（冻结）**：
```json
{"all": [{"field": "reading_status", "op": "eq", "value": "todo"}]}
```
- `field ∈ {reading_status, tag, collection, native, text_source}`
- `op ∈ {eq, in, not_in}`
- **内置三条**（迁移时种下，`builtin: true`）：待读 = `reading_status eq todo` / 在读 = `reading_status eq reading` / 已读 = `reading_status eq done`。

⭐ **辩护维度（写进代码注释，别只写"少写几个 if"）**：**实体化与否不取决于文献有多少篇，取决于规则有多少条、规则是不是数据**。当筛选逻辑是**代码**时，加一条规则＝改代码＋测试；当规则是**数据**时，加一条规则＝插一行表。**硬编码分支超过 2 处，"规则即数据"就回本**——我们有待读/在读/已读三条，**已经过线**。
⚠️ **本期不做用户自定义查询构建器**。三档演进：**① 预置规则 → ②「把当前筛选存为智能集合」→ ③ 构建器**（有第 ② 档，第 ③ 档可以一直不做）。**边界**：预置规则扩张也走"插一行表"，**上限约 8–10 条**；超过说明该上第 ② 档。

### 2.10 `block_exposures`（埋点 1 的分母 · **块曝光**）

| 列 | 类型 | 约束 |
|---|---|---|
| `id` | int | PK |
| `user_id` | int | FK `users.id`，**index** |
| `task_id` | int | FK `tasks.id`，**index** |
| `block_id` | str(64) | 非空 |
| `session_id` | str(64) | 前端一次打开阅读页生成一个 |
| `entered_at` / `left_at` | datetime | **两个时间戳**（R5：把"曝光定义之争"变成一次数据对照） |
| `created_at` | datetime | `utc_now()` |

- **唯一约束**：`(user_id, task_id, block_id, session_id)` —— **幂等**：同一 session 同一块只记一次。
- ⚠️⚠️ **分母口径是踩过坑的**：**修改率 ＝ 被改块数 / 被曝光块数**，**不是 / 总块数**。
  一篇 212 块的文献用户只精读了 80 块，**分母用 212 会把真实 18% 稀释成 7%，直接改变"建/砍记忆"的结论**。
- ⚠️ **生效前提（第三道闸门）**：**观测期 ≥14 天 且 曝光块数 ≥500** 才允许判"建/砍"，此前一律"继续观测"。
- ⚠️ **必须写明的前提（防循环论证）**：**"修改率是在提供了编辑入口的条件下测的"**——入口本身会抬高修改率（观察者效应）。**引用这个数字必须带这句前提。**

```
       ├─ materials ──┐
       ├─ drafts ─────┴─ citations
       ├─ memory_events              ← 台账唯一真源（M2 写 / M5 读 / M7 吃）
       ├─ auth_sessions
       └─ auth_tickets
```

**总数**：已有 **7** 张 + 本期新增 **10** 张。
**名单（10 个，数一遍核对）**：`collections` / `tags` / `task_collections` / `task_tags` / `smart_collections` / `materials` / `drafts` / `citations` / `memory_events` / `block_edits` / `block_exposures`。
⚠️ **上面这份名单里其实是 11 个名字——因为 `drafts` 与 `citations` 是两张表、但按"起草这一组"一起排期。**
→ **这就是"不要写需要人算的总数"的原因**：本文件**以名单为准**，不以任何"N 张"为准（**人算就会错**，这是形态文档台账算错三次换来的规矩）。

⚠️ **`materials` 与 M7 记忆的关系**：`memory_events` 是**环节台账**（L0），素材卡是**资产**——**两者不是一回事**，别把素材卡当记忆存。

## 4. M2 / M5 / M7 三方对同一批字段的依赖（**先看这张再改字段**）

| 字段 | M2（素材/台账数据层）在哪用 | M5（说得清/我的数据）在哪用 | M7（记忆）在哪用 |
|---|---|---|---|
| `memory_events.stage` | **写入**（各环节） | 台账表的**行标题** | L1 事实的**来源环节** |
| `memory_events.actor` | **写入**（local/api） | **数据流向芯片**（`● 不出本机` / `▲ 正文发往模型 API`） | 判断"这条记忆要不要发出去" |
| `memory_events.payload` | 写入模型名/参数 | 台账的**可下钻明细** | 提示词注入的**素材** |
| `materials.translated_quote` | 存快照 | 导出 | **术语一致率**的分母之一 |
| `block_edits.after` | 写入 | **逐条 diff** | ⭐ **句级纠错记忆的唯一来源** |
| `block_exposures.*` | 写入 | — | ⭐ **修改率的分母 + 生效闸门** |

⚠️ **改 `memory_events` 的任何一个字段 = 三方同时返工**。这就是"必须先冻结数据模型"的具体含义。

## 5. 明确不做（**写清是为了不被当漏项**）

| 不做 | 理由 |
|---|---|
| ❌ 知识图谱 / 图数据库（Nebula / Neo4j） | 重基建，且这一族在整合；形态 §2.3"三条不做"之一 |
| ❌ 工作区隔离（各自独立的 notebook） | **我们的"读懂"是跨文献的**——否则"该引哪一篇第几页"做不成 |
| ❌ 协作 / 共享（群组、多人同库） | **口径是「单部署、多账号、无协作」**：账号只用于**数据隔离与管理** |
| ❌ 全文检索换向量库 | 现在 FTS5（trigram）够用；换向量是另一个量级的依赖 |
| ❌ 给 `task_blocks` 加"块类型"列 | **块类型是当场算的**（`blocktypes.py` 是唯一权威）——落库会让"规则改了老任务不跟着变" |
| ❌ `drafts` 的版本历史表 | 本期只存当前稿；需要历史时再加（**别预建**） |
