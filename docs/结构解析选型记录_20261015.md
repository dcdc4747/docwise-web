## 二、4 类数字的基线怎么数的（判据写死，可复核）

| 数字 | 判据 | 为什么这么定 |
|---|---|---|
| **编号标题** | 行首 `I.` / `A.` / `1.` / `2.1.` / `一、`，行长 ≤90 字符，行尾不是句末标点 | 只数"文献自己带编号的章节行"——这是可逐条人工核对的量，不含"我觉得像标题" |
| **表注** | 行首 `^(TABLE\|Table\|表)\s*([IVXLC]+\|\d+)` | 表注是文献自己声明的表数，比"检测器说有几个表"可靠 |
| **编号公式** | **独占一行**的编号：`(n)` **或分节式 `(n.m)`** | 数学 arXiv 实测整篇用 `(n.m)`；只认 `(n)` 会把它数成 0（见第三节修正 2） |
| **参考文献条目** | 有区标题 → 从标题后数行首 `[n]` / `n.`；**文字层没有区标题时** → 退回"行首 `[n]`"锚定 | 化学 arXiv 实测没有 `References` 标题行，但条目真实存在（见第三节修正 1） |

生成命令（本地探针，与"引擎包装脚本"同性质，**不进公开仓库**）：

### 基线的三处修正（记录在案，免得下次再踩）

1. **参考文献区**：先按"标题行"定位 → 化学篇数出 **0 条**。打印末页后确认：`References` 标题**不在文字层里**，而 p16 起 `[1] F. Hund…`、`[2] M. Quack…` 真实存在。改成"行首 `[n]` 锚定"后 **47 条**。
   ⚠️ 与块分级那条教训同源：**查召回必须锚定位置，别做全文子串搜**——宽松搜"含'参考文献'的短行"会把正文里的 `下面根据参考文献[15]第15 页的方法分析` 当成区标题。
2. **公式编号**：先只认 `(n)` → 数学篇数出 **0 条**。逐样式清点：该篇 36 条**全是 `(n.m)`**，`(n)` 式 0 条。基线改成两种样式都认。
3. **表格**：先只按表注数 → 中文篇 0 条表注，但 PyMuPDF 报 4 个"表"。逐条打印 bbox 与首行后确认**4 个全是误报**（明细见 4.1）。

## 四、各候选实测

### 4.1 轻量规则法（引擎侧独立 venv 实测）

实测环境：`pymupdf==1.24.14`、`pdfplumber==0.11.10`、`refextract`（+ `python-magic-bin`）。
⚠️ **PyMuPDF 1.28.2 在本机装得上、导不进**：`_mupdf` DLL 初始化失败，**放宽权限后同样失败**（不是沙箱），换 1.24.14 正常。这条对落地有影响——引擎侧钉版本。

| 候选 | 标题命中 / 层级一致 | 表格 | 公式 | 参考文献条目 |
|---|---|---|---|---|
| **PyMuPDF 规则探针** | 化学 **11/11 · 11/11**；数学 **99/99 · 99/99**；中文 **18/18 · 18/18**（但共报 384 条） | 化学 **0/2**；数学 —（0 表）；中文 **0 真 + 4 误报** | 无原生能力（只能数数学字体 span：3102 / 9545 / 0） | 无原生能力 |
| **pdfplumber** | 无原生能力 | **0/2**；— ；**0** | 无原生能力 | 无原生能力 |
| **refextract** | 无原生能力 | 无原生能力 | 无原生能力 | 化学 **47/47**；数学 **54/53**；中文 **28/29** |

**逐条读法：**

- **标题**：命中与层级**都对**——层级是**编号深度**直接给的（`2.1` → 二级），不是猜的。但要看清这是**行级探针**，不是产品判据：项目里**块级判级的唯一权威仍是 `blocktypes.py`**，M6 要补的是"层级"这一列。中文篇行级规则共报 **384 条**（基线 18），多出来的全是数字开头的公式碎片——**这条与 `blocktypes.py` 的既有教训一致：判级要靠"块 + 版面信号"，不能靠单行文本形状。**
- **表格**：**轻量规则法在这 3 篇上不可用**，两个方向都错：
  - 漏：化学篇 2 个真表（`TABLE I.` / `TABLE II. Geometrical and dynamical quantities…`），`find_tables()` 与 pdfplumber **都是 0 命中**；
  - 误：中文篇 PyMuPDF 报 4 个"表"，逐条打印 bbox 后**全是误报**——p1 `Open Access` 徽标（1 行 3 列）、p6 `B 2`、p10 `−1− 3i`、p10 `−1+ 3i`（都是公式碎片）。**真表 0 个。**
- **公式**：三个轻量候选**都没有公式能力**。PyMuPDF 那三个数（3102 / 9545 / 0）是"带数学字体的 span 数"，中文篇用 CJK 字体所以是 0——**它不等于公式数，别当公式数用**。
- **参考文献**：refextract 与基线几乎逐条对上（±1 条）、纯 Python 规则法。**这是本轮唯一"拿来即用"的一项。**

## 六、结论：跑在哪一侧 + 为什么

> **结论：解析器一律跑在「引擎侧独立 venv 子进程」，后端只读 `result.json` 里的结果。一个都不进后端进程 / 后端 venv。**

理由按权重排：

1. **6 依赖红线是硬约束**（issue #92 明写"不可协商"）——任何解析器都进不了后端 venv，那"跑在后端进程"这一侧在本项目里**根本不存在**；
2. **License**：PyMuPDF 是 **AGPL-3.0**。它是唯一"已经在引擎侧"的候选，但也正因此**只能待在引擎侧**——独立进程 + 独立 venv，与后端依赖树无关；
3. **体量**：模型法要带 torch + 数百 MB 模型（Docling / MinerU / Marker 一族），后端进程背不动，也不该背；
4. **已有先例，不改架构**：`extract_blocks.py`（中文取字）、`ocr_blocks.py`（扫描件 OCR）、`translate_blocks.py`（逐段翻译）**全都是"引擎侧脚本 + 子进程调"**，本轮只是再加一条；
5. **失败隔离 + "缺失就退回"**：子进程崩了或结构缺失，表现为 `result.json` **少字段**，后端照既有行为退回、不抛异常（这正是 C1 判据②的落法）。

## 七、M6 落地建议：分两步，别一次吃下四类

1. **先落本轮有数字、引擎侧已有依赖的两类**：
   - **参考文献区**：refextract（Apache-2.0，实测 47/47、54/53、28/29）；
   - **标题层级**：编号深度直接给层级（实测层级一致 11/11、99/99、18/18）；**判级仍归 `blocktypes.py`，M6 只追加"层级"这一列**。
2. **表格 / 公式等能跑 torch 的机器上补测模型法**再定：Docling 优先（MIT + 68.9k★），Marker 备选（Apache-2.0）。**在补测之前，不要给表格/公式写任何"声称能用"的界面文案**（§七那条不实宣称的教训）。
3. 结构结果一律**只存原始量、不存判定结果**（照 `tasks.regions` 的既有做法）——判定规则将来改了，老任务不用重跑。
