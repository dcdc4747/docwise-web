# 产品形态说明 v1.3

> 本文回答一个问题：**docwise 长什么样、每个功能摆在哪儿。** 不拆任务卡、不写实现细节。
> 状态：2026-09-14 v1.3（电脑端与手机端形态均已定向，评审已收口）。v1.1 / v1.2 / v1.3 的变化见第九节。
> 相关：`docs/代码架构图.md`（代码层权威快照）、`frontend/prototype/product-form.html`（**可点开的形态原型**，与本文件配套）、`frontend/prototype/design-direction.html`（视觉原型 A 方案）。

---

## 一、一句话形态

**docwise 不是"一个上传翻译的页面"，而是"一个读论文的地方"。**

两级结构：**L1 库页**（我的论文 —— 上传、进度、翻找）与 **L2 阅读工作区**（全屏读一篇 —— 左文档、右助手）。
现在这两件事挤在同一条纵向瀑布里（库在页面中段、阅读被压在卡片页签里），所以要拆开。

## 二、已拍板决策

| # | 问题 | 决策 | 说明 |
|---|---|---|---|
| 1 | 主视图（电脑端） | **上 pdf.js，PDF 页内真划词** | 左栏由 pdf.js 渲染，可缩放 / 翻页 / 搜索 |

| 2 | 导读 / 术语落位 | **右栏副页签**（问答 ｜ 导读 ｜ 术语） | 读的上下文不被切走；点出处立刻看到左栏高亮 |
| 3 | 库页 hero | **空库出大 hero；有历史后收成一行** | 新用户第一眼有说服力；老用户直接看到自己的论文 |
| 4 | 手机端主视图 | **按块流式重排的段落视图**（v1.1 修订） | 实测已证中文稿与原版同为整页版面（635×824pt），手机上必然要放大拖；段落视图才真能读。顶部保留「原版」入口看图/公式 |
| 5 | 手机端助手 | **底部抽屉三档：peek（≈118px）/ 半屏 / 近全屏** | 点出处自动降到 peek 档，露出「已定位到第 X 页 · 第 Y 段」 |

| 7 | 阅读位置记忆 | **做**（v1.1 新增） | 卡片显示「上次读到第 5 页」，打开跳回；没记录的显示「开始阅读」而不是「继续读」 |
| 8 | 示例论文入口 | **做**（v1.1 新增） | 按标准挑选的公开论文，逐个登记来源与许可，**按学科 / 版式 / 篇幅分类**；同一套样本兼作后续回归测试集。仓库不放大文件（走演示环境或网盘） |

## 四、布局规则（照着做就不会走样）

**断点与分栏**

| 宽度 | 布局 |
|---|---|
| ≥ 1280px | 双栏：左 = 剩余宽度，右 = 380–480px（可拖拽，记住用户设置） |
| 1024–1280px | 双栏：右栏收到 340px |
| < 1024px | 单栏：**段落视图全宽** + 助手底部抽屉（peek / 半屏 / 近全屏） |

**左右两栏各自独立滚动**，互不带动；工具条与副页签吸顶，问答输入框吸底。

**出处规则（本产品的命门，五条硬性）**

> **2026-09-17 口径修订（用户拍板）**：出处**只说「第 X 页」，不再说「第 Y 段」**，并把
> **那一段的开头十几个字缀在标签上**（一页里常有多个出处，只写页码分不清哪个是哪个）。
> 理由：段号靠 PDF 版面切分算，实测在**没见过的期刊**上只有五六成准（评测台与四路独立审查见
> `temp/seg-audit/审查结论_汇总.md`）；**不准的段号比没有段号更糟**——用户会拿它去数，
> 数不上就整条出处都不信了。真正让人信的是"点下去那几句被高亮"，那个按**文字匹配**算，不依赖分段。
> 段号什么时候做到可信，什么时候再接回来（`blockLabel()` 留着没删，评测台也在）。

1. **出处说页码 + 那一句的开头**：一律显示「第 X 页 ·「这一句的开头…」」，块编号只出现在 `title`/详情里（可排查）。
   - **块必须真的在本任务的块列表里**才能给页码——模型偶尔会编出不存在的块编号，
     只按编号前缀给个页码等于**把编出来的位置当真显示**；推导不出就写「位置待定 / 出处未能定位」，
     **不许裸露编号，也不许假装**。
   - 点出处要能**高亮那几句原文**：这是出处的信任来源。
   - （旧口径存档）`block_id` 形如 `p<页序>_b<全文档块序>`，**`b` 是全局序号**，
     段号若要用必须按页内重算（实测：任务 2 共 92 块/3 页，最后一块是 `p2_b91`，直接当段号会显示"第 92 段"）。
2. **降级态一眼可辨**：没有出处的要点（如"由全文综合"的结论）→ 置灰、不可点、**不给箭头**，并附一句说明为什么没有。**死链绝不许做成活链样式**（否则等于伪出处）。
3. **坐标只在有出处时才显示**：导读/答案的坐标来自 LLM 返回的 `source_block_ids`（真数据，可以点前就显示）；**术语表没有出处字段**，则按钮先只写「在原文中定位」，**命中后回填**「已定位 · 第 X 页 ·「…」」，未命中直说「没找到，可能在图/表里」——不许预填坐标。
4. **点击必闪烁**：跳转后目标段滚入视口中部 + 高亮脉冲一次，否则用户找不到落点。
5. **定位失败要明说**：文本对齐是启发式（选区跨栏、重复句都可能失配）→ 宁可说"这段没能定位到原文块"。

**文案口径（别让数字自己拆台）**

- **秒数一律标来源**：写「引擎自报还需约 25 秒」，不写「预计还需 25 秒」；**耗时只有在真的知道时才给**（档位说明里不写"几十秒出稿"这种承诺）。诚实这个卖点，死于精确，不死于模糊。
- **档位只有一个写法**：`快档 · 最快` / `中档 · 平衡` / `精档 · 最准`，选择处、工具条、卡片一律用这一套。
- **失败给下一步**：失败的唯一下一步是「重新翻译」，给它主按钮权重；「继续读」只在**真的有阅读位置**时出现，否则写「开始阅读」。

**其他规则**

- 工具条「下载」必须写明对象（默认「下载双语稿」，原文 PDF 只用于左栏预览）；`⋯` 菜单装：文档信息 / 下载译稿（纯中文 · 双语）/ 以精档重新翻译（新建任务）/ 重新翻译 / 处理详情 / 问题反馈 / 删除。
- 翻译完成后任务条**不静默消失**：变绿显示「翻译完成 · 开始阅读」，几秒后可手动关闭。
- 划词浮标放在选区**上方**（放下方会盖住正要读的下一行）；贴顶时退回下方。
- 手机段落视图：段号写「段 N」，并在**跨页处插页分隔条**「—— 第 2 页 ——」，让「第 X 页 · 第 Y 段」在手机上找得到；点段落即可「就这句提问」（段落本身就是锚点，**不需要划词、不需要文本匹配**）。
- 手机抽屉：peek 档只露「页签 + 当前问题摘要」，chips 从半屏档起才出现；**切档不重置滚动位置**。
- 空库首屏只有一个示例入口（hero 三枚描边按钮），不再另放一行文字链接。
- 三态齐全：每个区块都要有 加载 / 空 / 失败 三态，失败必须给「重试」；**问答失败也要有人话文案**（"没答出来，通常是网络或服务繁忙" + 重试），保留问题原文。
- **不许编进度**：引擎没报就写「引擎还没报进度」；进度条永远在（不确定时画流动条纹）；「已用时间」才是主指标。
- **健康状态正常时不显示**：只在异常时出现。
- **右栏反膨胀**：以后每加一个功能，先问"能不能放进问答里"，页签数不再增加。
- 留白与层级：不做"整页卡片套卡片"；一屏最多一个强调色；层级靠留白与字重，不靠阴影。

## 七、已核实的事实（形态的地基，别再猜）

| 事实 | 证据 |
|---|---|
| 块编号 100% 可推导页号 | 全库 1510 / 1510 块匹配 `p<页>_b<块>`；`b` 是**全文档全局序号** |
| 中文稿与原版**同版面** | 原版 5 页 635×824pt → mono 也是 5 页 635×824pt（另一任务 10 页 → 10 页）。**中文稿不是流式文本** |
| 双语稿是**原页 / 译页交替** | dual = 原版页数 ×2（5→10、10→20）；一屏只有一种语言 |
| 译稿文字层有"伪装字" | 中文稿含 **169 个 CJK 兼容汉字**（U+F900–FAFF）：长得一样、码位不同；NFKC 归一化后 `search_for` 从 1 命中掉到 0 → **跨"选区 ↔ 原文块"的比较必须先 NFKC** |
| 档位目前只有快档有真实产物 | 全库 22 条 fast / 1 条 medium；精档在 registry 里映射 medium → 演示时点"精档"是未验证路径 |
| **块级译文已产出（2026-09-30 起）** | 引擎包装脚本把 pdf2zh 的「原文段落 → 译文」成对录进 `result.json`；实测一份 5 页英文论文 **42/42 块都有译文**，页序正确。**但要重新上传才有**：2026-09-30 之前跑的任务 `translated` 仍是空的（段落精读对它们回退显示原文 + 诚实提示） |

## 八、开工前必须先验证的三条风险

1. ~~**pdf.js 能否渲染我们引擎产出的 PDF**~~ → **✅ 已实测通过（2026-09-15）**。
   背景：PyMuPDF 全程报 `syntax error: unknown keyword: '8.526509999999999e'`（内容流有畸形数字）但能容错渲染，
   **pdf.js 是另一套解析器**，画不出来整个 L2 左栏方案作废。**实测**：拿 **4 份真实引擎产物**
   （EBSCO_04 mono 5 页 / dual 10 页、EBSCO_05 mono 10 页、AnimalFarm_03 dual 6 页）跑 pdf.js 4.10——
   **渲染指令流 31/31 页全成功、文本层 31/31 页全成功**（共 2461 个文本项，条目自带 `transform` 与 `width/height`，
   足够算高亮矩形），**pdf.js 自己一条 warning / error 都没报**。→ 段落级高亮与「点 PDF 段落提问」技术上成立。
   证据与探针脚本：`形态重写_交付包\L2验收\pdfjs可行性\`（复跑 `node probe.mjs <pdf…>`）。
   真要上，还有两条**必须先解决**，别踩：
   - **块文本 ↔ PDF 文字层对齐**：外文文献的**双语稿原页**与**中文文献的原稿**能直接搜到；
     **纯中文稿**块里存的是英文原文（用来搜的是块文本 `text`，不是译文 `translated`）、PDF 里是中文译文，直接搜必然搜不到——
     **但也不用改引擎**：双语稿是版式保持的"原页 + 译页"交替产物（原页 2N-1 / 译页 2N），
     拿原页命中的 y 区间去**译页**取重叠的中文段，再映射到纯中文稿的同一页同一区间即可
     （已实测：两处取到的中文行完全一致）。真对不上（图/表/扫描页没有文字层）时必须只跳页 + 明说，
     **不许假高亮**。
   - **拉取方式别用 `?ticket=`**：票据 60 秒有效，而 pdf.js 会按需分片拉取，读一篇几分钟 → 中途过期 = 读一半白屏。
     改走 `authFetch` 取 `ArrayBuffer` 一次性喂 `getDocument({data})`（单篇 0.2–1.6 MB，完全吃得下），
     顺带绕开「`/files` 要不要支持 Range(206)」这个问题。
2. **划词 → 原文块的对齐命中率**：文本对齐是启发式（双栏串栏、重复句、兼容字）；开工前做小样本实测（10 页 / 人工标注 30 段）。设计上的兜底：选区自带页码 → **先按当页过滤候选块**；仍歧义 → 取覆盖最深的块并标"可能对应多处"；对不上 → **诚实说定位失败**。
3. **票据 60 秒 vs 阅读时长**：pdf.js 按需分片拉取，用户读一篇要几分钟到几十分钟，**票据会中途过期**（表现为"读一半白屏"）。必须一并定：文件接口的票据策略、`/files` 是否支持 Range（206）。

## 十、大方向（供转述组员，不是任务卡）

1. **把"库"和"读"拆开** —— L1 库页 / L2 阅读工作区两级结构落地（形态骨架）。
2. **给"读"造一个真正的阅读器** —— pdf.js 接进左栏：缩放 / 翻页 / 搜索 / 连续滚动 / 语言三选（默认原版英文）。
3. **把"问"锚到文段** —— 划词 → 对齐桥 → 带锚点提问 → 出处高亮回跳；NFKC 归一化与"按页过滤候选块"是前提，失败要诚实降级。
4. **让长处看得见** —— 出处锚点（提问锚点与出处是同一个坐标系）、诚实进度、档位 = 成本 × 质量 × 时间、导读五字段卡。
5. **手机端** —— 段落视图 + 顶部诚实进度 + 底部抽屉三档 + PWA 真机实测。
6. **把阅读器的"看不见的活"撑住** —— 对齐失败、渲染失败、票据过期、引擎没报进度，四种情况都要有诚实出口，不假装。
7. **数据补齐（硬前提）** —— ① 原文块**页号**从 `block_id` 显式落库；② **术语表加出处字段**（术语表内定位现在是按文本找）；③ 提问接口加**可选锚点字段**；④ `last_read`（阅读位置）。
8. **样本论文库** —— 按标准挑选 + 分类（学科 / 版式 / 篇幅），登记来源与许可；兼作回归测试集。
