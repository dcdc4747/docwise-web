## 二、AI 层（本作品的核心）

### 2.1 三个概念

| 概念 | 文件 | 职责 |
|---|---|---|
| **场景 Scene** | `agent/scenes/*.py` | 一个"专业身份"：system_prompt + 工具白名单 + 输出结构 + 上下文 + 收尾校验 |
| **工具包 Pack** | `agent/packs/*.py` | 一组可执行工具（一个能力一个文件，registry 自动发现） |
| **运行时 runtime** | `agent/runtime.py` | 把 ABI 翻译成框架调用、跑多轮工具循环、校验出处、流式发事件 |

**场景定义（真实代码）**：

```python
Scene(
    id="write_compose", title="写作 · 和助手一起写这篇",
    system_prompt=SYSTEM, output_type=WriteAnswer,
    packs=("writing","library","terms","cite","check","biblio","materials","memory_write"),
    build_context=..., verify=verify_all, default_tier="standard",
)
```

### 2.2 工具 ABI（插件化的关键）

```python
def tool(ctx: ToolContext, args: dict | None = None) -> ToolResult
```

- `ctx`：用户、场景、页面上下文（如 `draft_id`）；
- `args`：模型给的参数（**dict**，不是拆开的 kwargs——这条踩过坑并写了用例）；
- 新增一个能力 = **加一个 `packs/xxx.py` 文件**，不用改 runtime。

**当前工具规模**：读懂 **15 个**（库检索/段落/术语/任务/进度/记忆/大纲/对比/图表/综述矩阵），
写作 **14 个**（草稿读写/素材/引文/校对/CSL/术语/库检索/记忆写入）。

### 2.3 两条产出通道

| 通道 | 语义 | 落地方式 |
|---|---|---|
| `revisions` | 逐句改写建议（original → revised） | 用户点「采用」才落地，可逐条/批量 |
| `ops` | **直接写正文**（append/prepend/replace/insert_after） | 自动落地 + 20 秒整批撤销 |

两条都过**服务端校验**：`original` / `anchor` 必须**逐字**出现在稿子里（换行归一后比对），
对不上一律剔除并在 `notes` 里如实说明"剔掉 N 条"。

### 2.4 流式事件

```
start → (tool_call → tool_result)* → (thinking | delta)* → final
```

- `tool_call/tool_result`：模型每次调工具都发，界面按到达顺序逐条入场；
- `delta`：**从结构化输出的 JSON 参数流里逐字剥出 `answer` 字段**（`_partial_json_string`），
  所以正文是"写出来"的，不是最后一次性出现；
- 收尾校验：出处只留工具真返回过的块编号（正则从工具结果里取），编的进 `dropped_sources`。

## 三、数据模型（关键表）

| 表 | 用途 | 关键字段 |
|---|---|---|
| `tasks` | 一篇文献 | status / tier / source_lang / regions / reading_status / text_source |
| `task_blocks` | 块（段落/标题/图注） | text / translated / layout / type(当场算) |
| `task_understanding` | 导读与术语 | guide_json / terms_json |
| `drafts` | 草稿 | **body_md（派生）+ body_html（富文本源）** / template_id |
| `draft_versions` | 版本快照 | body_md / body_html / source(user/ai/restore) |
| `citations` | 引文 | order / csl_json（M4 格式检查的唯一输入） |
| `materials` | 素材卡 | text_quote / page / block_id（句级溯源） |
| `memories` | 偏好 | 术语/译名、引用习惯 |

**为什么草稿存两份**：编辑器（TipTap）里的逐段字体/字号只能存在 HTML 里；
而引文 `[n]`、提纲、导出、AI 的锚点校验都按 Markdown 做。
两份的同步规则：`body_html` 是源，`body_md` 由它转换（只在一处转换：`writeRich.js`）。

## 四、关键工程决策（带原因）

| 决策 | 原因 |
|---|---|
| **引擎走子进程** | 引擎依赖重；后端 6 个依赖能保证"装得上、打得开" |
| **同源部署** | 一个地址给页面与接口；手机演示不用配 CORS / apiBase |
| **契约闸 `backend/.contract/api.json`** | 端点增删必须同步登记，CI 卡住"偷偷加接口" |
| **前端口径由用例钉住** | 数量/文案/结构都有断言；避免"改了没人发现" |
| **插入引文时生成 CSL-JSON 并落库** | 参考文献排版与格式检查共用同一份数据，不重复解析 |
| **AI 写入走 ops 而非直接改库** | 可整批撤销、可留版本；模型一轮里改多次也不会乱序 |
| **测试替身隔离 TipTap** | ProseMirror 依赖真实 DOM 量测，happy-dom 跑不了；页面行为用替身验 |

## 六、可扩展点

- **新能力**：加 `packs/xxx.py`（一个文件）+ 在场景 `packs` 里挂上；
- **新场景**：加 `scenes/xxx.py`（一个文件），前端自动出现在能力页；
- **新体例**：`frontend/src/writeTemplates.js` 加一条数据；
- **新板块专属知识**：规划中的 `skills/` 层（按需加载的 Markdown 知识包），
  与工具分离，避免把 prompt 撑爆。
