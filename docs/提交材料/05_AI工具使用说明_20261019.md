## 三、使用环节（逐处）

### 3.1 外文文献 → 中文（产品功能）

- **输入**：用户上传的 PDF（文字层或本地 OCR 识别出的段落）；
- **AI 做的事**：逐段/分批翻译成中文；
- **AI 不做的事**：不决定版式、不改公式、不写导读；
- **落地**：译文写回块级字段（`task_blocks.translated`），双语 PDF 由引擎重排。

### 3.2 结构化导读 + 术语表（产品功能）

- **输入**：抽样后的文献段落（超长文献均匀抽样，防超上下文）；
- **输出**：JSON——研究问题 / 方法 / 结论 / 创新点 / 局限 + 术语（原文-译文-定义）+ 出处块编号；
- **后处理**：后端**校验块编号是否真实存在**，编造的剔除并计数。

### 3.3 文献问答（产品功能）

- **流程**：检索相关块（本地 FTS5）→ 把块作为上下文 → 模型回答（结构化：答案 + 出处块编号）→ **后端校验出处**；
- **界面**：每条结论点回原文那几句并高亮；无出处的要点置灰不可点。

### 3.4 写作助手（产品功能）

两种产出通道，都由人决定是否落地：

| 通道 | AI 输出 | 人工把关点 |
|---|---|---|
| 改写建议 `revisions` | 逐句 `original → revised + reason` | 逐条「采用 / 忽略」，或批量 |
| 直接写入 `ops` | `append / prepend / replace / insert_after` + **锚点原文** | 自动落地但**20 秒内可整批撤销**；每次保存留版本可回滚 |

**服务端硬校验**：`original`/`anchor` 必须**逐字**出现在当前稿子里，否则这条被剔除，
并在返回里写明"剔掉 N 条"（不让模型的话直接变成事实）。

### 3.5 开发过程（辅助，须披露）

- 用 AI 编程助手参与**代码编写、重构、测试生成、文档整理**；
- 每一次改动都经过：跑 `ruff` + `pytest`（576 条）+ 前端 `vitest`（634 条）+ 浏览器真点验证；
- **架构决策、取舍与判据由团队做**（例如"草稿同时存 Markdown 与 HTML"、
  "AI 写入必须过锚点校验"、"回滚前先留档"——这些是团队定的规则，不是模型提的）。

## 四、生成流程（以"写作助手写入正文"为例）

```
用户："把这节的引言扩写成三句，直接写进正文"
   │
   ▼  前端 POST /api/agent/chat/stream（SSE）
场景 write_compose：system_prompt（写作规则）+ 14 个工具白名单
   │
   ▼  模型决定调哪些工具（可多轮）
如：read_draft（读当前稿）→ search_materials（找可用素材）
   │
   ▼  模型输出结构化结果 WriteAnswer{ answer, revisions[], ops[], source_block_ids[] }
   │
   ▼  后端校验（runtime.verify_all）
   ├─ 锚点 anchor 是否逐字存在 → 不存在则剔除该 op，notes 记"剔掉 N 条"
   └─ 出处块编号是否在本任务块列表里 → 不在则剔除并计数
   │
   ▼  前端 applyOps：写入编辑器 → 提示"AI 已写进正文（N 处）撤销"
   │
   ▼  保存时写 draft_versions（source=user）；回滚前再存一版（source=restore）
```

## 五、提示词 / 工作流（可复核）

> 以下为**真实系统提示词的节选**（完整版在仓库 `backend/app/agent/scenes/write_compose.py`、
> `read_ask.py`；提交版可按需附全文）。

**写作场景（节选）**

```
你是学术写作助手。你的任务是帮用户把这篇稿子写得更清楚，而不是替他把稿子写完。
规则：
1. 只在用户要求的范围内改；不要顺手改无关段落。
2. 要用 ops 直接写入正文时，anchor 必须是正文里逐字存在的原文片段。
3. 引用只能用 read_draft / search_materials 真的返回过的来源；没有来源的断言不要标出处。
4. 不确定的地方如实说不确定，不要编造数据、页码或文献。
```

**读懂场景（节选）**

```
你只能基于工具返回的文献内容回答。
- 每个结论都要带出处块编号（source_block_ids），编号必须来自工具结果。
- 找不到依据就说"这篇里没有提到"，不要用常识补。
```

**用户侧提示词（我们记录并展示的是"用户自己输入的"，不伪造）**：如
「这篇论文的主要结论是什么？用两三句话答」「把这节的引言扩写成三句，直接写进正文」
「这句该引吗」「按 IEEE 格式检查缺哪节」。

## 六、人工筛选与修改（我们的实际动作）

| 环节 | 人工做的事 |
|---|---|
| 翻译 | 抽查段落译文；术语冲突时以术语表/用户修改为准 |
| 导读 | 出处不对的条目**在界面置灰**（不是删掉假装没有）；用户可自己改导读 |
| 问答 | 用户可点出处核对；错误答案可重问 |
| 写作 | 逐条采纳/忽略改写建议；直接写入 20 秒内可撤销；版本可回滚 |
| 代码 | AI 产出的代码全部经人工审阅 + 测试 + 浏览器实测才合并 |

## 七、团队原创贡献（可举证）

1. **选题与产品设计**：三模块（读懂/起草/收口）划分、句级溯源的产品形态、右栏助手的信息架构；
2. **工程实现**：工具注册表与场景白名单（新增能力=加一个文件）、契约闸（85 端点三方对账）、
   时间口径统一（UTC）、同源部署、块分级判据（阈值来自实测）；
3. **质量规则**：AI 写入必须过锚点逐字校验、回滚前留档、编造出处剔除并计数、
   预览/导出一致性、老稿迁移策略；
4. **验证**：1210 条自动化用例（后端 576 + 前端 634）+ 浏览器端到端实测；
5. **文档**：架构、契约、实测记录、模板体例依据（对照公开规范）。

## 八、版权与数据合规

- **模型服务**：调用第三方大模型 API（DeepSeek），按其服务条款使用；API Key 存本地 `.env`，不入仓库；
- **文献数据**：用户上传的文献与稿件存**本地数据库与磁盘**；
  **翻译/导读/问答会把相关段落发送给模型 API**——因此我们不宣称"数据不出本机"；
- **第三方资源**：排版引擎、CSL 样式、OCR 模型均为开源组件，许可证随包保留（MIT/BSD/CC BY-SA 等），
  在《技术架构》与打包文件里列明；
- **生成内容标识**：界面在 AI 生成处显示标识（`AiBadge`），并保证"可撤销 + 可回滚"；
- **不用于**：训练模型、转售数据、绕过文献版权。
