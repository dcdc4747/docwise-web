# 作品说明（草稿 · 2026-10-19）

> 用途：报名系统「作品简介 / 创意来源 / 运行环境」+ 打包文件里的《作品介绍》。
> ⚠️ 提交前要做**匿名化**：删掉校名、人名、学号、二维码、本机路径。

## 一、一句话

**把一篇文献读成可核对的笔记，再把笔记写成可投出去的稿子**——
面向高校学生与研究者的文献理解与写作辅助平台，每条结论都能点回原文那一句。

## 二、我们解决的问题

学生读文献的真实困境不是"看不懂单词"，而是：

1. **读了记不住、引不准**——结论说着说着就脱离原文，写论文时找不到那句话在哪儿；
2. **读懂到写出来之间断了**——读完十篇，综述还是靠手工抄表格；
3. **投稿格式从零开始**——不同期刊体例不同（中文期刊要中图分类号、IEEE 要 Index Terms、
   APA 引言不带标题），学生往往写完再返工排版；
4. **AI 一键生成不可用**——写得漂亮但引文是编的，反而更危险。

## 三、作品做了什么

### 模块一：读懂

- 上传 PDF → 自动译成中文（外文）或直接取文字层（中文），保留原版面；
- **段落精读**：按块重排、原文小字 / 译文主文，点结论回跳到原文那几句并高亮；
- **结构化导读**：研究问题 / 方法 / 结论 / 创新点 / 局限，每项带出处的块编号；
- **术语表**：原文—译文—定义—出现位置；
- **AI 助手**（本作品的 agent）：自己决定查什么——先列章节、再读导读、再取正文段落，
  多轮调用工具后再回答，答案里的出处只保留"工具真的返回过"的块。

### 模块二：写作

- **富文本编辑器**：标题级别、加粗/斜体、对齐、列表、引用、**逐处字体与字号**、行距/段距/缩进；
- **期刊体例模板**（5 种）：中文期刊（GB/T 7714）、英文期刊（APA 7）、IEEE 会议、
  学位论文、研究报告——一键把章节骨架写进正文，正文仍由人写；
- **素材卡 → 引文**：读文献时存下的句子可插入正文，自动编号 `[1]`，点回原文；
- **参考文献排版**：按 CSL 生成 GB/T 7714 / APA / IEEE 样式，缺字段如实标出；
- **AI 写作助手**：可以直接往正文里写（可撤销）、可以只给逐句改写建议、
  能查"这句该引没引"、能按模板要求检查缺哪节；
- **版本历史**：每次保存留一版，AI 改稿前自动留档，可一键回滚；
- **导出**：`.md` / `.docx`（正文 + 参考文献）。

### 模块三：校对

- 一遍检查出三类问题：**该引未引**、**格式自检**（引文编号断档/重复、空引用措辞）、
  **无法判断**（单独一栏，不混进"报出"的计数）；
- 每条都给"原句 + 原因 + 判据"；给候选素材（第 X 页 · 哪一句）；
- **不自动改**：并列摆出问题，由人决定。

## 四、差异化（只讲这一句）

同类工具管到**文献级**（给篇导读、给段翻译），我们管到**句级**：
每条结论、每个术语、每条引文都带**块编号**，点一下回到原文那几句并高亮。
这不是"更准的摘要"，而是**可核对**。

## 五、技术要点（详见《技术架构》）

- 前端 Vue 3 + Vite；后端 FastAPI + SQLAlchemy + SQLite；同源部署（一个地址给页面与接口）；
- 文档处理走**本地引擎子进程**（版面解析、翻译、公式保护、OCR），后端只保留 6 个依赖；
- AI 层用 **pydantic-ai** 的最小实现：**工具注册表 + 场景白名单 + 多轮工具循环 + 出处校验**；
- 生成严格约束在"有出处"的范围内：模型编造的块编号会被后端剔除，并在界面如实显示"剔掉几条"。

## 六、运行环境

- 服务端：Windows / Linux，Python 3.12，SQLite；`uvicorn` 单进程（内置 worker）；
- 浏览器：Chrome / Edge 最新版（含手机浏览器，窄屏自适应）；
- 联网要求：需可访问所配置的大模型 API（DeepSeek 等）；
- 本地演示：`http://127.0.0.1:8000`（详见《系统说明》的运行步骤）。

## 七、适用与边界（如实写）

- **适用**：中文/英文文献的精读、术语统一、引文定位、按体例起草与自查；
- **不承诺**：不做"一键写完整篇论文"；不替代 Word/LaTeX 的最终排版（导出 .docx 后可自行套模板）；
- **数据**：文献与稿件存本地库；翻译、导读、问答会调用云端模型 API（不是"数据不出本机"）。
