## 一、产品是什么

**文献理解与写作辅助平台**——三个模块**彼此独立、又可以合作**，共享同一套文献资产：

| 模块 | 干什么 | 能不能单独用 |
|---|---|---|
| **读懂** | 读一篇文献：段落精读 / 原版 PDF / 纯中文 / 双语；结构化导读、术语表、带出处的问答 | 是 |
| **起草** | 写稿：素材栏 + 草稿区 + 助手；把素材插成引文，点引文回原文 | **是**——不需要先有文献 |
| **收口** | 检查稿子：该引未引、术语一致性、格式自检 | 是（入口在起草页里） |

⭐ **模块独立的证据不是"界面上有几个入口"，而是这一条**：**起草与收口可以不经过"读懂"直达**（已实测）。
⚠️ 反过来说：**"左栏可收起"不能当模块化的证据**——58px 那一列里不止三个模块图标，还有集合/标签/素材一整套。这条论证已废弃。

### 差异化只有一句

> **每条结论都能点回原文那一句。**

竞品（同类文献工具）普遍管到**文献级**——"推荐你读这篇"；我们管到**句级**——"这个结论来自第 2 页的那一句"。
我们**没有**"译文快照与原文的句级配对"这类数据结构上的对手，所以这条差异**必须在界面上一眼可见**，否则等于不存在。

## 二、交互模式：一个常驻左栏 + 右侧工作区

**"做什么"（动作）和"有什么"（资产）是两种不同的东西，不能用同一套导航表达。**
所以左栏分两段：**上段是动词，下段是名词。**

```
┌──────────┬──────────────────────────────────────────────┐
│ 左栏 260px│  右侧工作区（随左栏选择而变）                  │
│ docwise  │                                              │
│ ── 做什么 ─│  ← 第一段：动作入口（三个模块，各自独立）      │
│ ▸ 读懂    │                                              │
│ ▸ 起草    │                                              │
│ ▸ 收口    │                                              │
│ ── 我的库 ─│  ← 第二段：资产（这才是"知识库"，不是历史列表）│
│ ▸ 全部文献 │                                              │
│ ▾ 集合    │                                              │
│   · 手性课题│                                             │
│ ▸ 标签    │                                              │
│ ▸ 待读 3  │  ← 智能集合（规则可见）                        │
│ ▸ 素材 12 │                                              │
│ ▸ 草稿 2  │                                              │
│ ▸ 引用 34 │                                              │
│ ──────── │                                              │
│ 记忆      │  ← 记忆可看可删可下钻                          │
│ 处理过程  │                                              │
│ ──────── │                                              │
│ 本地优先 · 服务自持                                          │
│ 小研 ›   │  ← 账号区（点进个人中心，进入后高亮）            │
├──────────┴──────────────────────────────────────────────┤
│ 状态条：数据流向 / 本次用了哪个模型 / 待处理 3 处            │
└─────────────────────────────────────────────────────────┘
```

### 2.1 左栏可收起（260 ⇄ 58）

| 态 | 宽度 | 显示什么 |
|---|---|---|
| 展开 | **260px** | 图标 + 名称 + 计数徽章 + 分组标题 |
| 收起 | **58px** | **只剩图标**；悬停/聚焦出 tooltip 显示名称 |

- 左栏顶部一个 `«` / `»` 按钮；**`Ctrl+B`（macOS `Cmd+B`）等效**；**收起状态记住**（`localStorage`）。
- 收起时功能不丢：图标仍可点、选中态仍高亮、计数徽章藏起来但筛选照常。
- ⚠️ **tooltip 必须用 CSS 实现**（不用原生 `title`——延迟与样式不可控），且 **`:focus` 也要能触发**（键盘用户）。
- ⭐ **收起的唯一理由是"阅读时让出横向空间"**——不是模块指示器（那条论证已废弃）。

### 2.2 首页（第一次打开）不是 hero，是"我的库"

**老用户每次进来看到的应该是自己的资产，不是营销文案。**
`hero` 只在**空库**时出现一次；有历史后收成一行。

| 改动 | 为什么 |
|---|---|
| 大 hero → **左栏 + 我的库** | 看到资产而不是文案 |
| 上传卡 → **顶栏两个平级按钮**（＋上传文献 / ＋新建草稿） | 两者**平级**——这一条就解决了"模块没独立" |
| 卡片显示"2 天前" → **显示「在手性课题」「素材 4 · 引用 2」** | 从**时间导向**改成**资产导向** |
| 网格 → 网格 + **筛选 / 标签** | 从"翻找"变成"查找" |
| 底部多一行**知识库概况**（N 篇 · M 块 · X 素材 · Y 引用 + 标签云） | 让"攒资产"看得见 |

### 2.3 手机端（<720px）

左栏 → **底部标签栏 5 个**：**库 / 起草 / 检查 / 记忆 / 我的**。
⚠️ **第一个叫「库」不叫「读懂」**——它进的是书单，标签叫"读懂"会让窄屏用户困惑。
⚠️ **命名口径**：桌面叫「**收口**」（流程叙事词），手机标签因字数显示为「**检查**」，抽屉标题「检查这篇稿子」。**文档里一律写「收口（手机端显示为检查）」。**

⭐ **手机端的定位是"口袋里的库"**：待读队列 + 素材卡浏览（复习）+ 进度查看。
**不在手机上做精读、不缩桌面三栏**——文献类工具的手机端普遍只做"库 + 标注"，硬塞一个挤巴巴的精读页不如做减法。

### 2.4 断点（四级，不是一个断点管两件事）

| 宽度 | 布局 |
|---|---|
| **≥1100px** | 三栏全展开 |
| **1024–1100px** | **右栏改抽屉、左栏仍在**——桌面渐窄的自然过渡，**明确承认它** |
| **<860px** | 左栏收成 **58px 图标态** |
| **<720px** | 手机底部标签栏 |

## 三、三个模块各自长什么样

### 3.1 读懂

左栏选「读懂」→ 没选文献先进库；选了就进阅读工作区。
**左：段落精读（默认）/ 原版 / 纯中文 / 双语**（后三者用 pdf.js，所以点出处能高亮那几句、点 PDF 里任意一段能「就这段提问」）。
**右：三个副页签**（导读 / 术语 / 问答）+ **一个固定区块**「本篇已产出：素材 4 · 引用 2」。

⚠️ **页签数不增加**：素材**不做成第四个页签**，而是右侧的固定块——点进去是那一篇的素材清单。
⭐ **问答不是"一个聊天框"**：它是**取证据的手段**，所以每条答案都自带「＋存为素材卡」。

### 3.2 起草（**不需要先有文献**）

```
左栏 │ 素材（资产层）│ 草稿 │ 助手（提纲 / 引用 / 过程）
```
- 素材栏顶部有**来源筛选**（按集合 / 标签）——这就是**资产层与知识库的接口**："按手性课题这一组文献抽素材"。
- **素材为空时**显示「[去读懂一篇]」+「[不读文献，直接写]」——**后者必须真能用**。
- 插入引文后，**点 `[1]` 回原文高亮**；源文献已删则**如实说"源文献已删，仅存快照"**，不许做死链装活链。

### 3.3 收口 ⭐ **是起草页里的检查抽屉，不是独立页面**

**为什么改**：收口与起草**共用约 80% 的界面元素**（文档区 + 报告区），单独成页是重复。
做成抽屉后，**检查时能同时看到自己的草稿**（"这句话该引没引"要对着上下文看）。`Esc` 可关、点遮罩可关。

**三类检查**：

| # | 检查 | 口径 |
|---|---|---|
| ① | **该引未引**（核心） | 标出"非通识论断但无引用标注"的句子，**并指出该引素材库里的哪一条 · 第几页 · 哪一句** |
| ② | **术语一致性** | 并列摆出两处原文，**不自动改** |
| ③ | **格式自检（最小必要集）** | 只做 3–5 条**纯函数**规则：引文编号连续性 / 文内编号与文后条目一一对应 / 条目字段完整性。**输入是我们生成的 CSL-JSON，不接 Word、不做版面分析** |

⭐ **两条可直接念的口径**：
- **"格式检查做最小必要集，纵深押在引用语义。"**
- **"该引未引"的最保守判据**：① 标记词表（数据断言 / 他人观点两类）② **无 `[n]` 标注 → 报** ③ 有 `[n]` 标注、或含模糊限定词（可能/或许/一般认为）→ **不报**。④ **任何命中词前方 8 字内出现「我们/本文/本工作/本研究/本课题组」→ 一律不报**（"本研究表明"是作者自己的工作）。**宁可少报**——"查出的 3 处全部成立"比"查出 10 处一半误报"强十倍。

⚠️ **两个输入盲区（已记入实现待办）**：
- **E1 · 语言**：词表与判据全是中文的，**拖一份英文稿进来会静默失效**（一句都报不出来，且不会说"我不支持"——比报错更危险）→ 先判语言，英文稿走最小英文词表，并按语言路由到 `text_quote`（英文）/ `translated_quote`（中文）。
- **E2 · 引用制式**：判据核心是"无 `[n]` → 报"，但 GB/T 7714-2015 **允许两种制式**——一份**著者-出版年制**的稿子（全文无 `[n]`、但每句带「（作者，年份）」）会被**全部报成"该引未引"，误报爆炸且爆得隐蔽**。→ 判语言之后**再加一步判引用制式**；识别不出就**明示"未能识别引用制式"并归「无法判断」档**（不硬猜）。

### 3.4 个人中心（整页，不是抽屉）

六个区块：**① 身份**（含显示名可改、上次登录）· **② 账号安全**（改密码 / **登录设备与会话列表、可逐个吊销**）· **③ 我的数据**（概览 / **磁盘占用** / **一键导出全部数据** / 备份）· **④ AI 使用台账**（环节 × 走的是什么 × 产出 × **数据流向**；哪些被 AI 生成、哪些被人改过并可看 diff；**可导出 CSV / Markdown**）· **⑤ 偏好**（默认读法 / 档位 / 界面字号 / 动效跟随系统）· **⑥ 管理 + 危险区**（仅 admin 显示管理入口；**删除账号与全部数据**：二次确认 + 明说不可恢复 + **引导先导出**）。

⭐ **③④ 两块是"数据安全与隐私保护"和"AI 使用如实披露"的直接落点**——而且 ④ **就是环节台账的界面化，不是为合规额外造的东西**。
⚠️ **④ 里"哪些被人改过（可逐条看 diff）"依赖块修改事件**（M2 布点之后才有数据）——**数据就位前该区显示"暂无人改记录"**，沿用诚实机制，**不硬编**。

## 四、知识库模型（把"我的论文"做成资料库）

**五个实体**（都在现有 SQLite，不引新基建）：

| 实体 | 是什么 | 关键字段 |
|---|---|---|
| **文献** | 一篇读过的文献 | 现有字段 + `reading_status`（待读 / 在读 / 已读） |
| **集合** | **可嵌套**的组织容器，**一篇可属多个** | `name` / `parent_id` / `sort` |
| **标签** | 文献的**属性**（主题 / 方法 / 状态） | `name` / `kind` |
| **素材** | 从文献里取出的**证据快照** | `text_quote` / `page` / `translated_quote` / `source_name` |
| **智能集合** | **已保存的搜索条件**，自动更新 | `name` / `query`（规则即数据） |

**四条可直接搬的设计**（来自成熟文献管理器的公开模型）：

1. **集合是播放列表，不是文件夹**——一篇文献可以同时在「手性课题」和「毕业论文」里，**不复制**；
2. **标签承载"主题/方法/状态"三类**——**状态类最有价值**（待读/在读/已读），因为它驱动"我今天该干什么"；
3. ⭐ **标签是文献的属性（跟文献走），集合是人的组织（跟人走）**——跨库迁移时标签跟着走、集合位置不带；
4. **智能集合（已保存搜索）自动更新**——"待读 3"这类入口不用手工维护。

### 4.1 ⚠️ 三条语义必须写死（否则将来必然扯皮）

1. **子集合的文献不算在父集合里**——集合**只含直接成员**（照抄成熟实现，不发明第三种）。
   计数 = **直接成员数**。展示层可给括号辅数：「手性课题 3（含子集合共 8）」——**不改语义、靠加信息顺直觉**。
   **为什么不让步**：「包含子项」有个硬伤——**移出操作会变得不可预测**（用户把文献从父集合"移出"，它还在子集合里；父集合视图若聚合显示，用户会以为没移成功）。
2. **智能集合是"规则即数据"，不是硬编码**。辩护维度要说对：**实体化与否不取决于文献有多少篇，取决于规则有多少条、规则是不是数据**。
   加一条规则：代码里 = 改代码 + 测试；数据里 = 插一行表。**硬编码分支超过 2 处，"规则即数据"就回本**——待读/在读/已读三条已经过线。
   **落地范围**：预置规则 + **规则可见**（界面上能显示"规则：状态 = 待读"），否则它就退化成硬编码。
   **三档演进**：① 预置规则 → ②「把当前筛选存为智能集合」（成本极低，只把当前筛选序列化成一行）→ ③ 查询构建器（**有了第 ② 档，第 ③ 档可以一直不做**）。
3. **一篇可属多个集合**——标为**待验证假设**：多挂率 < 10% → 退化为文献上的单选字段。

### 4.2 知识抽取（直接复用已有能力）

- **导读 5 字段**（研究问题/方法/结论/创新点/贡献）→ 每条文献的知识摘要；
- **术语表** → 进跨文献术语偏好；
- **块分级**（题名/标题/图注/正文）→ 按章节看这篇讲了什么；
- **新增**：`reading_status` + **自动建议标签**（规则可读、可改）。

### 4.3 三条"不做"

1. ❌ **不做知识图谱可视化**（重基建，且这一族还在整合）；
2. ❌ **不做工作区隔离**（"一个 notebook = 一组来源"那种各自独立）——**我们的"读懂"是跨文献的**，否则"该引哪一篇第几页"就做不成。**工作区是组织，不是隔离**；
3. ❌ **不做协作 / 共享**——口径是「**单部署、多账号、无协作**」：账号只用于**数据隔离与管理**。

## 五、三个待验证假设（**先有数据，再决定机制建不建**）

| # | 假设 | 判据（预先写死） |
|---|---|---|
| 1 | **用户真的会去改译文**（"句级纠错记忆"完全依赖它） | **生效前提**：观测期 **≥14 天 且 曝光块数 ≥500**，此前一律"继续观测"。**建**：修改率 ≥15% **且** 被改块 ≥50；**砍**：修改率 <5%。其余 → 只对被改过的块做记忆，**不建不砍** |
| 2 | 写论文时一篇文献**真的会同时属于多个集合** | **多挂率 < 10%** → 退化为单选字段 |
| 3 | （原"埋点 3"已归位） | **它不是埋点，是收口的验收标准** |

### ⚠️ 埋点 1 的三条方法论护栏（都是被审查指出来的，别丢）

1. ⚠️ **分母是"被曝光块数"，不是"总块数"**。一篇 212 块的文献用户只精读了 80 块，**分母用 212 会把真实 18% 稀释成 7%，直接改变建/砍结论**。所以要**同时记块曝光**（进视口即记、**幂等**：同一 session 同一块只记一次）。
2. ⚠️ **必须写明前提（防循环论证）**：**"修改率是在提供了编辑入口的条件下测的"**——入口本身会抬高修改率（观察者效应）。引用这个数字必须带这句前提。
3. ⚠️ **埋点要记进入/离开视口两个时间戳**，分析时**用两种分母各算一遍**（全部曝光块 vs 停留 ≥3 秒）——**把"曝光定义"之争变成一次数据对照**。

⭐ **附带收益**：这个埋点本身就是"**人改留痕**"的证据——"哪些句是 AI 译的、哪些被学生改过"，**同时喂合规与材料**。

> ⚠️ **这里只列形态层面的依赖**；**具体任务卡、分支名、验收判据见 [任务划分与分工](任务划分与分工_v1_20261014.md)**。

| 期 | 主题 | 依赖 | 完成判据 |
|---|---|---|---|
| **M0** | **左栏骨架**（哈希路由 + 两段式左栏 + 收起态 + 首页换成"我的库" + 手机底部标签栏 + 账号区） | 无（**地基**） | 四个入口都能点、首页显示库而不是 hero、`Ctrl+B` 能收起且状态记住、**账号区点进个人中心且进入后高亮** |
| **M1** | **知识库**（集合 + 标签 + 智能集合 + 筛选 + 卡片资产计数 + 知识库概况） | M0 | 能按"待读"筛出 3 篇；一篇能同时挂两个集合；智能集合自动更新 |
| **M2** | **素材卡** + 问答落库 + **环节台账数据层** | M1 | **删掉源任务后素材卡仍显示出处** |
| **M3** | **起草**（三栏 + 插入引文 + 提纲 + 素材栏来源筛选 + 点 `[1]` 回原文高亮） | M2 | 插 10 条引文，条条带可点出处 |
| **M4** | **收口（检查抽屉）** | M3 | **自造样例 + 组内真稿，报告写"报出 N 处、人工判定 M 处成立"**（**不用百分比**）；⚠️ **样例必须含三篇：中文顺序编码 / 英文顺序编码 / 一篇著者-出版年制**；`M/N < 70%` → 收窄判据（继续少报） |
| **M5** | **说得清 + 我的数据**（处理过程一屏 + 决策日志 + 数据安全四件套 + AI 参与标注 + 导出 + 个人中心 ③④） | M2 + M0 | 底栏状态条能看到"本次用了什么"，能导出；**③④ 块可用、台账能一键导出（CSV / Markdown）** |
| **M6** | **结构升级**（标题层级 / 表格 / 公式 / 参考文献区；目录从平铺变树） | 无（**后端/引擎侧，不碰前端**） | 目录是树；参考文献区能自动出条目 |
| **M7** | **记忆**（术语偏好 / 引用偏好 / 句级纠错 + 请求前注入） | M1/M2 的数据层 | **术语一致率（有 / 无记忆）出对照数字** |

**两条要点**：

1. **M0 是硬门槛**——左栏入口、`#/write` 路由、账号区、手机标签栏全是它建的，**没合进 main 之前不要发 M1 之后的前端任务**。
2. **M6 是唯一能真正并行的一线**——**不碰前端**，第一天就能开工。

## 七、明确不做（写清是为了不被当漏项）

| 不做 | 理由 |
|---|---|
| ❌ **深色 / 沉浸模式** | 段落视图在暗色下成立，但 PDF 是画布、不跟随主题。需要一整套语义色重定义 + 逐屏验证 |
| ❌ 主题换肤 / 自定义配色 · 插画系统 / 吉祥物 · 品牌 VI 重做 | 本阶段不做"好看"，做的是"不干扰阅读 + 让溯源成为视觉签名 + 不空" |
| ❌ 玻璃拟态 / 渐变 / 3D / 视差 · 交互动效的"惊喜感" | 读文献时任何多余运动都是干扰 |
| ❌ **重基建**：向量库 / Pinia / Alembic / Capacitor / 图数据库 | 现有 SQLite + FTS5 + 手写迁移够用 |
| ❌ **用户自定义查询构建器**（条件组合编辑器） | 属于几千条规模的解法；我们有"预置规则 + 把当前筛选存为"两档就够了 |
| ❌ **宣称未实现的能力** | 撤过一次同类话术（见下） |

### ⚠️ 一条已纠正的不实宣称（留档，引以为戒）

**"精档 / 三档"**：`engine/registry.py` 里精档**一直映射到中档**（没有审校步骤），界面上却写着"最准，多一道审校"——
**2026-09-30 已从上传卡与「换档位重译」里撤下**，**界面只提供快 / 中两档**，也不再承诺"多一道审校"。后端枚举**故意保留**（老任务数据与校验还要用）。
**教训：界面上的每一个能力描述，都要能在代码里指出它对应的实现；指不出来就不许写。**
