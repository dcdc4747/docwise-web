# 断点逐档量测记录（2026-10-16）

> **这份文档回答什么**：形态 §3.4 定了四级断点（`≥1100` / `1024–1100` / `<860` / `<720>`），
> 但此前**只逐屏走过一次手机档**（`db96fcd`，<1024 那批），**桌面各档从没逐档量过**。
> 这里把 **12 个宽度 × 2 个页面**（库页 / 阅读页）的实测结果落下来，并给出**一条真实缺口**。
>
> 上一轮的量测（**390 窄屏**）见 [`窄屏390量测记录_20261016.md`](窄屏390量测记录_20261016.md)（已合进 main，#155）；
> **本文与它同一套口径**，两份合起来才是完整的"逐档"账。

## 一、口径（与 390 那轮逐条一致，便于对照）

- **环境**：`uvicorn` 同源部署（`frontend/dist` 已 `bun run build`）+ 无头 Chrome，
  `Emulation.setDeviceMetricsOverride(width, 900, dsf=1, mobile=false)`。
- **"溢出"分三档，绝不混成一句**：
  1. **文档级**：`document.scrollingElement.scrollWidth − clientWidth`（真出横向滚动条）；
  2. ⭐ **被裁**：元素右边界超出**最近的 `overflow-x` 非 `visible` 祖先**的右边界 → 用户看不到；
  3. **自家可横滚**：元素自己 `overflow-x: auto|scroll` → **有意的，不算 bug**。
- ⚠️ **为什么必须分档**：本项目 `.dw-layout` 是 `overflow: hidden`，
  内容被顶宽时**文档宽度一动不动**，只看第 1 档永远"一切正常"。
- 覆盖：宽度 **1440 / 1200 / 1100 / 1099 / 1024 / 1023 / 900 / 860 / 859 / 768 / 720 / 719**
  （四级断点的**每一级两侧**都取到），每档 × 库页 + 阅读页。

## 二、结论：**横向溢出与被裁，全档为 0**

12 档 × 2 页 = 24 次量测：**文档级溢出 0、被裁元素 0**。
（对比：同一口径在 390 那轮量出 3 处真被裁——阅读页 596 个、库页 31 个、处理过程 5 个。
那三处已在 PR #155 修掉，**本次桌面档复核没有发现同类问题**。）

## 三、四级断点行为对照

| 形态 §3.4 要求 | 实测 | 结论 |
|---|---|---|
| `≥1100px` **三栏全展开** | 1440：左栏 **260** + 正文 **1180** + 右助手 **400**（static） | ✅ |
| **`1024–1100px` 右栏改抽屉、左栏仍在** | 1100 / 1099 / 1024：**右助手仍是 340px 常驻（static）**，没有抽屉、**也没有任何"助手"开关** | ❌ **见第四节** |
| `<860px` **左栏收成 58px 图标态** | 860：左栏 **260**；**859：左栏 66.7**（= 58 + padding），图标态、文字藏起 | ✅ **边界落在 859/860 之间，与要求一致** |
| `<720px` **手机底部标签栏** | 720：标签栏 **不出现**；**719：出现**（高 45px） | ✅ **边界落在 719/720 之间，与要求一致** |
| （形态未写）`<1024px` 单栏 + 助手变底部抽屉 | 1023 及以下：`.assist` 不再渲染，改用 `.sheet`（absolute、peek 118px 高） | ✅ 与既有 v1 口径一致 |

**其他顺带量到的**（都正常）：

- 阅读页顶栏切换正确：`1024` 还是 **桌面 `.reader-top`**，`1023` 起换成**手机 `.ptop`**（只渲染一条）；
- 库页网格按预期降列：`≤1100` 三列→**两列**、`≤860`→**一列**（列数变化本身无溢出）；
- 写作页右栏（`.wr-helper`）在 `1024–1099` **确实变成 fixed 抽屉**（`style.css` 的
  `@media (min-width: 1024px) and (max-width: 1099px)`）——**说明"抽屉"这套做法仓库里已有先例**，
  缺的只是阅读页那一个。

## 四、⚠️ 量出来的真实缺口：阅读页右栏在该档没变抽屉

**现象**：`1024–1100px` 这一档，阅读页右助手 `.assist` 与 `1200px` 时**完全一样**
（`flex: 0 0 340px` + `static`），既没变抽屉、也没有抽屉开关。

**证据**（`docs` 侧引用，原始 JSON 在本地 `temp/measure-desktop.json`）：

| 宽度 | 左栏 | 右助手 | **正文列还剩** |
|---|---|---|---|
| 1200 | 260 | 340px static | — |
| **1100** | 260 | **340px static** | **840** |
| **1099** | 260 | **340px static** | **839** |
| **1024** | 260 | **340px static** | **764** |

即：**1024 宽的窗口上，固定 chrome 占掉 600px（左栏 260 + 右助手 340），正文列只剩 764px**。
这正是形态 §3.4 要把它做成抽屉的理由（原文："桌面渐窄的自然过渡，**明确承认它**"）。

**代码侧对照**：`style.css` 里 `.dw .assist` 只有两条规则——
第 585 行 `flex: 0 0 400px; … display: flex;`（基档）与第 896 行 `@media (max-width: 1280px) { flex: 0 0 340px }`。
**没有任何 `1024–1099` 档的 `.assist` 规则**，所以那一档只能继承 `≤1280` 的常驻形态。

**要改的话，缺的是三样**（不是一行 CSS）：

1. `.assist` 在该档的 `position: fixed` 抽屉形态（照 `.wr-helper` 那套抄）；
2. **一个"助手"开关按钮**——`ReadView.vue` 现在**没有任何 assist 折叠/开关**（顶栏只有搜索/下载/更多）；
3. **一个开合状态**（`useReader` 里加，或复用既有 `assistTab` 那类 store 字段）。

⚠️ 这三样都是**动界面**，而且改的是"设计已冻结"的形态文档里写明的四级断点——
**需要你拍板**，所以本文只记录现状与证据，**没有动代码**。

### ✅ 2026-10-17 已补上（本节从"缺口"变成"已修"）

用户拍板"要做完"，三样都落地了（分支 `feat/read-assist-drawer`）：

| 缺的 | 补成什么 |
|---|---|
| ① 抽屉形态 | `style.css` 新增 `[断点]` 段：`@media (min-width: 1024px) and (max-width: 1099px)` 里 `.assist` 改 `position: fixed; right: 0; width: 340px; transform: translateX(100%)`，展开加 `.assist-open` 归位（照 `.wr-helper` 那套，不另发明） |
| ② 开关 | 顶栏加「助手」按钮（`.assist-toggle`），只在那一档出现；**文案与图标随开合变**（助手 ↔ 收起助手） |
| ③ 状态 | `useUi.assistDrawerOpen` + `toggleAssistDrawer()` / `closeAssistDrawer()`，**默认收起**（正文先拿回整宽）；与手机的 `sheetState` 是两套，**没合并** |

**实测（Chrome DevTools MCP 逐档量的，量的是 `position` / `transform` / 正文列宽）**

| 宽度 | 开关 | `.assist` | 正文列 |
|---|---|---|---|
| 1440 | 藏 | static 400 | 780 |
| 1200 | 藏 | static 340 | 600 |
| **1100（档外第一个宽度）** | **藏** | **static 340** | 500 |
| **1099** | 显示 | **fixed，收起时 translateX(340)** | **839**（原来只有 499） |
| **1024** | 显示 | **fixed，收起时 translateX(340)** | **764**（原来只有 424） |
| 390（手机） | 不渲染 | `.sheet peek` | 323（未受影响） |

⚠️ **实拍抓到一个坑并修掉**：抽屉是全高 `fixed`，展开后会**把顶栏那个「助手」开关自己盖住**——
鼠标用户点开之后只剩 Esc 一条路回去。所以抽屉**自带一个关闭键**（右上角 ×，只在那一档显示）。
关闭键放在 `.tabs` **外面**：`.tabs` 的契约是"只有三个页签"，`app.smoke.test.js` 直接断言页签文字。


## 五、一条文档与实现对不上的小事

形态 §3.4 的断点表**只列了四行**（≥1100 / 1024–1100 / <860 / <720），
但仓库里实际还有一条 **`≤1280`**（`.assist` 400 → 340）。也就是说
**`1280` 这个档在文档里根本没写**——下次照文档推"断点只有四个"的人会漏掉它。
建议顺手在表格里补一行（或补一句"另有 1280 一档只调右栏宽度"）。
