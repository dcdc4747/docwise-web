# Agent 工具箱清单与设计规则（2026-10-18）

> 这份文档回答一个问题：**这个 agent 到底能用什么**。
> 工具的权威定义在代码（`backend/app/agent/packs/*.py`），
> 这里的表格由 `GET /api/agent/scenes` 的 `tools` 字段**实时可核对**——
> 文档说有多少个，接口就该吐出多少个。

## 一、为什么要这份清单

第一版只把「检索知识库」包成了工具，等于**把 agent 当成了搜索引擎**。
这个项目真实的能力面远不止检索：翻译任务、导读与术语表、素材卡、草稿、引文、
参考文献排版、校对检查、记忆与偏好。

清单的作用是把"能力面 → 工具 → 场景"这条链固定下来，
避免**拍了脑袋加工具**，也避免**明明有能力却没给 agent**。

## 二·五、挂载结果（实测，2026-10-18）

```
read_ask      → 9 个工具
  search_library, read_blocks, search_terms, list_tasks, get_understanding,
  get_progress, request_retranslate, get_preferences, search_memories

write_compose → 13 个工具
  list_drafts, read_draft, search_materials, search_library, read_blocks, search_terms,
  list_citations, suggest_citation, run_check, format_bibliography,
  list_materials, get_material, create_material
```

⚠️ **13 已接近上限**：工具再多，模型选工具的准确率会掉。
超过 15 个就该**拆场景**（例如 `write_compose` 与 `write_check` 分开），
而不是继续往一个场景里塞。

⚠️ **已知重复**：`writing.search_materials` 与 `materials.list_materials` 功能重叠
（前者是历史位置）。下一步应把检索挪进 `materials`，`writing` 只留草稿相关工具。

## 三、场景挂载原则

| 场景 | 该挂哪些包 | 理由 |
|---|---|---|
| `read_ask`（读懂） | `library` `terms` `tasks`（+ `translate`） | 读懂侧要能"找到那篇 → 读段 → 对术语 → 看进度" |
| `write_compose`（写作） | `writing` `library` `terms` `cite`（+ `check` `biblio` `memory` `materials`） | 写作要"读稿 → 找依据 → 统一术语 → 查引文 → 排版 → 自查" |

**一个包可以被多个场景共用**（`library`、`terms`），这是刻意的：
能力复用，权限（谁能用）由场景白名单决定，不靠复制代码。

## 四、四条硬规则（写工具前先对照）

1. **读工具随便给，写工具必须显式确认**
   写操作（重译、建素材、插引文、改稿）的入参必须有 `confirm`，
   缺省状态只解释"需要用户在界面上确认"，不真做。
   理由：agent 不能被一句话就改坏用户的东西。

2. **归属过滤必须在工具里做**
   `ctx.user_id` 不匹配一律当"找不到"，不靠前端拦。
   已有用例钉着这条（读别人的草稿/文献/素材都要读不到）。

3. **不许 import `pydantic_ai`**
   `packs/` 与 `scenes/` 只认 `contracts.py` 的 ABI；换引擎只改 `runtime.py`。
   有结构用例正则匹配真实 import 语句。

4. **handler 签名固定 `(ctx, args: dict | None = None)`**
   runtime 以 `spec.handler(ctx, payload_dict)` 调用。
   写成 `(ctx, draft_id=None)` 的后果实测过：整个 payload 被当成 draft_id →
   `int(dict)` 抛异常 → 模型重试两次后整轮失败（`Tool ... exceeded max retries`）。

## 五、还没包的能力（按价值排序）

1. **长文精读**：`summarize(task_id, section)` —— 超长文献分段摘要（现在只能整篇导读）；
2. **写作多句改写**：现在 `revisions` 一条一句，应支持整段 + 逐条接受/拒绝历史；
3. **记忆写入**：`remember(term_pref)` —— 术语与写作偏好跨会话（需要用户确认）；
4. **任务生命周期**：`retry` / `cancel` / `purge`（都属于写操作，全部要 confirm）；
5. **插图与表格**：`list_figures(task_id)`（块分级已有 caption 判据，可直接用）；
6. **对比阅读**：`compare_tasks(task_a, task_b)` —— 两篇同主题文献的异同。

## 六、怎么验证清单没过期

```bash
cd backend
uv run python -c "
from fastapi.testclient import TestClient
from app.main import app
for item in TestClient(app).get('/api/agent/scenes').json()['items']:
    print(item['id'], len(item['tools']), item['tools'])
"
```

表格里的"工具"与输出的名字**必须一一对应**；
用例 `tests/test_agent_core.py::test_scenes_endpoint_lists_ready_scenes`
会断言至少这三个包在（`library` / `terms` / `tasks`）。
