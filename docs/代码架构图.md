# 代码架构图（当前阶段）

> **约定（长期）**：本图是当前代码架构的权威快照。**改代码（尤其模块 / 接口 / 数据结构 / 路由 / 引擎层）后，必须同步更新本图**，方便后续 AI 一看就懂、能深入底层。与本仓库 `AGENTS.md` 的"后端结构"一节保持一致；相应的长期记忆在顶层 `AGENTS.md` 的"代码架构图"一节。

## 分层架构

```
前端 SPA（Vue3 + Naive UI，App.vue 单文件）
   │  fetch /api/*、EventSource /api/tasks/{id}/events、HEAD /files/{mono|dual}
   ▼
FastAPI（main.py：全部路由 + SSE）
   │  enqueue(task_id)
   ▼
worker（TranslationWorker：单进程串行 + 行锁认领 + 线程池跑引擎 + 事件总线）
   │  get_engine(tier).translate() 子进程
   ▼
engine/（可插拔：base 接口 → open_source 快档 / medium 中档 / registry 按档位选）
   ▼
SQLite（tasks / task_history / task_blocks / task_understanding）
```

## 模块依赖（Python import 拓扑）

```
配置/存储层：
  config.py ──► pydantic_settings（.env；含 DEEPSEEK_* 与 DOCWISE_ENGINE_*）
  db.py     ──► config；SQLAlchemy engine/session（get_db）
  models.py ──► db；engine.base.BlockState   # Task / TaskHistory / TaskBlock
引擎层：
  base.py        ──► stdlib   ABC TranslationEngine + TranslateRequest/TranslationResult + 状态枚举
  open_source.py ──► base      # 快档：subprocess 调外部翻译脚本 → result.json
  medium.py      ──► open_source  # 中档：继承快档、换 DOCWISE_ENGINE_MEDIUM_* 前缀
  registry.py    ──► base/open_source/medium  # _ENGINES 按 Tier 选引擎；PRECISE 当前映射 medium
  __init__.py    ──► 以上全部，对外 re-export
worker/路由层：
  worker.py ──► db；engine；models   # 扫表恢复/行锁认领/线程池跑引擎/落库/发布事件
  main.py   ──► config；db；engine；models；worker   # 全部路由 + SSE + 建档
  llm.py    ──► config；httpx 调 DeepSeek 抽导读/术语（M1 首次真跑 LLM）
前端：
  main.js  ──► App.vue；style.css
  App.vue  ──► naive-ui 组件 + fetch(/api/*) + EventSource + HEAD(/files/*)
```

## 核心数据流（上传 → 出稿 → 预览）

```
① POST /api/tasks/upload：存文件到 data/uploads/ → 建 Task(pending) → worker.enqueue 返回 202
② worker._loop：_claim(pending→in_progress,行锁,清旧块) → _load_request
      → get_engine(tier).translate()(线程池) → 引擎 subprocess→result.json(mono/dual+blocks)
      → _persist_result(写 TaskBlock + Task.status/progress/双路径) → bus.publish(completed/failed)
③ 前端 startProgress：EventSource /events → applyEvent(progress/status)
      → completed 后 checkPreview(HEAD files/mono|dual) → iframe / 下载
④ 获取结果：GET /files/{mono|dual}[?download]；历史 GET /api/tasks；详情 GET /api/tasks/{id}→blocks
⑤ 导读/术语：GET /api/tasks/{id}/understanding（取缓存/状态）；POST 同路径（惰性：未算则调 extract_understanding(带 block_id) 抽取并缓存，成功 ready、失败 failed）
```

## 后续功能接入点（2026.9.8 定稿）

> **关键定稿决策**：①移动端**用 PWA**（不碰原生 Capacitor/APK——响应式网页可装主屏当 App 用，已核实同类非原生形态可获认可）；②**导读/问答用"全量入上下文"**（V4 约 1M 上下文，单篇 <10 万 token 整篇可行），**不建向量库/ChromaDB**；③**导读/术语惰性按需计算**（不走 worker、不建状态机）；④**加 `GET /understanding` 派生状态兜底**；⑤**加 `app/deps.py` 集中依赖注入**。

| 功能点 | 改哪个文件 | 加什么 |
|---|---|---|
| M0 LLM 质量预演（半天~1天） | 独立脚本 / `app/llm.py` | 首次真跑 DeepSeek，验"结构化 JSON 稳定性 + 导读/术语质量 + 单篇 token 成本"；**不验裁剪**（单篇不裁剪） |
| M1 导读/术语（理解层） | 新建 `app/llm.py` + `models.py` + `app/deps.py` | `extract_understanding(texts)->{guide(带 source_block_id), terms}`；**惰性按需**：用户打开"导读/术语"页签才调 LLM、缓存、失败显示"暂无导读"；**不走 worker、不建 enrich 状态机**；`GET /understanding` 派生状态兜底 |
| M2 阅读工作台（UI） | 先抽 composable（`useTaskRunner` 独 owner EventSource、`useTaskHistory`，**不装 Pinia**），再拆组件 | 结果区多 Tab（双语稿/导读/术语表/问答）；**精修 3 个 hero 屏**（双语对照/手机导读卡/档位权衡可视化）；手机加"点溯源"底部抽屉（原文+译文+高亮+出处） |

| M4 论文问答 | 复用 `app/llm.py` + 新路由 | **全量入上下文**（整篇译文+章节标记塞给 DeepSeek）+ **FTS5 词法检索做"长度/噪声超阈值"兜底**；按 block_id 引用、找不到就诚实兜底；**不建向量库** |

## 关键观察（改动时注意）

1. **LLM 只配置、零调用**：`config.py` 有 `deepseek_api_key/model/base_url`，但代码里没有任何 LLM 客户端调用 → M0/M1 才首次跑起来。
2. **main.py 单文件全路由**：先加 `app/deps.py` 集中依赖注入（`get_event_bus`/`get_engine`/`get_db` 走 `Depends`）；等 M4 真加路由再拆 `app/routers/`。
3. **App.vue 是单文件巨组件**：先抽 composable（状态边界）再拆组件；用 `useTaskRunner`/`useTaskHistory`，**不装 Pinia**；再拆 `ReadingWorkbench`/`GuideTab`/`TermsTab`/`AskTab`/`HistoryList`。
4. **worker 单进程串行 + SQLite 单写者**：所有写库**收敛到一条写路径**；富化**不进 worker 任务状态机**（改惰性按需）；WAL 常开但**不背书并发写**。
5. **SSE 靠进程内事件总线（单进程）**：`worker` 与 SSE 端点共享 `app.state.event_bus`，**勿用 `--workers N` 多 worker**、**勿引入跨进程 pub/sub**（过度设计）；`understanding` 状态一律走 `GET /understanding` 派生，**不新增专用 SSE 事件**。
6. **precise 档当前映射 medium**（`registry.py` 里 `Tier.PRECISE: MediumEngine`），精细引擎未真正接入。
7. **无质量/回退/打回逻辑**：属后续阶段（2027），当前不加，答辩别吹。
8. **迁移**：保留 `create_all` + `_ensure_schema`（`PRAGMA table_info` + ALTER ADD 缺列），**不用 Alembic**；对真实存量库手测一次。
9. **不引入重基建**：**不建向量库/ChromaDB、不装 Pinia、不引入 Alembic、不引入 Capacitor**（用 PWA）——都是为"1 人现场答辩 + 9 月交稿"控成本。
