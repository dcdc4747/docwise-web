## 分层架构

```
前端 SPA（Vue3，App.vue 单文件；PWA：manifest + 最小 SW，可装主屏/离线）
   │  **界面形态 = 原型即设计权威**（`frontend/prototype/product-form.html`）：两级结构
   │  L1「我的论文」库页 / L2 全屏阅读工作区；`.dw` 命名空间整段照搬原型的 <style>，
   │  模板类名与原型一一对应（topbar / lib-wrap / hero / upload-card / grid3 / paper-card /
   │  reader-top / thin-bar / doc-pane / assist / tabs / composer / sheet / toast / menu …）。
   │  **同源部署**：后端直接托管 frontend/dist，一个地址同时给页面与接口（webapp.py），
   │  此时 apiUrl() 退化成相对路径、CORS 用不上；不同源时才需要 ?apiBase= / VITE_API_BASE
   │  **未登录先出登录页**；已登录后：authFetch（Bearer 请求头）+ 票据（?ticket=，给带不了头的请求）
   │  左栏：**段落精读**（我们自己的 DOM，锚点成立）/ **PDF 视图**（pdf.js 渲染 + 文字层，
   │  点出处能滚到那一段并高亮、点 PDF 里的段落能提问）——两种都能"点出处就落在那一段上"
   │  HEAD/GET /api/tasks/{id}/files/{mono|dual}、EventSource /api/tasks/{id}/events
   │  任务动作：取消（进行中）/ 重试（失败·已取消）/ 删除（两步确认）
   │  进度：SSE 推"阶段 + 引擎自报分页进度 + 预计剩余"；拿不到就显示"引擎还没报进度"（不编百分比）
   ▼
FastAPI（main.py：启动/健康检查/CORS/挂载路由与前端产物；routers/：tasks 任务与进度、ask 问答、auth 账号、admin 后台；deps.py 统一鉴权守卫；/api/health 真检查）
   │  enqueue(task_id)；POST /api/tasks/{id}/ask → llm.answer_question（全量上下文 / FTS5 兜底）
   ▼
worker（TranslationWorker：单进程串行 + 行锁认领 + 线程池跑引擎 + 事件总线 + **取消信号表** + **进度搬运工**；心跳 + 周期扫表 + 单任务异常不杀循环）
   │  get_engine(tier, source_lang, target_lang).translate(request, cancel) 子进程（Popen + 轮询取消 → terminate）
   │  进度：progress.py 解析 data/outputs/{id}/engine.log 里引擎的 tqdm 进度条（解析不出就返回 None）
   ▼
engine/（可插拔：base 接口 → open_source 快档 / medium 中档 / **native 中文文献取字** / registry 按"语言对+档位"选）
   ▼
storage.py（磁盘治理：data/uploads、data/outputs/{task_id}、data/backups；删任务/重试清文件、启动回收孤儿目录）
   ▼
SQLite（WAL + busy_timeout；users / auth_sessions / auth_tickets / tasks(user_id, stage, eta_seconds, started_at, finished_at) / task_history / task_blocks / task_understanding / task_blocks_fts[FTS5 trigram]）
   ▼
日志（logging_setup：data/logs/docwise.log，5MB 轮转 ×3；写不了文件自动降级为控制台）+ 引擎日志（data/outputs/{task_id}/engine.log，既是失败诊断来源，也是"真进度"的数据来源）
```

               **三条口径**：① 只跳转不判断（类型只由 `blocktypes.py` 给，前端不自己再猜一遍，
               免得两处口径打架）；② **少于 3 条不渲染这条**（一两个标题的文献摆目录是噪音）、
               一条都没有（老任务 / 扫描件）整条不出现——**不硬造**；③ 桌面 `.doc-pane` 与窄屏 `.pdoc`
               两处各渲染一份（两处的块渲染本来就是分开写的），都指向同一个 `traceTo`。
               测试锁在 `tests/app.smoke.test.js`（列出来 + 跳过去 + 太少不渲染）。
               **原版 / 纯中文 / 双语 PDF**＝`components/PdfPane.vue` 用 **pdf.js** 渲染
               （canvas + 文字层坐标，所以**点出处能滚到那一段并画高亮框、点 PDF 里的段落能提问**；
               以前用 iframe 时这是做不到的，见关键观察 23）
               ✅ **块级译文已解决（2026-09-30）**：这里曾经是个真缺口——**全库 task_blocks 的
               `translated` 一律为空**（引擎包装脚本只写 `{block_id, text}`，译文只存在于 PDF 产物里），
               后果是段落精读只能回退显示原文、问答/检索/FTS 喂给模型的上下文也是原文（模型现场翻译）。
               现在包装脚本在**外部翻译引擎**转换时**把「原文段落 → 译文」成对录下来**并写进 `result.json` 的
               `translated` 字段，做法是钩住三处内部状态：`TranslateConverter.receive_layout`（认页）、
               `ThreadPoolExecutor.map`（那一页按阅读顺序排好的段落——`executor.map` **保序**）、
               `BaseTranslator.translate`（所有翻译器的唯一漏斗，缓存命中也要过它）。
               **块直接取自引擎自己的段落**，顺序与译文天然对齐，**不做任何模糊匹配**
               （第一版拿 PyMuPDF 的块去撞引擎的段落，41 块只贴上 29 块且会错配，已废弃）。
               实测：一份 5 页英文论文 **42/42 块都有译文**，页序正确（p0 6 / p1 12 / p2 12 / p3 11 / p4 1）。
               界面仍保留诚实提示（`hasBlockTranslations` → 「暂无块级译文」）——那是给**历史任务**的：
               2026-09-30 之前跑过的任务译文仍然为空，要重新上传才有。
               ✅ **块上带版面信号了（2026-10-01，任务 3a）**：`receive_layout` 里有**两个同下标的栈**——
               `sstk`（段落文本，我们本来只抓了它）与 `pstk`（段落属性：`size` / `x0` / `x1` / `y0` / `y1`）。
               现在在 `ThreadPoolExecutor.map` 那个挂钩点**顺着调用栈读 `receive_layout` 那一帧的 `pstk`**，
               按 **(页, 原文) 为键**写进每块 `layout`（**不是**与 `sstk` 平行的数组——块列表是**过滤后**的：
               跳空串、跳纯公式、按 (页, 原文) 去重，平行数组一错位几何就全贴到别的段上），
               键与文字层那条路一致：`{unit_h, y0, y1, x0, x1, page_h}`（矩形四角都带，
               因为**双栏页光靠 y 分不开左右栏**——实测第 0 页 `I. INTRODUCTION` 在右栏 y≈297.9、
               左栏正文 y≈297.1）。三个口径要点：
               ① `unit_h` 是**段落内最大字号**（更大的字会顶上去），与文字层那条路的"span 字号中位数"
               不是同一个口径——块分级靠"大 **且短**"两条一起挡，契约写在 `scripts/extract_blocks.py` 里；
               ② `y0` 已翻成**距页顶**（pdfminer 的 y 自下而上：`page_h - y1`），但实测比 PyMuPDF 的行顶
               **系统性地高约 2.2pt**（10pt 正文；字体框顶 vs 行 bbox 顶）——同一坐标系里的固定口径差，
               只用来算相对位置；
               ③ 页高取自**版面数组的形状**（`self.layout[pageid].shape[0]`，引擎按 72dpi 渲染、
               1px = 1pt），**不能拿 `ltpage.height`**——图表（figure）也会过一次 `receive_layout`，
               那时它是图的高；同一页还会被过好几遍（实测 17 页调了 18 次）。
               **录不到几何就照常出块**（`layout` 键都不出现，分级器自动退回文字形状）：三道路障任一不过
               就整批不录——`sstk is items`（确认是这一份段落栈）/ `len(pstk) == len(sstk)` / 页高取得到；
               同页同一段两趟几何不一致 → 该段 `layout = None`（宁缺勿错）。
               实测：化学 arXiv 17 页 **212/212 块带字号与位置**，EBSCO 那份 **42/42**。
               核对手续与全部数字见 `docs/块分级阈值实测记录.md` 第三节。
               ⭐ **外文标题为什么整段消失（同一批查出来的根因，2026-10-01）**：引擎默认的"公式字体"
               正则里有 `CM[^R]`——**CM 后面跟任何非 R 的字母都当公式字体**。LaTeX 排的文献里这条会误伤
               **文本**字体：`CMBX*`（Computer Modern Bold Extended＝章节标题与论文题名，实测 976+374+53
               个字符）和 `CMTI*`（文本斜体，666+76）。被当公式的字符**不进段落文本栈**，只留 `{vN}`
               占位符；纯公式段又不成块 → **标题整段消失**（连题名都没了）。修法用**引擎自己的开关**
               `vfont`（非空时完全替换内置那条），把判据收窄成**数学字面白名单**
               （`CMMI/CMSY/CMEX/MSBM/CMMIB` 那族），**没有改人家的代码**。
               实测 A/B（同一份 PDF、同一台机器、只差这一个参数）：块 **182 → 212**、公式占位符
               **840 → 730**、标题位置上有独立块 **0/37 → 26/37**（其余是多行标题的续行，已并进同一块）。
               产物 PDF 逐页比对过：题名从英文变成「分子旋转动力学中的手性时间结构」、`I. INTRODUCTION`
               变成「一、引言」、`III. CHIRAL MEASURES` 变成「III. 手性测度」，**页数、版式、公式都没坏**
               （左侧那条 arXiv 边栏竖排乱码是引擎固有的老问题，改前改后一模一样）。
               ⭐ **版面区域（任务 A 的第三层）**：引擎自己跑一次版面模型，把每页 `{cls, bbox, conf}`
               写进 `result.json` 的 `regions` → `tasks.regions`（新列，`_ensure_schema` 补）→
               任务详情接口把它交给 `classify_blocks(blocks, regions=…)`，**后端只按坐标贴标签、不切块**。
               坐标口径**写死一处**：origin 左上、y 向下、单位点（实测抽 20 块，块矩形与它落到的区域框
               几乎逐点重合）；按"块**首行中心点**落在哪个区域里"贴，多个区域时取**面积最小**的。
               实测价值（真数字）：化学那份 21 条标题本来靠文字/字号就认得出来、**另有 9 条只有区域
               认得出来**（`II. ORIENTATION TRAJECTORY…`、`Appendix A~G`），另救回 **2 条罗马数字表注**
               （`TABLE I./II.`，文字规则只认阿拉伯数字）；EBSCO 那份 7 条候选里 5 条是真标题

## 核心数据流（上传 → 出稿 → 预览）

```
① POST /api/tasks/upload：存文件到 data/uploads/ → 建 Task(pending) → worker.enqueue 返回 202
② worker._loop：_claim(pending→in_progress,行锁,清旧块,记 started_at/stage) → _load_request（带 output_dir=data/outputs/{task_id}）
      → get_engine(tier, source_lang, target_lang).translate(request, cancel)(线程池) → 引擎 Popen→result.json(mono/dual+blocks) + engine.log
        （**中文文献** source=target=zh：走 native.py → scripts/extract_blocks.py，产出 `mono`=原稿副本、`dual`=null、每块 `translated`=null）
      → 同时起"进度搬运工"：每 1.5s 解析 engine.log 的 tqdm → 写 Task.progress/eta_seconds + bus.publish(progress)
      → _persist_result(写 TaskBlock + 终态/进度/双路径 + finished_at) → bus.publish(completed/failed)
③ 前端 startProgress：EventSource /events → applyEvent(progress/status/eta/页进度)
      → completed 后 refreshWorkbench(GET /api/tasks/{id} 一次取全) → iframe / 下载
④ 获取结果：GET /files/{mono|dual}[?download]；历史 GET /api/tasks；详情 GET /api/tasks/{id}→blocks + files_ready + understanding_status（工作台一次取全）
⑤ 导读/术语：GET /api/tasks/{id}/understanding（取缓存/状态）；POST 同路径（惰性：未算则调 extract_understanding(带 block_id) 抽取并缓存，成功 ready、失败 failed）
⑥ 论文问答：POST /api/tasks/{id}/ask {question} → 总字符 ≤ docwise_ask_full_context_max_chars 走全量上下文；超阈值走 FTS5 trigram 召回 Top8（**必须限定本任务**，2 字词 LIKE 兜底同样限定）→ answer_question 按 block_id 引用（出处 id 经存在性校验）；召不回/失败诚实返回，不编造
⑦ 回访（补门）：历史行"继续读" → openWorkbench(task) 与上传后走同一条路径 → 工作台四页签 + 溯源；「详情」按钮才打开分块状态抽屉
⑧ 运维（保命基建）：启动初始化日志 → 全链路打点（入队/开始/结束用时/失败堆栈）；worker 心跳 + 空闲每 30s 扫表兜底；GET /api/health 真检查（DB 写探测 + 心跳新鲜度 + 队列长度）
⑨ 账号与鉴权（B 批）：未登录 → 登录页；POST /api/auth/register|login → 返回令牌（库中只存 sha256）→ 之后所有任务接口带 `Authorization: Bearer`；
      进度推送/PDF 预览/下载这三种"带不了请求头"的请求 → 先 POST /api/auth/ticket 换票据（绑定 用户+任务+用途，60 秒）→ 拼 `?ticket=`；
      所有任务接口按归属过滤（非本人 404）；`POST /api/tasks`（传服务器路径的旧入口）已删除；存量无主任务启动时归属 `DOCWISE_LEGACY_OWNER`
⑩ 任务生命周期（E 批）：
      **取消** POST /api/tasks/{id}/cancel → 跑着的：worker.request_cancel 置 CancelToken → 引擎线程轮询到就 terminate 子进程 → 引擎回 CANCELLED → worker 落库 cancelled 并发事件；
        排队中的（还没被认领）：条件 UPDATE（WHERE status='pending'）直接置 cancelled，worker 认领时自然跳过；
      **重试** POST /api/tasks/{id}/retry（仅 failed/cancelled）→ 清旧块与旧导读 + 删上一轮产物 + 状态回 pending + 重新入队（task_history 保留，能看出重试过几次）；
      **删除** DELETE /api/tasks/{id} → 先叫停（在跑的话）→ 手工清子表（块/历史/理解/票据，**没有外键级联**）→ 删任务行 → 删上传原件与 data/outputs/{id}；
        子进程死后 worker 发现任务已不存在，会再清一次输出目录（kill 瞬间可能刚写了东西）；
      **磁盘治理** 启动时回收孤儿结果目录（不属于任何任务）+ 陈旧引擎临时目录；`scripts/backup_db.py` 用 VACUUM INTO 备份（WAL 下直接拷 .db 会丢最近改动）
⑪ 诚实进度（F 批）：
      引擎（子进程）翻译时用 tqdm 往 stderr 打进度条，`open_source.py` 把 stdout/stderr 一起重定向到
      `data/outputs/{task_id}/engine.log` → `progress.py` 按 `[\\r\\n]+` 切开取**最后一条**：
      `40%|██  | 2/5 [00:01<00:01, 1.72it/s]` → 页进度 2/5、速率、引擎自报的预计剩余；
      worker 里的"进度搬运工"每 1.5s 搬一次（**只增不减**：引擎分阶段重跑时进度条会回到 0，落库取历史最大值），
      写 `tasks.progress/eta_seconds/stage` + 推 SSE；详情接口另外**当场**从日志解析一份 `engine_progress`（比库里那份新，最多差 1.5 秒）；
      排队中的任务给 `queue_position`（前面还有几篇 = 正在跑的 + id 更小的 pending）；
      **解析不出就什么都不显示**——前端显示"引擎还没报进度"，不编一个假百分比（这是 F 批的全部意义）
⑫ 同源部署（后端托管前端产物）：
      `webapp.mount_frontend(app)` 把 `frontend/dist` 挂到 `/`，于是 `http://<局域网IP>:8000/`
      同时给出页面与接口（前端 `apiUrl()` 退化成相对路径，CORS 用不上）；**挂载点必须写在 main.py 最后**；
      `/api`、`/files` 下的未知路径不参与 SPA 回退（保持 JSON 404），只有浏览器导航（`Accept: text/html`）才回退 `index.html`；
      `index.html` / `sw.js` / `manifest.webmanifest` 发 `Cache-Control: no-cache`；
      产物不存在就跳过挂载并打日志（开发态不构建也能起服务），启动日志顺便列出本机局域网地址
```

11. **问答检索（M4）**：FTS5 用 **trigram** 分词器（unicode61 不拆 CJK，`实*` 零命中；trigram 最少 3 字符）——查询词 = ASCII≥3 字 + CJK 三字滑窗（去虚词）；2 字词（如"方法"）trigram 查不到，走 `translated/text LIKE %词%` 兜底；FTS 表每次启动 DROP+重建（rebuild 回填，容忍分词器/结构变更，开发库代价可忽略）。**问答不进 worker、不缓存、同步直调 LLM**。
12. **检索必须限定任务**（已修的坑）：`task_blocks_fts` 是外部内容表（rowid = `task_blocks.id`），查询要 `JOIN task_blocks tb ON tb.id = f.rowid AND tb.task_id = :task_id`；**block_id 跨任务会重名**（每个任务都有 b1/p0_b0），不过滤会把别的论文的块当本论文出处、而前端按当前任务解析后**看不出引错**。另外 SQLite 下 `bm25()` 必须写表真名（`bm25(task_blocks_fts)`），写别名会报错并被降级分支吞掉。
13. **前端只有一个工作台入口**：`openTask(task, {tab})`（历史"继续读" / 上传后 / 首屏示例入口共用）→ `refreshWorkbench(taskId)` 一次取全（blocks + files_ready + understanding_status）；别处不要再各写一套加载逻辑。理解层保持惰性：打开任务只 GET，用户点"导读/术语"页签才 POST 生成，且每个任务只自动试一次（失败由"重试"按钮显式触发）。
14. **韧性约定（保命基建）**：① **单个任务的任何异常都不得杀死 worker 循环**（`_loop` 里 try/except + `_fail_safely`）；② 新增后台逻辑时要 `logger` 打点（入队/开始/结束用时/失败堆栈），**别再出现"出事没有记录"**；③ 健康检查必须**真验证**（现在会真写一次库并读 worker 心跳），不要写死返回 ok；④ `setup_logging()` 在 `main.py` 导入时调用一次（幂等），测试里也有覆盖。
15. **鉴权与归属约定（B 批）**：① 新增任何"按任务"的接口，必须用 `load_owned_task(db, user, task_id)` 校验归属（**返回 404 而不是 403**，不暴露"存在但无权限"）；② 新增"浏览器自己发起"的接口（iframe / `<a href>` / EventSource 之类）时，鉴权必须走 `get_user_for_files` / `get_user_for_events`（它们接受 `?ticket=`），**不能只认请求头**；③ 前端新增请求一律用 `authFetch`（自动带令牌 + 401 回登录页）；新增上述三种 URL 一律用 `urlWithTicket()`，不要手拼；④ **票据不一次性消费**（60 秒内可重复使用），否则同一页面多次取 URL 会互相把票用掉、表现为"有时打不开"。
16. **测试约定（B 批）**：功能测试默认"已登录"（conftest 覆盖 `get_current_user`/`get_user_for_files`/`get_user_for_events` 返回固定用户，账号 id 见 `tests/helpers.py` 的 `TEST_USER_ID`）；**直接建任务时必须带 `user_id=TEST_USER_ID`**；鉴权类测试（`test_auth`/`test_authz`/`test_admin`）不走覆盖、用真实令牌；上传目录在测试里被指向临时目录，避免写仓库 `data/`。
17. **任务生命周期约定（E 批）**：① **取消不算失败**：状态是第四个终态 `cancelled`，SSE、前端 `TERMINAL_STATES`、健康检查都要认它（漏一处的表现是"进度条卡住不再更新"）；② 取消信号只由 `worker.request_cancel(task_id)` 发，**滚动库里落库由 worker 做**——接口层别抢着写终态，否则会和 worker 的 `completed/failed` 落库打架；③ **数据库外键没开级联**（SQLite `PRAGMA foreign_keys` 默认关，模型里也没写 `ondelete`），所以删任务必须在代码里手工删 `task_blocks`/`task_history`/`task_understanding`/`auth_tickets`；④ 结果文件一律落在 `storage.outputs_dir(task_id)`（**不要用 `tempfile.mkdtemp`**，散落的临时目录没法按任务清理；受限环境里 mkdtemp 建出来的目录还写不进去）；⑤ 引擎子进程用 `Popen` 而不是 `subprocess.run`——只有 Popen 才能中途终止；输出重定向到 `engine.log`（**不要用管道**：管道写满会互相卡死，日志也留不下来）；⑥ 删除/清理文件必须过 `storage.remove_file/remove_dir`，它们只删 `data/` 以内（防记录里的路径被人改过、删到系统文件）。
18. **诚实进度约定（F 批，含两次踩坑后的定稿）**：① **不许编进度**——解析不出引擎进度就说"引擎还没报进度"，宁可显示不确定，也不要一个假装在走的百分比；② 进度数据源只有一个：引擎自己打到 `engine.log` 的 tqdm 进度条，`progress.py` 负责解析；**tqdm 用 `\r` 原地重绘**，所以必须按 `[\r\n]+` 切开取最后一条（按行读只会读到第一条）；进度条单位是**页**（引擎侧 `tqdm(total=total_pages)`）；③ **子进程输出必须不缓冲**：`open_source.py` 给引擎子进程设 `PYTHONUNBUFFERED=1`——stderr 重定向到文件时是块缓冲的，而进度条本来就"停在原地"（`\r` 不换行），不设的话进度会在缓冲里攒着、快结束才一次性落盘；④ **但别指望引擎的进度条会平滑**：实测同一台引擎、10 页论文，中途可能十几秒不更新一条（只有开头和结尾各刷一次）。**所以"已用时间"才是主指标**（`started_at`/`finished_at` 由 worker 写、前端本地走秒），引擎报的页数一律标成"**引擎自报**"（是引擎说的，不是我们的承诺）；⑤ **进度条永远要在**：不知道百分比时画一根流动的条纹条（`show-indicator` 只在 `indicator-placement="outside"` 下生效，所以"不写百分比"这一支别用 inside 指示器）——曾经"没数字就不画"，用户看到的就是"进度条没了"；⑥ 落库时**进度只增不减**（引擎分阶段重跑时进度条会回到 0，跳回去像坏了）；⑦ 读日志只读尾部（`read_log_tail`，默认 8KB）；⑧ 新增"进度类"字段时，前端三处都要认：SSE 事件、轮询兜底、详情接口。
19. **前端渲染约定（前端测试的由来）**：① **模板里要渲染的值一律用 `computed` / `ref`，不要用普通函数**——模板插值一个函数名（少写一对括号）会被 Vue `String(fn)` 把整个函数源码印在页面上，而 `vite build` 完全不报错（F 批真出过这个事故，是用户截图发现的）；② 所以前端加了**渲染冒烟测试**（`frontend/tests/app.smoke.test.js`，vitest + happy-dom）：真挂载 `App.vue`、打开一篇任务，断言页面文本不含 `function `、`=>`、`{{` 这类源码痕迹，**并直接断言原型的结构类名在、旧结构类名不在**（`FORBIDDEN_LEGACY`）——结构退化要红，不能靠人眼；③ 文案逻辑抽到 `src/progressText.js` 做纯函数单测，App.vue 只包一层 computed；④ 改前端后请跑 `cd frontend && bun run test`（首次需要 `bun install`，依赖已在 package.json 里）；⑤ **改了 `sw.js` 或应用壳记得把 `CACHE_NAME` 升一位**，否则用户会一直吃旧壳、刷新也看不到新版本。
20. **中文文献约定（对象是文献本身，不限于外文）**：① **选引擎看语言对，不看档位**——`is_native_pair(source_lang, target_lang)` 两个都是中文才走 `NativeEngine`；**只判源语言是错的**：`zh → en` 是翻译任务，必须交给翻译引擎；② **没有译文不是缺陷**：中文文献的块 `translated` 一律 `null`，理解层（导读/术语/问答）取的是 `translated or text`，所以不需要任何特判——**新写的代码凡是要"读块文字"，都必须继续用这个兜底**；③ **产物就是原稿**：取字引擎把上传的 PDF 复制成 `mono`、`dual` 留空，前端据此把"双语稿"页签改成"原文"、只留一个下载按钮；**判断依据用后端返回的 `native` 字段**，别在前端再实现一遍语言规则；④ 取字脚本 `scripts/extract_blocks.py` 跑在**引擎 Python** 里（需要 PyMuPDF），变量是 `DOCWISE_ENGINE_NATIVE_PYTHON`（未配回退 `DOCWISE_ENGINE_PYTHON`）；**脚本刻意不回退 `DOCWISE_ENGINE_SCRIPT`**，那是翻译引擎的脚本；⑤ **扫描件走本地 OCR**（2026-09-30 起）：文字层是空的时候自动调 `scripts/ocr_blocks.py`——本地 ONNX OCR，**离线、零成本、模型随包自带**。**跨语言的扫描件再走一步逐段翻译**（`scripts/translate_blocks.py`：按编号批量送、按编号贴回，**不做位置对齐**——错位比漏译更糟；某批失败就留空并打日志，界面如实显示"这段没有译文"），产物只有原稿（没有重排版式的 PDF）。实测：8 页中文扫描件 77 秒 → 177 行 → 73 段；5 页**双栏**英文扫描件 → OCR 46 段、**46/46 段全部译出**（同一篇走文字层那条路是 42 段，量级吻合）。
   ⚠️ **段落合并的两个坑**（都是量出来的，别照搬直觉）：
   ① **不用"倍数 × 行高"**——OCR 框紧贴字形，同页行高能差 25%（实测 51–65px），而基线间距很稳；用 1.8×行高 会让整页切成一行一块。
   ② **行距基准必须按栏筛**——双栏页里按 y 排序的"相邻两行"常常**分属左右栏**（实测间距只有 4–10px，真行距 31–37px），把这些串进中位数会把基准拉低一半。正解：对每一行往下找**本栏**最近的一行（横向重叠 ≥ 30%）量间距，取中位数当基准，间距 ≤ **1.25 × 基准**算同一段（实测段内 ≈1.00×、段间 ≥1.33×）。改前 246 段、改后 46 段。
   **样本 <4 条不敢信基准**（两三行的页面里中位数就是段间距），退回按行高判；合并用**并查集**（OCR 在双栏页给的行序是混的）。`result.json` 里带 `mode`（`text-layer` / `ocr`）说明这批字怎么来的；**这个字段一路落到 `tasks.text_source`**（引擎 → `TranslationResult.mode` → worker 落库 → 任务详情接口），界面据此显示「这份文献是扫描件：文字由本地 OCR 识别，可能有个别错字」——**扫描件的字是认出来的，不说明白用户会把 OCR 的错当成原文的错**；**别为了"能跑通"把图片块也塞进块列表**；⑥ block_id 形如 `p{页序}_b{块序}`，**页序从 0 起**（与外部翻译引擎的包装脚本口径一致，前端 `blockLabel` 统一 +1 显示成人看的页码）。
   ⚠️ 这里踩过坑：取字脚本曾写成 `page_no + 1`（1 起），而翻译路径是 0 起，导致**中文文献的「第 X 页」整体多一页**
   （实测一份 8 页文献，最后一块显示成"第 9 页"）。**页号基准只有一处说了算：产块的那一端**，前端不许自己推断。
21. **块分级（阶段 3 第一小步，2026-09-30；2026-10-01 接上引擎那条路）**：`app/blocktypes.py` 把每块判成 **题名 / 章节标题 / 图注 / 正文**（`title` / `heading` / `caption` / `body`），在 `routers/tasks.py` 的 `_serialize_block` 里**当场算**并随详情接口返回；前端只按 `type` 上样式（`pg-title` / `pg-heading` / `pg-caption`），正文不加样式。三个设计决定：
     - **文字形状 + 版面信号，判定只在后端这一处**（编号 `1` / `2.1` / `一、` / `（一）`、常见章节名、全大写短行、`Figure/Fig./Table/图/表 + 数字` 前缀；块上带 `layout` 时再比一比"这块比正文大不大"）。**三条取字路谁手里有版面量谁就往块上带，但判定不跟着走**——各判一遍类型口径必然漂移。三条路当前各给得出什么：**文字层 ✅**（`scripts/extract_blocks.py`：字号 + 加粗 + 位置）、**外部翻译引擎 ✅**（2026-10-01 起：字号 + 位置，**给不出加粗**）、**扫描件 OCR ❌ 还没接**（`ocr_blocks.py` 手里其实有行高与 bbox，是下一步的活）；

     - **题名区＝首页最前面 3 块**（论文题名常被拆成 2–3 块），**在合格的里面取字号最大的那块**（2026-10-01 修，见下）。
     ⚠️ **实测踩到的四条**（都用真样本抓的，别放松这些护栏）：① 全大写规则会吃进**作者署名行**（`BY MADELINE COHEN, AARON PIERCE, …`）与**页脚**（`20AALLSPECTRUMIWWW.AALLNET.ORG`）→ 限长度 ≤45、词数 ≤4、**不含数字与点号**、**不以标点开头**（OCR 切碎的署名碎片就是这么挡掉的）；② 首页头部会掉出 `L` 这种**碎片块** → 题名要有长度下限；③ **罗马数字编号先剥掉再判全大写**（`I. INTRODUCTION` 那个点号否则会被误杀）；④ 中文期刊的 `（一）xxx` **既可能是小标题也可能是正文段首** → 靠**行尾标点**区分（正文那句以句号收尾）。

23. **PDF 视图约定（pdf.js，2026-09-15 上）**：① **为什么不用 iframe**——iframe 里是浏览器自带的阅读器（PDFium），拿不到 DOM 与文字位置，"点出处跳到那一段""点 PDF 里的段落提问"**物理上做不到**；pdf.js 有文字层坐标才能做。风险 1（能不能渲染引擎产物）已实测通过，见 `docs/产品形态说明.md` 第八节。② **命中粒度是"段"不是"行"**：行按纯几何并成段（`pdfText.buildParagraphs`：横向重叠 ≥30% **且** 基线间距 ≤1.8 倍行高；用并查集，所以不依赖行的排列顺序，双栏也不会串）。阈值取自真实产物实测——**段内行距 14.7、段间 ≥25.3**，1.8 倍刚好卡在中间。鼠标扫过与点中亮的都是整段。③ **三种产物都能对到段**：双语稿原页 / 中文文献原稿直接按文本搜到；**纯中文稿靠"几何参照"**——块里是英文、这一份是中文，直接搜必然搜不到，但双语稿是**版式保持的交替产物**（原页 2N-1 / 译页 2N），拿原页命中的 y 区间去译页取重叠的中文段，再映射到纯中文稿的同一页同一区间即可（实测两处取到的中文行完全一致）。**这条不用改引擎、不用改后端**，只读双语稿的几何。真对不上（图/表/扫描页没有文字层）时**只翻页 + 如实说，绝不假高亮**。④ **拉取别用 `?ticket=`**：票据 60 秒，pdf.js 按需分片会中途过期 → 改走 `authFetch` 取 `ArrayBuffer` 一次性喂 `getDocument({data})`，顺带不用管 `/files` 要不要支持 Range。⑤ **同一个 canvas 上并发 `page.render()` 会直接抛错**（"Cannot use the same canvas during multiple render() operations"）——所有渲染必须走 `PdfPane` 里那条**串行渲染链**，每页另有 `rendering` 标记挡重复请求；缩放变化要**先 `task.cancel()`** 再重画，否则旧尺寸会盖掉新尺寸。⑥ 命中坐标只存一份（**缩放 1 的视口坐标**），显示时统一乘当前缩放——窗口一变只改系数，不用重算命中。⑦ 命中方式用**DOM 热区**（`data-para`）而不是拿点击坐标反推行号——缩放、滚动都不会算歪。⑧ pdf.js 的**标准字体数据**由 `vite.config.js` 里的插件从 `node_modules` 发到 `dist/pdfjs/standard_fonts/`（762 KB 第三方二进制，**不进 git**）；不配的话没嵌字体的页面会退化成替代字体。⑨ 单测换掉 `src/pdfLoader.js` 就行——定位与命中全建立在文字层上，跟真不真画 canvas 无关。
