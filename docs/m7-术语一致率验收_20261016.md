## 一、判据原文（照抄，免得后面越说越松）

- **D9**：M7 验收 —— **术语一致率（有记忆 / 无记忆）对照数字**（`docs/任务划分与分工_v1_20261014.md`）
- 形态 §5 待验证假设 1 的**生效前提**：观测期 **≥14 天 且 曝光块数 ≥500**，此前一律"继续观测"；
  ⚠️ **修改率的分母是"被曝光块数"，不是"总块数"**；
  ⚠️ 引用这个数字**必须带前提**："这是在**提供了编辑入口**的条件下测的"。

## 二、怎么测（脚本已入库，零成本可复现）

```bash
cd backend
.venv\Scripts\python.exe scripts/measure_term_consistency.py --baseline
```

它读**库里已有的导读术语表**（`task_understanding`，`status=ready`），跨运行/跨文件统计：
**同一个原文词，被翻成了几种中文说法**。

⚠️ **按"文件名"分组，不按 task 数**——这是这次踩出来的口径：

> 库里同一份 PDF 往往被跑过好几次（同一个 `filename`、多个 task）。
> 按 task 分组会把"**同一篇重复运行的稳定性**"当成"跨文献一致性"报出去，**那是把口径说过头**。
> 所以脚本分开报：① 同一文件内部（可复现性）；② 不同文件之间（跨文献一致性）。

## 三、结果一：无记忆基线（**真实数字，可复现**）

| 项 | 数 |
|---|---|
| 有导读结果的运行 | **14 次** |
| 其中**不同文件** | **8 个** |
| 术语（去重） | **96 条** |

### ① 同一文件、多次运行之间（可复现性）

**共现 17 条，说法不一致 6 条 → 一致率 ＝ 11/17 ＝ 65%**

| 术语 | 库里出现过的中文说法 |
|---|---|
| `advisory board` | 咨询委员会 / **顾问委员会** |
| `vendor champion` | 供应商冠军 / **供应商倡导者** |
| `vendor champions` | 供应商冠军 / **供应商拥护者** |
| `vendor/law firm partnership` | 供应商与律所合作伙伴关系 / **供应商与律所合作** |
| `vendor/law firm partnerships` | 供应商与律所伙伴关系 / **供应商与律所合作伙伴关系** |
| `workflow integration` | 工作流整合 / **工作流集成** |

（加粗的是"少数派"说法。这 6 条全部来自 `pdf_EBSCO_04.pdf` 的多次运行。）

### ② 不同文件之间（跨文献一致率）

**共现 15 条，说法不一致 0 条 → 一致率 ＝ 15/15 ＝ 100%**

### ⚠️ 一处口径更正（我自己第一版算错了，留档）

第一版按 **task 数**分组算，得到 `26/32 ＝ 81%`。那个数**混了两种口径**：
把"同一篇重跑"和"不同文献"当成一件事。按文件名分开之后才是上面这两行——
**65%（可复现性）与 100%（跨文献）**，而 81% 这个数**不要再引用**。

## 四、结果二：有记忆的对照 —— **现在算不出来，如实说明**

**注入链路本身已经通了、也有证据**（不是"写了没接"）：

- `tests/test_memory_inject.py` 16 条用例，其中：
  - **问答接口端到端**：库里存一条术语 → 提问 → 模型收到的 system 提示词里真有它，且命中计数 +1；
  - **导读接口端到端**：同上；
  - **没有记忆时一个字节都不变**（system 必须严格等于原来的提示词）。
- 抓到的注入文本长这样（实测输出）：

  ```
  【术语偏好】用户已固定以下译名，**必须沿用**：advisory board → 咨询委员会；…
  （以上只是**用词与格式**的偏好：`source_block_ids` 仍必须确实支撑结论，
    不因为有偏好而放宽出处要求。）
  ```

**但"模型是否真的沿用"这一步跑不了**，卡在密钥上：

```
httpx.HTTPStatusError: Client error '401 Authorization Required'
  for url 'https://api.deepseek.com/chat/completions'
```

`backend/.env` 里的 `DEEPSEEK_API_KEY`（35 位，`sk-…7ec`）**被服务端拒绝了**。
所以：

- ⛔ **没有**"有记忆 / 无记忆"的对照数字；
- ⛔ **没有**拿旧数据冒充（旧数据里根本没有"记忆"这回事）；
- ✅ 脚本的对照模式已写好，密钥一好就能跑：

```bash
cd backend
.venv\Scripts\python.exe scripts/measure_term_consistency.py --ab 6 ^
  --pref "advisory board=咨询委员会" ^
  --pref "vendor champions=供应商冠军" ^
  --pref "workflow integration=工作流整合"
```

它会：同一篇、同一份文本，先跑一遍**不带记忆**，再跑一遍**带上这些偏好**，
逐条打印"期望 / 实际 / 沿用几条"。

⚠️ 脚本**故意不自己"发明"标准**（必须由人 `--pref` 显式给出）——
否则就成了"自己定标准再拿它证明自己"。

## 五、这次量出来的、比数字更值得记住的一条

**65% 说明的不是"翻译不准"，而是"同一份文本跑两次，术语说法会变"。**

也就是说：记忆在这个产品里的第一价值其实是 **稳定性**（把用户认下的说法钉住），
其次才是"跨文献统一"。而"跨文献"这一项**现在基线就是 100%**（15/15），
**本来就没什么可提升的**——所以将来如果只盯"跨文献一致率"去证明记忆有用，**会证明不出来**。
真要证明，该看的是 **① 同一篇重复运行的一致性（65% → ?）** 与
**② 用户显式改过的说法是否被沿用**。

⚠️ **别把这句写成对外宣传**：这是**单库、单批样本（8 个文件、其中一份 PDF 跑了 7 次）**
的内部测量，不是评测结论。

## 六、限制（引用这个数时必须一起说）

1. **分母是术语条数**，不是词频；只统计在 2 篇及以上出现过的术语；
2. 这测的是"**说法是否统一**"，**不是翻译准确率**；
3. ⚠️ **单复数/标点未归一**：`vendor champion` 与 `vendor champions` 被当成两个词，
   实际是同一个概念 → ① 的分母因此偏小（真实冲突可能更多一点，也可能更少）；
4. 样本偏窄：只有 `pdf_EBSCO_04.pdf` 有多次运行（7 次），其余多数只有 1 次；
5. **有记忆的对照缺失**（密钥 401），所以本文只有"基线"，没有"对照"。
