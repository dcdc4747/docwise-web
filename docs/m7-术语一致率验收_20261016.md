## 二、怎么测（脚本已入库，零成本可复现）

```bash
cd backend
.venv\Scripts\python.exe scripts/measure_term_consistency.py --baseline
```

它读**库里已有的导读术语表**（`task_understanding`，`status=ready`），跨运行/跨文件统计：
**同一个原文词，被翻成了几种中文说法**。

⚠️ **按"文件名"分组，不按 task 数**——这是这次踩出来的口径：

> 库里同一份 PDF 往往被跑过好几次（同一个 `filename`、多个 task）。
> 按 task 分组会把"**同一篇重复运行的稳定性**"当成"跨文献一致性"报出去，**那是把口径说过头**。
> 所以脚本分开报：① 同一文件内部（可复现性）；② 不同文件之间（跨文献一致性）。

## 四、结果二：有记忆的对照（**2026-10-17 补测完成**）

### 4.1 方法

```bash
cd backend
.venv\Scripts\python.exe scripts/measure_term_consistency.py --ab 6 ^
  --pref "advisory board=咨询委员会" ^
  --pref "vendor champions=供应商冠军" ^
  --pref "vendor champion=供应商冠军" ^
  --pref "workflow integration=工作流整合"
```

- **同一篇**（task 6，`pdf_EBSCO_04.pdf`，41 段 / 11,640 字）、**同一份文本**、**同一台机器**；
- 唯一变量：**有没有把用户固定的译名注入 system 提示词**；
- 偏好 5 条 → **实际注入 4 条**（`vendor/law firm partnerships` 那条这篇正文里既没出现原文词、
  也没出现那个译法 → 按"宁少不滥"不注入，这是 `enrich` 的护栏在工作）；
- **重复 3 轮**（每轮 A/B 各一次真实调用），报分布而不是单点。

### 4.2 结果（3 轮，逐轮一致）

| | 无记忆（A） | 有记忆（B） |
|---|---|---|
| 第 1 轮 | 0/4 | 3/4 |
| 第 2 轮 | 0/4 | 3/4 |
| 第 3 轮 | 0/4 | 3/4 |
| **合计** | **0/12 ＝ 0%** | **9/12 ＝ 75%** |

**更该看的那个数（把"这轮没抽到"剔掉）**：

| | 抽到的条数 | 说法与偏好一致 |
|---|---|---|
| 无记忆 | 3 条（每轮 1 条） | **0/3 ＝ 0%** |
| 有记忆 | 9 条（每轮 3 条） | **9/9 ＝ 100%** |

也就是说：**只要模型抽到了那个词，没记忆时它三次都用了别的说法**
（`vendor champions` → 供应商倡导者 ×2、`vendor champion` → 供应商拥护者 ×1），
**有记忆时九次全部严格沿用**。三轮零抖动。

### 4.3 ⚠️ 三个必须一起说的前提

1. **分母会动**：模型每轮**自己选**要抽哪些术语。A 轮里 `advisory board` /
   `workflow integration` 经常根本没被抽出来，所以 `0/12` 里有一部分是"没抽到"而不是"翻错"。
   → 所以第二节那个 **9/9 vs 0/3（抽到就对上）** 才是这条链路的直接证据；`0% → 75%` 是"沿用率"口径。
2. **单篇**（一份杂志 PDF）、**单模型**（`deepseek-chat`）、**3 轮**。要下统计结论得扩到多篇多轮。
3. 这测的是"**用户给的说法有没有被沿用**"，**不是翻译准确率**——它证明注入生效，不证明译得更好。

### 4.4 顺带量到的一件事（值得记）

**有记忆的那一轮，模型更容易把相关术语抽出来**：A 轮经常只抽到 1 条相关术语，
B 轮稳定抽到 3 条（`advisory board` / `vendor champions` / `workflow integration`）。
推测是注入的那段提示词起到了"点名"作用。⚠️ 这只是观察，**没有单独设计实验去证实**，
别当成结论用。

## 五、这次量出来的、比数字更值得记住的一条

**65% 说明的不是"翻译不准"，而是"同一份文本跑两次，术语说法会变"。**

也就是说：记忆在这个产品里的第一价值其实是 **稳定性**（把用户认下的说法钉住），
其次才是"跨文献统一"。而"跨文献"这一项**现在基线就是 100%**（15/15），
**本来就没什么可提升的**——所以将来如果只盯"跨文献一致率"去证明记忆有用，**会证明不出来**。
真要证明，该看的是 **① 同一篇重复运行的一致性（65% → ?，见 §4.2 的 0%→75%）** 与
**② 用户显式给的说法是否被沿用（见 §4.2 的 0/3 → 9/9）**。

⚠️ **别把这句写成对外宣传**：这是**单库、单批样本（8 个文件、其中一份 PDF 跑了 7 次）**
的内部测量，不是评测结论。

## 六、限制（引用这些数时必须一起说）

1. **分母是术语条数**，不是词频；只统计在 2 篇及以上出现过的术语；
2. 这测的是"**说法是否统一**"，**不是翻译准确率**；
3. ⚠️ **单复数/标点未归一**：`vendor champion` 与 `vendor champions` 被当成两个词，
   实际是同一个概念 → ① 的分母因此偏小（真实冲突可能更多一点，也可能更少）；
4. 样本偏窄：只有 `pdf_EBSCO_04.pdf` 有多次运行（7 次），其余多数只有 1 次；
5. **§4 的对照是单篇 + 单模型 + 3 轮**：能证明"注入被沿用"，**不足以当统计结论**；
6. ⚠️ **§4 的分母会动**（模型自己选要抽哪些术语），所以除了沿用率，
   **一定要同时看"抽到就对上"那个 9/9 vs 0/3**。

## 七、怎么复现（环境上的两个坑，都真踩过）

```bash
cd backend
.venv\Scripts\python.exe scripts/measure_term_consistency.py --baseline     # 零成本
.venv\Scripts\python.exe scripts/measure_term_consistency.py --ab 6 --pref "原文=译法" ...
```

- ⚠️ **`.env` 是按当前工作目录读的**（`SettingsConfigDict(env_file=".env")`）。
  从仓库根目录跑脚本时密钥会读到**空串** → 模型 API 回 **401**，看起来像"密钥失效"，
  其实是"没找到 `.env`"。脚本里已 `os.chdir(BACKEND_DIR)`，从哪跑都行；
- ⚠️ 控制台是 GBK 时 `⚠️`/`→` 会抛 `UnicodeEncodeError`，脚本里已 `stdout.reconfigure(encoding="utf-8")`。
