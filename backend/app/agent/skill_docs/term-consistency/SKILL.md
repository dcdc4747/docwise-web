# 术语与译名一致

## 先查表，再开口

涉及术语、译名、缩写时，第一步永远是 `search_terms(query=词, task_id=当前篇)`。
查到了就照库里的译法写；查不到才自己译，并标明「术语表里没有，建议译作……」。

## 与库里不一致时

以**库为准**，并明确说明差异：

「库里把这词译作『通信』，你这句写的是『通讯』，建议统一为『通信』
（见 task 12 的术语表）。」

不要默默改掉用户的用词，也不要反过来用用户的写法覆盖术语表——
**术语表是这套产品的资产，改它要用户点头。**

## 首次出现给全称 + 缩写

- 中文：检索增强生成（Retrieval-Augmented Generation，RAG），此后只用 RAG；
- 英文：Retrieval-Augmented Generation (RAG)；
- 摘要与正文各展开一次是期刊允许的；同一节内不重复展开。

反例：全文一次都没展开就写 RAG；或者每段都展开一遍，
读者以为出现了好几个不同概念。

## 不同文献译名冲突

同一术语在两篇文献的术语表里译法不同时，**并列陈说**，不要私自统一：

「A 篇译作『注意力机制』，B 篇译作『关注机制』；本回答沿用 A 篇，
因为用户正在读 A。」

同时给出两篇的 task_id，方便用户回查。若用户要求统一，再问以哪篇为准。

## 同义混用要收口

同一概念在一段里出现「模型 / 模式」「样本 / 样例」「显著 / 明显」这类混用时，
指出并建议统一；但**统计上的「显著」不能换成「明显」**——前者有检验含义，
后者没有。

## 缩写判据

- 全大写 2–6 个字母、且在本篇术语表或原文里出现过展开式，才当缩写；
- 不要给普通词造缩写（把「方法」写成 M）；
- 同一缩写在本篇指两个东西时，必须分开写清，不能靠上下文猜。

## 反例

1. 把 LLM 展开成「大型语言模型」，而库里是「大语言模型」；
2. 库里那条本身是错译（「神经网路」），仍照抄——应先指出可能有问题，再给建议；
3. 术语表查不到就编一个「标准译名」，不标「建议」；
4. 中文正文里中英混排，同一句一半用英文缩写一半用中文全称。

## 判据

全文同一概念只有一个写法；与术语表的差异都被说出，而不是被抹平；
缩写首次出现有展开；冲突的译名并列且各自可回查。
