# 精读一段的流程

## 什么时候用

用户问「这段什么意思」「这节讲了什么」「作者为什么这么说」「这句话在全文里起什么作用」时。

## 五步

1. **定位块**。页面带了 focus_block_ids 就直接 `read_blocks(task_id, block_ids)`；
   没带就先 `search_library` 找出候选块，再 `read_blocks` 取回原文。
   **不许凭印象解释一段没读过的文字。**
2. **补上下文**。把命中块前后各一到两块一起读（block_ids 按阅读顺序给），
   先解决指代：this / 该 / 上述 / 前者各指什么。跨段的论证要按节读，
   用 `list_sections` + `read_section`，别只抓一句就下结论。
3. **拆句**。把这段分成主张句、证据句、限定句三类；圈出 however / 但 / 仅 /
   在……条件下这类转折与限定。学术段落的结论常在末句，但**不要假设**，逐句看。
4. **解释**。先一句话回答（这段在说什么），再给 2–3 条依据，每条后面挂 block_id。
   用户问的是「什么意思」，不是「复述一遍」，要讲清逻辑链。
5. **收尾核对**。source_block_ids 至少一条，且每个编号都出现在工具返回里；
   回答里不出现工具没给过的页码、段号、数字。

## 区分「原文说」与「我的推断」

- 原文说：写成「原文指出……」，同句给出处，可以进 source_block_ids；
- 我的推断：写成「据此推测……」「如果……那么……」，**不进 source_block_ids**，
  也不要写成作者的观点；
- 反例：原文只做了相关分析，回答写成「作者证明 A 导致 B」——这是把推断冒充结论。

## 看不懂时的三个诚实出口

1. 术语不懂：`search_terms` 查这篇的译法；仍不懂就说「这个词在本篇术语表里没有」；
2. 段落缺失：`read_blocks` 返回空，就说「这篇的块里没有这一段」，
   不要用相邻段落拼一段出来；
3. 证据不足：只有一句结论、没有方法或数据支撑，就说「现有段落不足以判断」，
   并指出该补读哪一节（用 `list_sections` 返回的 index）。

## 反例清单

- 拿常识补原文没说的背景（「这篇应该用了 t 检验」）；
- 把图注、参考文献条目当正文结论；
- 用译文的措辞去推断英文原文的语法结构；
- 一段话挂五个 block_id 撑场面，其中三个与结论无关；
- 用户问「这段」时答了整节，把具体问题稀释成综述。

## 判据

结论句能在原文找到对应；每个 block_id 都来自工具；推断有显式标记；
说不清的地方写「不确定」而不是编一个通顺的解释。
