# 结构梳理（章节 / 目录）

## 唯一的结构来源

用 `list_sections(task_id)`。它按块顺序返回 `{index, kind, text, block_id}`：

- `kind=title` 是**文献题名**，不是一节；
- `kind=heading` 才是章节标题；
- `index` 是读某一节时要传给 `read_section` 的序号。

**不要用正文里的「一、二、三」自己拼目录**，也不要按 PDF 页码猜顺序。

## 层级与跳号如实说

工具**不给层级**，只能从编号形状推断，并且要说清这是推断：

- `I.` / `II.` 一级，`A.` / `B.` 二级；
- `1` / `1.1` / `1.1.1` 逐级；
- `一、` 与 `（一）` 通常是两级中文编号。

跳号就照实说：「原文从 3 直接到 5，第 4 节未出现在块流里」，
**不要自动补一个第 4 节**。编号重复（两个「二、」）也要指出，
可能是扫描件切块或原文笔误。

## 没有标题就说没有

`list_sections` 返回空、note 写「没有识别到章节标题」时，回答必须是：

「这篇没有识别到章节标题（可能是扫描件，或结构不在块流里）。」

然后给替代方案：用 `read_blocks` 按块读，或按摘要 / 关键词 / 图表说明定位。
**绝对不许**拿正文第一段充当「引言」、拿图注充当「图 1 小节」、
拿参考文献首条充当「参考文献一节」。

## 顺序与「缺哪一节」

- 顺序 = index 升序 = 引擎写库的阅读顺序；扫描件双栏可能错序，
  发现语义跳脱时要说明「顺序可能受版面切分影响」；
- 用户问「缺哪一节」时，只能对照**用户给出的清单**或该刊常见结构说「未识别到」，
  不能说「原文没有」——没识别出来不等于不存在。

## 输出格式

1. 一句话总览（共 N 条标题、覆盖到哪一节）；
2. 编号列表：`index · 标题 · block_id`，题名单独置顶；
3. 缺口：未识别到的层级、跳号、重复编号；
4. 下一步：要读哪一节就用 `read_section(task_id, index)`。

## 反例

- 把「摘要」当第一章编号；
- 把 `FIG. 3` 图注列进目录；
- 用户问第三节讲什么，直接用 index=3 去读（index 是结果序号，不是章节号）；
- `read_section` 返回 `truncated: true` 还说「这一节读完了」；
- 把题名当成「一、引言」列进目录。

## 目录与页码

工具只给块顺序，不给页码。用户问「第几页」时，只有工具返回里带页才回答；
没有就说「页码待定」，**不要按块号乘一个页均值去估**。目录顺序按 index，
不按标题文字排序，也不按字数多少排。

## 判据

列出的每一条都能在 `list_sections` 的结果里找到；顺序与工具一致；
没有标题时明确说没有；跳号与截断都如实标注。
