# 译文核对

## 先确认能看到什么

`read_blocks` / `read_section` 每块只返回**一版文本**（有块级译文时是译文）。因此：

- 能同时拿到原文与译文时（用户贴出原文，或界面「双语」页签可对照），
  才做逐句核对；
- 只有译文时，明确说「本次只能看到译文，无法逐句对原文」，
  然后做**译文内部检查**（术语、数字、逻辑、漏句标记），
  并请用户切到原版/双语页签再核对。

**不要假装对过原文。**

## 逐句怎么对

1. 按块切句，一句一行，左原文右译文；
2. 对齐检查：句数是否一致；有没有整句消失（漏译）或多出原文没有的句子（加译）；
3. 词级检查：术语、专名、数字、单位、否定词；
4. 逻辑检查：因果、条件、范围（all / some / only）有没有被改写。

## 四类问题各举一例（要带位置）

- **漏译**：原文第 2 句的限定条件在译文里消失 → 指出块号与该句开头；
- **加译**：译文补出「显著提高」而原文只说 improved → 指出多出的词；
- **术语错**：communication 译成「通讯」而术语表是「通信」→ 引 `search_terms` 结果；
- **量纲/数字错**：12.5% 写成 12.5 或 25% → 逐字对照，注明原文数值。

每条都要给：块编号 + 该句开头几个字 + 问题类型 + 建议改法。

## 不能判断时

- 原文缺失、扫描件 OCR 有错字、公式或表格无法还原 → 写「不确定」，
  并说明缺什么；
- 一句话有两种合理读法 → 并列两种译法，不要挑一个当定论；
- 只看到译文 → 不下「准确 / 不准确」的总结论，只报可验证的局部问题。

## 输出格式

1. 一句结论（能判断到什么程度）；
2. 问题清单（类型 / 位置 / 原文 / 译文 / 建议），按严重程度排；
3. 未能核对的部分与原因；
4. 若整体无明显问题，也要说清核对了哪几句、依据是什么。

## 反例

- 只看中文顺不顺，就说「译文准确」；
- 把「译得更好」当成「译错了」；
- 指出漏译却说不出漏了哪一句；
- 用机器回译去证明原文意思（回译本身也会错）；
- 把「术语与库里不同」直接判成错译，而不看语境。

## 与术语表联动

核对术语时先跑 `search_terms`，把库里的译法当基准；译文与库不一致时，
先判断是译文错还是术语表错，再给建议。术语表没收录的词只能按语境判断，
标「不确定」而不是直接判错。同一术语全文多次出现时，逐处核，不要抽查一处就推广。

## 判据

每个判断都有位置；四类问题能区分；判断不了就说不确定；
不把「没看到原文」包装成「核对通过」。
