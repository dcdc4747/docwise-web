# 多篇对比矩阵

## 列定义（写死，不要临时加列）

| 列 | 取值来源 | 缺失时写 |
|---|---|---|
| 研究问题 | 导读 research_question | 未报告 |
| 方法 | 导读 method | 未报告 |
| 数据 | 导读没有就 `read_blocks` 找样本/数据描述 | 未报告 |
| 结论 | 导读 conclusion | 未报告 |
| 可引用句 | `build_matrix` 的 quote，或 `read_blocks` 的原文，逐字 | 无可用引文 |

列顺序固定。**不要因为某篇多一个「创新点」就加一列**，那会让矩阵没法横向读。
`build_matrix` 实际给的是研究问题 / 方法 / 结论 / 术语 / 可引用句；
「数据」一列要自己从块里补，补不到就写「未报告」，不要空着。

## 步骤

1. 定范围：`build_matrix(topic=主题词, limit=N)`。它按文件名与导读文本筛，
   有导读的优先；
2. 认缺口：返回的 `missing` 是没导读的文献。**不猜内容**，
   先对每篇试 `get_understanding(task_id)`，仍无导读就留在 missing；
3. 补引文：`build_matrix` 的 `quote` 是该篇被引用过的原文，可直接用；
   不够就用 `read_blocks` 取该块，逐字复制，不改写；
4. 出表：一行一篇，行首写 task_id 与文件名；每格末尾给出处
   （导读字段名，或 block_id）；
5. 收尾：表下一句总览（几篇、最大分歧在哪），再列 missing 与「未报告」的格子。

## 一格一出处

- 导读来的格子：标「导读 · 结论」这类来源，不挂 block_id
  （导读是模型生成的，不是原文）；
- 原文来的格子：挂 block_id；
- 一个格子不要挂三个块充数，选最直接的那一个；
- 跨篇比较的结论（「三篇都认为……」）要能逐篇点回各自那一格。

## 不能做的事

1. 把 A 篇的结论填进 B 篇的行；
2. 用「类似」「同上」省掉出处——矩阵的价值就是可追溯；
3. 给 missing 的文献补一句「可能也关注……」，那是猜；
4. 把方法列写成评价（「方法很扎实」），方法列只写做了什么；
5. 只排有导读的几篇，却不说还有几篇被 limit 截掉了。

## 同一篇的多个版本

同一篇重复上传会得到不同的 task_id。矩阵里只保留最新且已完成的那一篇，
并在表下注明「同名另有一版，未计入」；**不要把两版当成两篇文献做对比**，
那会把同一份结论数成两条独立证据。若两版内容确有差异，单独说差异，不混进矩阵。

## 判据

每行都有 task_id；每个非空格子都能追到导读字段或块；
missing 与「未报告」都在表下如实列出，没有静默省略；
总览里的每个判断都能在表里找到对应行。
